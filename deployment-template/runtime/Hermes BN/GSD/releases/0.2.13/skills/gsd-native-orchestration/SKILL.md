# Действующий порядок GSD в Hermes

Используй для задачи, требующей объяснений, проверки оснований или выбора различающей проверки. Сначала зафиксируй вопрос, область и ограничения пользователя. Не превращай поиск объяснений в допуск внешнего действия. Для простого справочного ответа не запускай полный цикл без необходимости.

## Вызов настоящих ролей

Для обычного вопроса вызови `gsd_research`, предварительно получив схему через `tool_describe`. Передай одну точную `scope`, `question`, новый `request_id`, ограничения и исходные наблюдения. Адаптер связывает одинаковую область между компонентами и запускает тот же настоящий цикл G/S/D. Все переданные наблюдения считаются материалом построения: они не являются независимой отложенной проверкой. Профиль по умолчанию Standard; неизвестный риск не объявляй оценённым.

Для расширенной композиции используется `gsd_analyze`. G, S, D, GS, GD, SD допустимы по исходным договорам; отсутствие владельца не закрывается предположением о его работе. В расширенном интерфейсе `generation.scope` и `request.scope` должны совпадать **буквально**, не только по смыслу. Различие отклоняется до запуска ребёнка.

Минимальный корректный пример формы; замени содержание фактическим вопросом, ограничения и наблюдения сохраняй точно:

```json
{
  "components": "GSD",
  "request_id": "new-stable-analysis-id",
  "request": {
    "generation": {
      "id": "new-stable-generation-id",
      "task": "Породить различимые объяснения предъявленного изменения",
      "product_kind": "hypothesis",
      "seed": "Данные, которые действительно использованы при построении объяснений",
      "scope": "Точная область вопроса",
      "frame": "Процесс, измерение и нулевые альтернативы",
      "constraints": ["Ограничения пользователя; анализ без внешнего действия"],
      "method": "agent",
      "max_candidates": 4,
      "scan_budget": 20
    },
    "candidates": [],
    "observations": [],
    "scope": "Точная область вопроса",
    "question": "Что известно, что остаётся и какая проверка различит версии?"
  }
}
```

`method=agent` запускает настоящего G. `supplied` означает предоставленный набор, не новое порождение. `variation` и `morphological` — исходные конечные вычисления. Не подставляй искусственный ответ вместо недоступного ребёнка.

Наблюдение имеет ровно поля `id`, `key`, `value`, `source_id`, `origin_group`, `state`, `method_valid`, `used_for_generation`. Допустимые состояния: `observed`, `not_measured`, `invalid`, `unavailable`; две последние метки пригодности — настоящие JSON boolean. Отсутствующее измерение не становится нулём или опровержением.

Если факт появился в seed, task, условиях или ином материале построения, укажи `used_for_generation=true`. Значения действительно отложенной проверки не включай в материал G. Присвоенное имя группы и метка false сами по себе не доказывают независимость. Копии одного первичного источника сохраняют общее происхождение.

Для S/D без G нужны действительные текущие кандидаты; для D без S — соответствующий текущим версиям ComparisonReview. При отсутствии возвращается зависимость, а не выдуманное исполнение. Нельзя понижать профиль ради ресурса или объявлять одну модель независимой профессиональной экспертизой.

## Полные адресные операции

`gsd_catalog` ищет точный адрес; `gsd_contract` возвращает полный исходный договор. `gsd_work` исполняет его настоящим владельцем. Процедуре нужен готовый сохраняемый случай и run_id. `gsd_work_file` допустим только для явно независимых целых записей: ядро и замыкание передаются каждой задаче; общий вывод по частям автоматически не возникает.

Для серьёзной многошаговой работы используй сохраняемый случай через `gsd_case_create/get/next/change`. Не изменяй его бюджет или полномочия. Не принимай собственное постусловие: `commit`, `accept_limited` и `close` требуют отдельного доверенного решения. Оператор связывает новый сеанс с существующим случаем без пополнения ресурса.

## Завершение

Назови фактически исполненные роли, основание вывода, остатки, следующий различитель и ограничения. Сохрани различие: выполненное вычисление, модельный продукт `unreviewed`, предметная проверка, разрешение и внешний эффект. План проверки не является результатом; риск пропуска не равен вероятности.

При ошибке обязательного механизма останови зависимую работу. Не повторяй прежний request_id как новый запуск. `gsd_runtime_status` показывает общий расход, `gsd_stop` останавливает семью. Недоступный исполнитель, неполный источник и неподтверждённое действие не считаются успехом.

## Явное продолжение после завершения G

В выпуске переходника 0.2.5 `gsd_analyze` принимает необязательный `resume_G_job` вне `request`. Применяй его только после фактического `completed`/`SUCCEEDED` G в той же семье: точные `generation` и все наблюдения построения должны совпасть с сохранёнными входами. Новый `request_id` обозначает продолжение, а не повтор G. Поздние проверочные наблюдения можно добавить с `used_for_generation=false`, сохранив их первичный источник и ограничения независимости. Хост проверяет сохранённую квитанцию, семейство и входы; чужой, незавершённый или изменённый G отвергается. G не запускается повторно; S/D исполняются реально. Предыдущие неуспешные записи и расход сохраняются.

Отсутствие общего бюджетного срока не отменяет срока пригодности отдельной передачи. Просроченную передачу нельзя автоматически объявлять свежей.
