# Полнота документарного корпуса Hermes BN

Реестр обслуживает обычный Hermes, UDR и GSD через сервер context. Исходные байты, извлечённые единицы, доставки модели и смысловая приёмка — четыре различных результата. Успешное извлечение не означает чтение. Ответ модели подтверждает получение входа, но не доказывает его понимание.

## Порядок работы

1. Перед работой загрузить навык `document-corpus-completeness`. Зафиксировать область, корень корпуса, версию и требуемые этапы. Для UDR обязательны `plan`, `collect`, `analyse`, `verify`, `report`; при использовании GSD дополнительно `G`, `S`, `D`.
2. `document_catalogue(path, request_id, required_phases)` сохраняет полный перечень файлов и неизменные снимки. Для вложения применять возвращённый `attachment:...`, а не произвольный путь. Ошибка перечисления каталога делает inventory_complete=false; число файлов под ним не выдумывается. Каждый неподдерживаемый, недоступный или изменившийся при копировании файл остаётся видимым пропуском.
3. Последовательно просмотреть все страницы `document_status` и извлечь каждый зарегистрированный источник через `document_extract`. Просмотреть все страницы `document_describe`; не ограничиваться первой выдачей. При ошибке исправить формат или доступ; не заменять исходник пересказом.
4. Большой корпус разделить `document_partition`. Пакеты включают непересекающиеся исходные единицы без копирования оригиналов. Одна большая единица сохраняется целиком в пакете и читается фрагментами. Разбиение пакетов повторно запрещено. Неподдержанные источники не исчезают из общего реестра.
5. `document_read(corpus_id, doc_id, unit, offset, max_chars)` возвращает точный фрагмент. Продолжать до `has_more=false`, затем переходить к следующей единице. Текст и необходимое изображение проверяются до обращения к модели. Ошибка исполнителя не создаёт квитанцию чтения.
6. Для UDR переключать реальный этап через `udr_research(action=phase)`. Для G/S/D этап определяется реальной дочерней сессией, а не аргументом модели. Родитель не может зачесть чтение за G/S/D.
7. Выполнить ограниченное GSD для каждого необходимого пакета; сохранять типизированные продукты с привязкой к пакету. В UDR использовать существующие подзадачи Beads и ограниченную команду; не создавать второй движок и рекурсивные команды. После пакетов отдельно сопоставить их результаты: противоречия, повторяющиеся свидетельства, зависимости и необработанные остатки. Пакетное покрытие не заменяет такой синтез.
8. На переходах сверять общий `document_status`. При пробелах запрещено объявлять полное чтение или завершать UDR как `complete`. Допустим `partial` с точным перечнем пробелов. Сохранять идентификаторы корпуса, пакетов, исследования и задач для продолжения через любое время.
9. При изменении исходников создать новую версию корпуса с новым `request_id`. Прежний запрос адресует прежний снимок. Старые квитанции не переносятся на новые байты.
10. Перед выдачей отчёта проверить ссылки на оригиналы, адреса страниц/листов/таблиц, покрытие и смысловую обоснованность. Масштабный отчёт передавать файлом Markdown с коротким статусом.

## Форматы и границы

| Формат | Реальное извлечение | Ограничение |
|---|---|---|
| TXT, MD, JSON, JSONL, XML, HTML, SQL | Все исходные блоки UTF-8 с границами байтов | Другие кодировки требуют явного преобразования; SQL не выполняется; структура JSON сама не доказывает смысл |
| PDF | Все страницы, текст; графические страницы также PNG | Защищённый PDF требует доступа; слишком крупное изображение требует отдельного разбиения; доставка изображения не гарантирует распознавание мелкого текста |
| CSV, TSV | Все строки и поля, включая заголовок | Явный разделитель; UTF-8; автоматическое угадывание не применяется |
| XLSX, XLSM | Все листы, включая скрытые, координаты, формулы и сохранённые значения | Макросы не исполняются; комментарии, графики, внедрения и другие неразобранные части — явный пробел |
| XLS | Сохранённые значения листов | Исходные формулы не восстановлены; полный исходный документ не принимается |
| DOCX | Все XML и связи контейнера, включая колонтитулы и примечания | Изображения и внедрённые объекты — явный пробел; не утверждается точность визуальной вёрстки |
| ODS | Структурные строки, атрибуты повторений, формулы в атрибутах | Не эквивалент вычисленному документу; визуальные части требуют отдельной проверки |
| RTF | Исходный текст контейнера и декодированный текст | Внедрённые объекты/изображения — пробел |
| SQLite | Согласованный снимок с подтверждёнными записями WAL, все таблицы и полная схема | Представления фиксируются определениями, не исполняются; триггеры и SQL не запускаются |
| Parquet | Схема и все строки | Не исполняются расширения Arrow; специализированные типы помечаются представлением |
| Другие | Оригинал и запись в перечне | `unsupported`, не полное чтение; требуется отдельный проверенный преобразователь |

Ни один компонент не гарантирует понимание любого произвольного формата. Запрет на ложную полноту действует также для пустых извлечений, отсутствующего исполнителя, повреждённого снимка, недоставленного изображения и незавершённой страницы.

## Состояние и восстановление

Реестр находится в основной памяти SQLite, а неизменные оригиналы и единицы — в её каталоге documents. Записи содержат контрольные суммы, единицу, интервал текста, реальную сессию, этап и идентификатор обращения к модели. Квитанции переживают смену процесса и повторный вход. Неопределённый исход обращения не считается успешным. Повторяется только явно непрочитанная часть, не весь сбор автоматически.

Для восстановления требуется согласованная копия SQLite вместе с каталогом documents, конфигурацией Memory, установленными декодерами и их зафиксированными зависимостями. Обезличенная поставка сохраняет код и пустой реестр; чужие оригиналы, корпуса, квитанции, сессии и ключи переносить нельзя.
