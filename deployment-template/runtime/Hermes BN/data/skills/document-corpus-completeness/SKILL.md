name: document-corpus-completeness
description: Полный учёт документарного корпуса, больших вложений и адресного чтения на всех фазах Hermes BN, UDR и GSD.
---

Перед обработкой корпуса фиксируй все файлы, неизменную версию и обязательные этапы. Извлечение, получение инструментом, получение моделью и смысловая проверка различаются.

1. `document_catalogue`: все источники, новая версия — новый request_id. Для вложений используй только подготовленный attachment: путь.
2. Перечитай все страницы `document_status`, извлеки каждый источник `document_extract`; все единицы перечисляет `document_describe`. Неподдержанные источники остаются пробелами.
3. Большой корпус дели `document_partition` на конечные адресные пакеты. Следуй next_offset; не дели пакеты повторно. Не отсекай обязательное из-за длины контекста.
4. В каждом этапе читай назначенные единицы `document_read` полностью до has_more=false. Для UDR обязательны plan/collect/analyse/verify/report и реальное переключение action=phase; для GSD — роли G/S/D. Родительское чтение не заменяет чтение роли. Изображения доставляет доверенный обработчик.
5. Для каждого пакета запускай необходимую ограниченную GSD-работу; сохраняй типизированные продукты. В UDR связывай независимые задания существующим bn_udr_team и Beads, сохраняй результаты до продолжения. Запрещены рекурсивная делегация и повторная обработка без новой причины.
6. Итоговый синтез должен сопоставить продукты всех пакетов, межпакетные противоречия, зависимости и пробелы. Квитанции доставки не доказывают понимание или предметную истинность.
7. Перед переходом и итогом сверяй общий document_status. При неполном обязательном этапе — partial и точные остатки; не complete. Сохраняй corpus_id, пакеты, run_id, задачи и исходные контрольные суммы для продолжения через неопределённое время.
8. Полное чтение произвольных форматов не гарантируется: защищённые/повреждённые документы, неизвестные форматы, внедрения и непроверенные визуальные части остаются открытыми пробелами. SQL и макросы не выполняй. Не выдавай машинную выдержку за весь оригинал.
9. Большой готовый отчёт передавай файлом Markdown; отдельно краткий статус: завершено, выполняется, следующий шаг, пробелы.

XLS (BIFF8): читай через обычные document_*; обработчик Apache POI работает без сети, записи, исполнения формул и макросов. formula — выражение, восстановленное из исходных двоичных записей; cached — сохранённый результат, который может быть устаревшим. Не подменяй одно другим и не объявляй книгу пересчитанной. Учитывай все скрытые листы, строки, столбцы, объединения, именованные ссылки, массивы, комментарии и свойства документа. Макросы, графические объекты, внешние книги, непонятные записи и неразобранные правила оформления остаются пробелами. Старое чтение XLS только по значениям не считается новым полным чтением: создай новый request_id, сохрани историю и заново прочитай оригинал.
