# Текущий порядок развёртывания — 16 октября 2026

Этот документ относится к обновлению macOS на Apple Silicon. Он заменяет прежние текущие указания о версиях, сохраняя исходные подписанные поставки как историческую основу.

## Состав восстановления

Нужны **оба слоя соответствующего варианта**: полный архив 14.10.2026 и обновление 16.10.2026 с окончанием r2. Применяйте r2 прямо к основе 14 октября; прежнее обновление16октября отдельно не накладывается. Отдельное обновление не является полной установкой. Их имена, размеры, SHA-256 и адреса частей определяет recovery-set.json. Собирать части следует предоставленным restore.py; проверять и применять — apply-update.py. Не смешивайте полный и обезличенный варианты.

Полный вариант зашифрован age и содержит учётные данные, историю и материалы прежнего владельца. Для него нужен отдельный ключ восстановления. Обезличенный вариант открыт, без пароля: прежние входы, владельцы, базы исследований, разрешения, приёмка и состояние задач не переносятся.

## Безопасная последовательность

1. Соберите архив основы и архив обновления r2, проверьте SHA-256. Распакуйте их в два новых отдельных каталога на APFS. Рабочие базы нельзя размещать на exFAT/NTFS. Не распаковывайте поверх работающей системы.
2. Примените apply-update.py к новой распакованной основе. Средство сверяет исходный манифест и запрещает замену действующего экземпляра. Затем проверьте обновлённый MANIFEST.jsonl штатным verify.py. Сохраните квитанцию применения.
3. Для восстановления прежнего владельца следуйте RECOVERY.md: сначала остановите только его службы, сохраните изменения после снимка, восстановите согласованные код, настройки и состояние; проверьте обязательные контроллеры. Не запускайте вторую копию того же Telegram-бота или Zotero Sync.
4. Для нового пользователя используйте только обезличенный комплект. Выполните deployment/prepare.py, затем deployment/prepare-udr.py, затем deployment/prepare-memory.py. После всех трёх подготовок, до входа в аккаунты, выполните bundled BN Python: `runtime/Hermes BN/hermes-agent/venv/bin/python deployment/finalize-prepared.py`. Этот шаг согласует все подставленные пути, манифесты и транспортные допуски; он не создаёт разрешений на внешние действия. Выбирайте новые пустые каталоги R; путь, заканчивающийся на /env, должен занимать не более 49 байтов UTF-8; выбранный путь R должен быть без пробельных символов. Эти шаги не означают подключение служб или производственную приёмку.
5. Модель и вычислительные службы требуют собственных доступов. OAuth ChatGPT не является ключом API для эмбеддингов. Установленная конфигурация использует GPT 6.1 Sol и Voyage voyage-4-large, 1024 измерения; другой выбор требует согласования контрактов и проверки. Чужие ключи или состояния переносить нельзя.
6. Вход во внешние службы поиска, извлечения, научные каталоги, Telegram и Zotero Sync выполняется отдельно новым владельцем. Он не требуется для проверки локальной подготовки и не выполняется автоматически.
7. Перед производственной работой настройте собственные полномочия служб и выполните проверки из ACCEPTANCE.md. Исходная приёмка прежнего владельца не наследуется.

## Действующие версии и отдельные закрепления

- Hermes BN: 0.22.2, commit d923a5eb487a17c0a68801bba9ef0f56c81040a8; собственный Python 3.14.6 в комплекте.
- GSD Engine: 3.0.3; переходник 0.2.13, отдельная проверенная сборка совместимости с Hermes 0.22.2 и исправлениями переносимости. Полный набор процедур сохранён; это не новый выпуск исходного GSD.
- Общая память: 1.2.8; Cognee: 1.6.4.
- Beads BN и локальный исполнитель Beads UDR: 1.3.1. В неизменённом подписанном SDK Foundation исходная версия Beads остаётся 1.1.0. Её нельзя принимать за фактический локальный исполнитель. Локальное переопределение задаёт абсолютный путь и SHA-256 в UDR/state/adapters/beads-runtime.json.
- Dolt BN: 2.4.2. Отдельное основание UDR и встроенный Dolt Beads имеют собственные закрепления; не заменяйте их произвольной общей версией.
- Research 0.44.0b2 и Foundation 0.14.0b1 сохранены согласованной подписанной парой. Вспомогательный Hermes UDR, Graphiti/Neo4j, Zvec, Serena, Mirage и наблюдаемость сохраняют совместимые закрепления этой платформы. Новая версия отдельного пакета не подтверждает его совместимость с парой.

Полные фактические значения и границы — CURRENT-VERSIONS.json. Исторические отчёты и исходные руководства поставщиков сохраняют свои даты и исходные версии. Они не заменяют этот текущий порядок и локальные переопределения.

## Исправления переносимости

В комплекте должны находиться все следующие части, а не только новый исполняемый файл Beads:

- bounded UDR udr_compare_rates — десятичное сравнение двух конечных неотрицательных значений, без команд, сети и файловых записей;
- UDR udr_workspace — адресные страницы до 4096 символов, полный байтовый SHA-256, SHA-256 фрагмента, offset/end_offset/next_offset/complete;
- обязательная регистрация ровно возвращённого фрагмента для сборщика;
- локальный BeadsAdapter с абсолютным исполнителем, проверкой SHA-256 и неизменяемыми квитанциями повторов; старые неизвестные исходы не обнуляются;
- штатная отмена фоновой рецензии и подтверждение перед выходом CLI;
- объединение динамического набора расширения с одноимённым MCP-набором, чтобы доступные инструменты не исчезали при выборе udr.

Для команд --toolsets используйте имена серверов из конфигурации, например udr, context и beads. Префикс mcp- на этапе предварительной проверки CLI в этом выпуске может считаться неизвестным. Имена конкретных методов берите из tool_describe; описания запрашивайте группами не более 10.

## Установочные материалы

Исходные пакеты поставщиков и их подписи не переписаны. Для Beads 1.3.1 добавлены официальные дистрибутивы macOS arm64, Linux amd64 и Windows amd64 с проверкой официальных сумм. Python 3.14.6 включён как полный переносимый исполняемый комплект и отдельная локальная перепаковка фактически проверенной установки: повторное получение исходного архива вернуло 403/404. Она не объявляется подписанным архивом поставщика.

Это обновление получило исполнительную приёмку на macOS arm64. Прежний комплект для Linux/Windows и его исходные ограничения сохраняются; полная приёмка нового ядра на этих двух системах не заявляется. Наличие дистрибутивов не равно проверке развертывания.

Для символического анализа R используется поддерживаемый Serena Rязыковой сервер, пакет languageserver0.3.20 в отдельной библиотеке R/serena-library и доверенный R/serena-bin/R. Он вызывает нативный R.framework, используемый /Applications/R.app. Для этой функции R.app/R.framework4.6 должен быть установлен штатным пакетом; системная библиотека не изменяется. Все42бинарных пакета CRAN sonoma-arm64 и42исходных пакета сохранены вR/distribution/serena-lsp-20261016. На другой ОС/ветке R требуется собственная сборка и проверка; наличие исходников не является приёмкой иной платформы.


При восстановлении прежнего владельца сохраняются как прежний Cognee engine, так и новый engine-dataset-isolation-v2 с согласованными первичными квитанциями. Не удаляйте старую проекцию до собственного решения об архивировании. Состояние каждого действующего документа проверяется отдельно: наличие нового кода не завершает миграцию старого индекса. Для нового пользователя prepare-memory.py создаёт пустое собственное пространство; переиндексация чужих источников не выполняется.


Обезличенная основа r2: используйте Hermes-BN-GSD-and-UDR-Complete-new-user-20261014-clean-r2.tar.zst из текущего recovery-set. Её полезные файлы и исходный логический манифест совпадают с основой14октября, но упаковка пересоздана без AppleDouble, расширенных атрибутов, ACL и флагов прежнейmacOS. Старый физический обезличенный архив14октября оставлен только как историческая версия. Дляполного зашифрованного режима сохраняется прежняя проверенная основаfull14октября.
