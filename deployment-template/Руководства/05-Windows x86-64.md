# Чистая нативная установка: Windows x86-64

Целевая система — Windows 11 x64, PowerShell, Python/Node/Java/R для Windows. Docker и WSL не используются. Эта архивная работа не исполняла Windows-программы; собственная нативная приёмка обязательна.

1. Проверьте внешний SHA256: `Get-FileHash -Algorithm SHA256 -LiteralPath АРХИВ`. Установите штатные tar/7-Zip и нативный zstd. Для полной копии также нужен age для Windows и отдельный ключ. Не передавайте ключ вместе с публичной поставкой.
2. Из TAR извлеките сначала Руководства, distribution, deployment, CROSS-PLATFORM-SOURCES.zip и README. Полное дерево macOS содержит ссылки и несовместимые бинарные файлы; на Windows нужны исходники и платформенные дистрибутивы. CROSS-PLATFORM-SOURCES.zip не требует переноса Mac venv/двоичных библиотек.
3. В distribution/native/windows-x86_64 есть Git, Python 3.13.14/3.13.15, 3.12.14, 3.11.16, uv, Node 24.18.0, JDK21, SQLite, Beads, оба Dolt, Neo4j, iii, Collector, R 4.6.1/4.5.3 и необходимые дополнительные средства. Сверьте manifest. Для подписанного EXE/MSI выполните `Get-AuthenticodeSignature -LiteralPath ФАЙЛ`; не считайте издательскую подпись проверенной, если проверен только SHA. Согласие с лицензией/системные изменения выполняет владелец.
4. Создайте отдельные новые каталоги программ/состояний/проекта/профиля. Не переназначайте USERPROFILE или LOCALAPPDATA. Включённые DLL и соседние файлы сохраняйте вместе с программой; не копируйте только один EXE из комплекта.
5. Для каждой среды создайте нативную venv. Пример:

```powershell
uv.exe venv --python 'C:/НОВЫЙ/python/python.exe' 'C:/НОВЫЙ/BN/venv'
uv.exe pip install --python 'C:/НОВЫЙ/BN/venv/Scripts/python.exe' --no-index --find-links 'C:/ПАКЕТ/distribution/python-packages' -r 'C:/ПАКЕТ/ЗАКРЕПЛЁННЫЙ_ПЕРЕЧЕНЬ.txt'
```

Windows-only пакеты pywin32/pywinpty/tzdata и concurrent-log-handler включены; uvloop/ptyprocess не применяются. Для Hermes сначала зависимости и build tools, затем штатный editable install включённого исходника с --no-build-isolation. Обычная сборка wheel не поддерживается; обход через переменную Nix не применяется. Пути Python заканчиваются Scripts/python.exe, а не bin/python.
6. npm используйте как npm.cmd при запрете npm.ps1; глобальный ExecutionPolicy Bypass не нужен. Все tarballs npm из закреплённых lock-файлов включены, также Electron для Windows. Подготовьте собственный кэш через npm cache add и соберите исходник оболочки на целевой платформе. Готовая macOS .app на Windows не используется.
7. R установите включённым официальным EXE в новый каталог. Нужные пакеты можно собрать из исходников; для компилируемых пакетов потребуется соответствующий Rtools: https://cran.r-project.org/bin/windows/Rtools/. Rtools/Windows SDK относятся к системной среде Windows; их лицензии/установка не принимаются архиватором за владельца. Установленная библиотека macOS не заменяет библиотеку Windows.
8. Neo4j работает с собственной Windows-сборкой и JDK21; Graphiti/AgentMemory/Zvec/Serena/Mirage используют свои native venv. Включены опубликованные Windows wheels Zvec. Пассивный XLS использует явный JDK21 policy; до собственного отрицательного испытания контроля и чтения его путь не принимается.
9. Файлы секретов защищаются ACL: доступ только владельцу и необходимым системным администраторам, без групп Users/Everyone. Проверьте права реальным загрузчиком Foundation; chmod-подобная запись в Python не является доказательством достаточного Windows ACL.
10. Выполните ветви PowerShell официальных docs/setup/ru/01–11. Создайте собственные планировщики/службы, а не launchd. Устанавливайте только свои права, модели/ключи и ботов. Далее — руководства 06–09 и настоящее испытание на Windows. Linux/macOS результаты не являются результатами Windows.
