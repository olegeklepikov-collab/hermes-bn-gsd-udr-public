# Проверки и границы

Спроектировано, реализовано и подключено: общий слой памяти 1.0.3 для трёх рабочих профилей BN и всех шести настроенных каналов. Проверено: первичный журнал, реальные три индекса, Mirage, Serena, обязательные контроли, обычный CLI, UDR и самостоятельные профили. Три настоящие роли G/S/D получили одинаковый родительский контекст с правами только чтения.

Четырнадцать отдельных испытаний нового кода проходят; четырнадцать штатных регрессионных испытаний обязательного контроллера Hermes проходят. Негативные и граничные случаи включают секрет, выход за проект, чужую область, подмену подписи, дочернюю запись, смену области родителя, неизвестную схему, конфликт версии, потерю контекста/журнала, целую большую запись и атомарный бюджет параллельных запросов.

Три реальных индекса возвращают одну запись с совпадающими ID, версией и хешем. Проверены две версии, повторное чтение и отзыв; отозванная запись не возвращается первичным поиском и индексами. Zvec восстановлен в отдельной копии из первичного журнала и кэша векторов. SQLite backup проверен integrity_check и повторным чтением.

Обычный CLI прочитал память и первичный файл. UDR получил общий контекст внутри начатой работы; самостоятельный GSD выполнил запрос при отключённом UDR, самостоятельный UDR — при отключённом GSD. Родительская проверка GSD достигла конечного лимита после исполнения ролей; итог завершён одним дополнительным обращением без новых ролей. Это отражено двумя отдельными результатами, а не заменой неуспеха на успех.

Изначальные проверки Telegram выявили исчерпанный срок старой семьи и отсутствие нового сервера в списках каналов. Старая маршрутизация сохранена в точке отката; новый маршрут создан штатно, срок прежней семьи не продлён. Списки всех каналов исправлены. Дополнительный not_found объяснён фактически полученными именами без разделителей __; сообщение без сложного полного имени нашло и вызвало точные инструменты. Доставка общего контекста и выполнение обоих инструментов через реальный входящий Telegram подтверждены. Агент отправил проверку через приложение Telegram по явному разрешению владельца; ответ визуально получен. Журнал подтвердил memory_recall и memory_files, результаты трёх индексов и совпадение хеша с исходником.

MCP-клиент при трёх отклонённых вызовах временно ограничивает сервер. Негативные проверки самого переходника выполнены отдельно; ограничение клиента не выдаётся за исполнение отсутствующего проверяющего механизма. Отказы индексов проверены реальным отключением адреса/исполнителя в отдельной конфигурации, без остановки рабочих служб.

Ограничения: один владелец; зарегистрированные проекты; нет автоматического просмотра всего диска, научного принятия или запуска всех индексов на каждом обращении модели. Граф хранит типизированные предметные связи, не устанавливает причинность. Проверены символы Python; остальные языковые серверы требуют отдельной проверки при регистрации проекта. Визуальное управление GUI/TUI и запуск нового расписания не выполнялись; их набор инструментов проверен штатным разрешением Hermes. Прежние процедуры GSD и сторонние источники не переобозначены как заново испытанные.

Повторные команды для отдельной копии/при изменении кода:

```sh
PYTHONPATH=Memory/releases/1.0.3:hermes-agent hermes-agent/venv/bin/python -m unittest discover -s Memory/releases/1.0.3/bn_memory -p 'test_*.py' -v
hermes-agent/scripts/run_tests.sh tests/plugins/test_required_execution_control.py -q
```

Реальные модельные сценарии сохранены в checks/native_check.py и результатах native-*.json. Не повторяйте их автоматически: GSD/UDR создают состояния и расходуют конечный общий ресурс. Успешные проверки не требуют новых кругов без изменения соответствующего пути.
