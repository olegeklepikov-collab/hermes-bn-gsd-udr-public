# Отказы, восстановление и откат

## Порядок отказов

Недоступный AgentMemory, Graphiti/Neo4j или Zvec отмечается в результате поиска как unavailable. Первичный журнал продолжает работать; пустой ответ индекса не объявляется отсутствием знания. Запись сначала фиксируется в SQLite, затем индексируется; неудачная индексация остаётся pending. Повтор ограничен явным вызовом memory_sync.

Потеря первичного журнала, неизвестная схема, неверный хеш, подмена подписи или области закрывают зависимый путь. Отказ наблюдающего события не заменяет проверки: перед инструментом и итоговыми аргументами модели действуют обязательные контроллеры. Старые дочерние роли блокируются после смены проекта родителя.

Общая память не требует запуска контроллера UDR и работает в bn-gsd-only; в bn-udr-only работает без GSD. Совместный профиль сохраняет обязательность обоих модулей. Переход в самостоятельный профиль — явное действие владельца, без продолжения отказавшей операции.

## Снимок и восстановление

```sh
source environment.sh
hermes-agent/venv/bin/python Memory/memoryctl.py snapshot /absolute/private/memory-snapshot.sqlite
hermes-agent/venv/bin/python Memory/memoryctl.py verify-snapshot /absolute/private/memory-snapshot.sqlite
```

SQLite backup сохраняет согласованный снимок, включая версии и кэш векторов. Файл содержит данные владельца; храните его с доступом только владельцу. Вместе с ним сохраняйте settings.json, host.key, текущий выпуск кода и настройки подключений. Ключ не помещайте в открытый пакет документов.

Проверка восстановления выполнена в отдельном каталоге: integrity_check=ok, повторное чтение вернуло исходный хеш. Для замены рабочего журнала сначала остановите шлюз BN и остальные работающие CLI BN; сохраните прежние memory.sqlite, memory.sqlite-wal и memory.sqlite-shm. Поместите проверенный снимок как memory.sqlite в Memory/state с правами 0600, не смешивая его с WAL прежнего состояния. Запустите BN и выполните чтение по ID. Состояния GSD и UDR этой операцией не откатываются.

## Перестроение производных

```sh
hermes-agent/venv/bin/python Memory/memoryctl.py rebuild zvec --max-batches 30
hermes-agent/venv/bin/python Memory/memoryctl.py rebuild zvec --resume --max-batches 30
```

Допустимые имена: agentmemory, graphiti, zvec. Первый вызов ставит текущие версии в очередь; --resume продолжает без повторной постановки всего массива. Команда показывает pending и complete. Восстановление Zvec из первичного журнала и сохранённых векторов проверено в отдельной копии без замены рабочего индекса. Недостающие векторы потребуют доступного Voyage и дневного бюджета.

## Откат подключения

Остановите только шлюз BN и выполняющиеся CLI BN. Затем из корня BN:

```sh
source environment.sh
hermes-agent/venv/bin/python Memory/activate.py rollback
```

Команда проверяет хеши точки Memory/checkpoint, восстанавливает прежние настройки профилей, обязательные политики, списки инструментов и исходный переходник независимого UDR; удаляет только добавленные расширение и навык. Новый журнал памяти сохраняется. После этого запустите штатный шлюз BN. Для полного отката всех данных используйте ранее созданную зашифрованную резервную копию GSD and UDR с отдельным ключом.

Исчерпанный двухчасовой срок семьи GSD не продлевается автоматически. Новый разговор получает отдельную семью, а общий слой сохраняет долговременные записи. В проверке обнаружена сохранённая старая маршрутизация после /new; новый маршрут создан через SessionStore.reset_session, прежняя история не удалена.
