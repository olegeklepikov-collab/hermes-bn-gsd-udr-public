description: Общая память, контекст, поиск материалов и чтение кода всего Hermes BN; обычные задачи, GSD и UDR.
---

1. Общие предпочтения и адресный контекст уже доставлены расширением. Для дополнительного поиска используй `mcp__context__memory_recall`: local — первичный журнал; hybrid — также AgentMemory, Graphiti/Neo4j и Zvec. Укажи короткий предметный запрос, limit до 10; большие результаты читай следующей страницей.
2. Сохраняй необходимые решения, ограничения и заметки через `memory_record`: content, source_ref, kind, request_id. task — текущая работа; project — повторное использование в проекте; owner — явно общие сведения. Не сохраняй переписку целиком, секреты или неподтверждённые выводы как факты. local:путь связывает запись с хешем текущего исходника; kind=source требует точной цитаты.
3. Для исправления передай id и expected_revision; повторно прочитай запись через memory_read. Для отзыва используй memory_retract с текущей версией. История сохраняется; прежняя переписка не стирается. Проверяй результаты индексов; memory_sync выполняет один ограниченный проход.
4. Файлы: memory_files(path,offset,limit), относительный путь текущего проекта или абсолютный адрес собственного зарегистрированного проекта. Список доступных корней — memory_status.readable_projects. Чтение прежнего или другого проекта не требует memory_scope и не переключает текущую задачу. Секреты, ссылки и незарегистрированные корни запрещены; дочерняя роль не расширяет область. Код: memory_code(action=overview/symbol/references,path,symbol); Serena читает, не редактирует. Проекты регистрирует владелец местной командой; memory_scope выбирает только зарегистрированный проект.
5. GSD и UDR используют тот же контекст. Дочерние роли получают область родителя и только чтение; G/S/D не получают лишних инструментов. Память не разрешает внешние действия и не подтверждает научные выводы. Beads/Dolt сохраняют собственные задачи и версии, без дублирования.
6. Отказ производного индекса означает ограниченный поиск, а не пустую базу или успешную проверку. Потеря первичного журнала или обязательного контроля закрывает зависимый путь. Не запускай рекурсивный поиск, автоматические делегации или бесконечные повторы.


Смысловой поиск 1.4.0: содержательные обращения автоматически получают проверенный словарный и векторный контекст. `memory_recall` по умолчанию hybrid. `records` — целые записи памяти; `source_fragments` — допущенные точные фрагменты с источником и хешем. `memory_read` читает MEM- и SRC-. Поле `source_index` в memory_status показывает очередь, готовые фрагменты и исключения. Получение фрагмента не означает чтение целого документа; обязательное чтение остаётся через document_read или исходный документ UDR. Дочерняя роль не строит повторный общий поиск и читает только назначенные единицы.
