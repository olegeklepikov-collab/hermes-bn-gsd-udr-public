# Hermes BN: полная установка на новый Mac с Apple Silicon

Дата комплекта: 17 октября 2026 года. Исполняемая подготовка проверена на macOS 26.5.1 (25F80), arm64; совместимость с более ранней macOS требует отдельной проверки. Текущий публичный выпуск: `public-2026-10-17-gsd-udr-r2`.

Репозиторий: https://github.com/olegeklepikov-collab/hermes-bn-gsd-udr-public

Материалы выпуска: https://github.com/olegeklepikov-collab/hermes-bn-gsd-udr-public/releases/tag/public-2026-10-17-gsd-udr-r2

## 1. Что именно устанавливается

Это самостоятельная нативная установка Hermes BN с GSD, UDR и общей системой памяти. Docker и WSL не используются. Комплект обезличен и не зашифрован. Он не переносит аккаунты, ключи, историю, исследовательские материалы, разрешения и подтверждение работоспособности прежнего владельца.

Файлы репозитория — исходники, документация и средства развёртывания. Полные исполняемые среды находятся в материалах выпуска. Одного скачивания исходников или `git clone` недостаточно.

Обязательны два согласованных слоя:

| Слой | Итоговый файл | Размер | SHA-256 |
|---|---|---:|---|
| Очищенная основа | `Hermes-BN-GSD-and-UDR-Complete-new-user-20261014-clean-r2.tar.zst` | 17 801 925 827 байт | `cbf18ffe88011c66fea0498068c2119ad3bacad376a35bd6fbe2f9e9b7f9fce1` |
| Обновление | `Hermes-BN-GSD-and-UDR-new-user-update-20261016-r2.tar.zst` | 919 710 867 байт | `e032943a25685d8c3f43eb391ec909683cd1444ba12062f7c43750b035bd89a9` |

Основа опубликована десятью частями; обновление — одним файлом. Всего загружается 18 721 636 694 байта. Программа `restore.py` проверяет каждую часть, порядок, итоговый размер и SHA-256. Старую основу без `clean-r2`, полный личный архив и прежние обновления сюда не подмешивать.

## 2. Подготовка Mac

1. В меню Apple → «Об этом Mac» проверьте процессор Apple M1/M2/M3/M4 или другой Apple Silicon. В Терминале `uname -m` должен вернуть `arm64`. На Mac Intel этот двоичный комплект не применять. Не запускайте Терминал через Rosetta.
2. Рабочие данные разместите на APFS. exFAT/NTFS подходят для перевозки архивов, но не для рабочих баз и исполняемой установки с правами и символическими ссылками.
3. Практический запас — не менее 150 ГБ свободного места на время установки. Это резерв для частей, собранных архивов, распакованной основы, обновления и рабочих данных, а не измеренное минимальное требование. Для крупных корпусов нужен дополнительный объём. 16 ГБ памяти — исходный ориентир; параллельные индексы и большие исследования требуют собственного измерения нагрузки.
4. Используйте отдельный каталог и текущую обычную учётную запись macOS. Существующие Hermes, Homebrew, R, Zotero и их данные не заменять автоматически. Учётная запись администратора потребуется только для штатных системных установщиков.
5. На новом Mac установите инструменты командной строки Apple, если их ещё нет:

```bash
xcode-select -p
```

Если команда сообщает об отсутствии инструментов:

```bash
xcode-select --install
```

Завершите системный диалог. Сведения Apple: [документация Xcode](https://developer.apple.com/xcode/resources/). Затем проверьте:

```bash
uname -s
uname -m
sw_vers
python3 --version
git --version
/usr/bin/curl --version
```

Для начальных средств требуется Python не ниже 3.9. Если `python3` отсутствует, установите Python 3 с [официальной страницы Python для macOS](https://www.python.org/downloads/macos/) и откройте новое окно Терминала. Внутри комплекта собственный Python; системный нужен для начальной загрузки и проверки.

Для краткости далее используются отдельные переменные `BN_KIT`, `BN_DEST`, `BN_ROOT`, `UDR_ROOT`. Переменные `HOME` и `CODEX_HOME` изменять нельзя.

## 3. Получение публичного комплекта

В новом окне Терминала:

```bash
umask 077
mkdir -p "$HOME/HermesInstall"
cd "$HOME/HermesInstall"
git clone --depth 1 --branch public-2026-10-17-gsd-udr-r2 \
  https://github.com/olegeklepikov-collab/hermes-bn-gsd-udr-public.git kit
BN_KIT="$HOME/HermesInstall/kit"
cd "$BN_KIT"
shasum -a 256 -c SHA256SUMS
python3 restore.py --download \
  --parts-dir "$HOME/HermesInstall/parts" \
  --output-dir "$HOME/HermesInstall/archives"
```

`SHA256SUMS` проверяет внешние средства установки, руководство и программы распаковки; части и архивы проверяются отдельно по `recovery-set.json`. Исходники закреплены Git и собственным манифестом `deployment-template/SOURCE-MANIFEST-SHA256.json`. Авторизация GitHub, GitHub CLI и ключ расшифрования не нужны. Загрузка может занять значительное время. Успех — сообщение о проверенном полном комплекте «основа + обновление». Если существующий файл не совпал с суммой, программа останавливается и не перезаписывает его. Выберите новый каталог либо отдельно разберите повреждённый файл; проверку сумм не отключать.

Альтернатива без `git clone`: на странице репозитория выберите Code → Download ZIP, распакуйте и задайте `BN_KIT` фактическим абсолютным путём этой папки. Материалы выпуска всё равно нужны. После распаковки ZIP восстановите право исполнения командой `chmod +x "$BN_KIT/restore-tools/zstd"`; сценарий `restore.sh` вызывается через `bash`. При ручной загрузке положите десять частей в `parts/base/`, файл обновления в `parts/update/`, затем выполните `restore.py` без `--download` с явными путями.

Загруженная часть проверяется до включения в итоговый архив. Уже собранный совпадающий архив используется повторно. Программа не продолжает произвольно повреждённый `.partial`: сначала разберите причину остановки. Совпадение SHA подтверждает соответствие опубликованному комплекту; само по себе оно не заменяет подпись поставщика.

## 4. Распаковка и применение обновления

Пример назначения — `$HOME/hbn`. Это должна быть новая, ещё не существующая папка. Если домашний путь содержит пробелы или слишком длинный для R, выберите иной собственный короткий путь на APFS; ограничения ниже проверяются до подготовки.

```bash
BN_DEST="$HOME/hbn"
test ! -e "$BN_DEST"
test ! -e "$HOME/HermesInstall/update-r2"

bash "$BN_KIT/restore-tools/restore.sh" \
  "$HOME/HermesInstall/archives/Hermes-BN-GSD-and-UDR-Complete-new-user-20261014-clean-r2.tar.zst" \
  "$BN_DEST"

python3 "$BN_DEST/verify.py" "$BN_DEST"

bash "$BN_KIT/restore-tools/restore.sh" \
  "$HOME/HermesInstall/archives/Hermes-BN-GSD-and-UDR-new-user-update-20261016-r2.tar.zst" \
  "$HOME/HermesInstall/update-r2"

python3 "$BN_KIT/apply-update.py" \
  --base-root "$BN_DEST" \
  --update-root "$HOME/HermesInstall/update-r2"
```

Продолжайте только после успешного завершения каждой команды. При проверке основы ожидается `mismatches: 0`. Применение обновления само проверяет полезные файлы, полный конечный манифест, права, ссылки и лишние пути. Сохраняйте `RESTORE-APPLIED.json`.

Основа и распакованное обновление должны быть отдельными соседними каталогами; обновление нельзя размещать внутри основы. Эти действия не запускают программы и службы. Встроенный `restore-tools/zstd` позволяет распаковать комплект без установки Homebrew.

До подготовки можно отдельно повторить проверку при наличии конкретной ошибки или подозрения:

```bash
python3 "$BN_KIT/apply-update.py" \
  --base-root "$BN_DEST" \
  --update-root "$HOME/HermesInstall/update-r2" --verify-only
```

Не запускайте эту проверку неизменного архива после подстановки собственных путей, входа в аккаунты или создания рабочих данных: такие изменения ожидаемо отличаются от заводского манифеста. Для установленной системы действуют новые местные манифесты.

## 5. Нативный R.app и системные зависимости

R.app — графическое приложение `/Applications/R.app`; его вычислительная основа — `/Library/Frameworks/R.framework`. Это отдельный компонент от изолированных сред R BN/UDR.

1. Найдите поставленный пакет:

```bash
find "$BN_DEST/system-software" -name 'R-4.6.1-arm64.pkg' -print
```

2. Проверьте подпись найденного файла: `pkgutil --check-signature /полный/путь/R-4.6.1-arm64.pkg`. Откройте пакет через Finder или `open /полный/путь/R-4.6.1-arm64.pkg`.
3. Прочитайте лицензию и завершите установку в системном окне. Пароль администратора вводите только туда. Официальный источник: https://cran.r-project.org/bin/macosx/ . Если уже используется другая версия R, сначала решите вопрос совместимости; не заменяйте её молча.
4. Проверьте:

```bash
/Library/Frameworks/R.framework/Resources/bin/R --version
open /Applications/R.app
```

Serena использует `R/serena-bin/R` и отдельную библиотеку `languageserver` 0.3.20, а не произвольную библиотеку пользователя. 42 двоичных пакета macOS arm64 и их исходники включены. На иной версии R/ОС нужна отдельная сборка и проверка. Положительное нахождение входящих ссылок R в исходной приёмке не подтверждено; обзор и чтение определения символа проверены.

В комплекте также есть системные дистрибутивы, закрепления и рецепты зависимостей. Homebrew при необходимости: https://brew.sh/ . Не копируйте весь `/opt/homebrew` поверх существующего: сначала сопоставьте `DISTRIBUTIONS.json`, каталоги `system-software`, `shared-software`, `distribution` и уже установленные версии. Для Neo4j требуется Java 21; точный путь задаётся в собственной службе. Архив не включает macOS и не обещает полностью автономную установку инструментов Apple.

## 6. Подготовка нового независимого экземпляра

Сначала задайте пути. Они должны оставаться неизменными после подготовки:

```bash
BN_ROOT="$BN_DEST/runtime/Hermes BN"
UDR_ROOT="$BN_DEST/runtime/Hermes UDR"
BN_R="$HOME/hbr"
UDR_R="$HOME/hur"
UDR_BOOT="$HOME/hub"
```

Каталоги `BN_R`, `UDR_R` и `UDR_BOOT` не должны существовать. R-пути должны быть без пробельных символов. Путь `BN_R/env` должен занимать не более 49 байтов UTF-8; для UDR действует проверка длины закреплённой двоичной среды. Проверка примера:

```bash
python3 - "$BN_R" "$UDR_R" <<'PY'
import sys
for path in sys.argv[1:]:
    if any(c.isspace() for c in path):
        raise SystemExit('Выберите пути R без пробелов')
if len((sys.argv[1]+'/env').encode())>49:
    raise SystemExit('Сократите путь BN_R: вместе с /env не более 49 байтов')
print('Начальная проверка путей пройдена')
PY
```

Выполните последовательно, останавливаясь при первой ошибке:

```bash
cd "$BN_DEST"
python3 deployment/prepare.py \
  --r-runtime "$BN_R" --init-local-databases

python3 deployment/prepare-udr.py \
  --r-runtime "$UDR_R" --timezone UTC \
  --host-bootstrap "$UDR_BOOT"

"$BN_ROOT/hermes-agent/venv/bin/python" deployment/prepare-memory.py

"$BN_ROOT/hermes-agent/venv/bin/python" deployment/finalize-prepared.py
```

Вместо UTC можно указать свою часовую зону, например `Europe/Moscow`. Если решено передавать техническую почту Crossref/NCBI, передайте собственный `--contact-email` соответствующим подготовительным программам. Чужие адреса не использовать.

Первые этапы перемещают собственные среды R, подставляют пути, создают пустые Beads/Dolt, новые ключи GSD/UDR/памяти, независимые состояния и профили. Последний этап согласует местные контрольные суммы после всех подстановок. Он обязателен **до авторизации**: при обнаружении уже сохранённого входа новый профиль не запечатывается как чистый.

Подтверждения лежат в `deployment/prepared.json`, `GSD-prepared.json`, `UDR-prepared.json`, `Memory-prepared.json`, `FINALIZED.json`. Ожидаемые признаки: новые ключи и состояния; `services_started: false`, `accounts_authorized: false`. Это результат подготовки, ещё не работающая исследовательская платформа.

При частичной ошибке не удаляйте защитные отметки и не запускайте заново создание ключей поверх существующих. Сохраните ошибку и квитанции, устраните указанную причину; продолжайте лишь незавершённый этап, если его входы подтверждены. Для смены расположения используйте новое чистое извлечение.

## 7. Проверка подписанной пары и подготовка служб

Исходные подписанные Research/Foundation внутри комплекта не переписаны. Их проверяют по поставленным ключу, манифесту и подписям до первого рабочего использования. Наличие локального SHA не следует называть подписью поставщика. Исходный commit Hermes не имеет подтверждённой подписи выпуска.

Откройте следующую точную исходную последовательность внутри установки:

1. `$UDR_ROOT/source/docs/setup/README.md`.
2. `$UDR_ROOT/source/docs/setup/HERMES_KNOWLEDGE_WORK_PLATFORM_SPEC.md`, `$UDR_ROOT/source/docs/setup/HERMES_ZERO_TO_DEPLOYMENT_ROADMAP.md`, `$UDR_ROOT/source/docs/setup/HERMES_DEPLOYMENT_AGENT_HANDOFF_PROMPT.md`.
3. Руководства `$UDR_ROOT/source/docs/setup/ru/01-platform-and-hermes.md` … `11-mirage.md` по порядку.
4. Текущие `$BN_DEST/CURRENT-SETUP.md`, `CURRENT-VERSIONS.json` и `$BN_DEST/Руководства/06-Службы память GSD UDR.md`, `07-Аккаунты и защищённый ввод.md`, `08-Приёмка и восстановление.md` уточняют местную конфигурацию и приёмку.

Существующие программы уже включены; команды исходных руководств по скачиванию/установке применяются только к действительно отсутствующим компонентам. Не заменяйте установленную закреплённую пару более новыми пакетами автоматически.

### Порядок и критерии готовности

| Порядок | Компонент | Действие нового владельца и проверка |
|---:|---|---|

| 3 | iii / AgentMemory | Собственные каталоги состояния, область агента, запрет автоматического сжатия оригиналов; сначала iii, затем обработчик |
| 4 | Neo4j | Собственная база, каталоги и пароль; слушать только loopback; `RETURN 1 AS ok` возвращает 1 |
| 5 | Модель и эмбеддинги | Собственный OAuth модели, отдельный ключ эмбеддингов; до индексирования закрепить модель и размерность |
| 6 | Graphiti | Свой конфигурационный файл и область проекта; после добавления эпизода дождаться обработки и найти факт |
| 7 | Zvec / Cognee | Пустые собственные пространства; запись, поиск, точное обратное чтение оригинала, проверка разделения областей |

| 9 | Phoenix / Collector | Местные адреса и отдельные журналы; фактическая доставка события |
| 10 | Foundation / Research, общая память BN | Свои права и конфигурация; миграции и реальные внутренние адаптеры; одна MCP-схема не заменяет эту проверку |
| 11 | GSD / UDR и каналы | Обязательные контроллеры доступны; дочерние роли наследуют ограничения; затем CLI/Telegram и проверка полного цикла |

Для каждого процесса сначала проверьте собственный запуск в Терминале. Конфигурации долговременных служб находятся в `$UDR_ROOT/state/services/*.json`; сверяйте их реальные `argv`, `cwd`, `env_file`, порты и пути с вашей машиной. Нельзя запускать шаблоны с `__PLACEHOLDER__`, `/ABSOLUTE` или чужой областью. Секреты — отдельные файлы 0600 в каталогах 0700, а не аргументы команд или `plist`.

Для Foundation штатная программа находится в `profile/plugins/hermes-foundation-bridge/scripts/configure_native_runtime.py`. Она создаёт `native-runtime.json`, запрашивает пароль Neo4j скрыто и не меняет сам пароль базы. Используйте точные параметры из раздела 10 исходного руководства, включая свой Node и Python `foundation-graph`. Существующая конфигурация не перезаписывается. Не выдумывайте согласие или права SQL ради успешного запуска.

### Регистрация macOS LaunchAgent

После фактического запуска и проверки одной службы создайте её LaunchAgent штатным средством. Пример для уже настроенного `agentmemory.json`:

```bash
(
  source "$UDR_ROOT/environment.sh"
  HERMES_PYTHON="$UDR_ROOT/software/hermes/.venv/bin/python"
  "$HERMES_PYTHON" "$UDR_SETUP_DIR/scripts/render_services.py" \
    "$UDR_ROOT/state/services/agentmemory.json" \
    "$UDR_ROOT/state/services/generated" --platform macos
)

plutil -lint "$UDR_ROOT/state/services/generated/org.hermesudr.agentmemory.plist"
launchctl bootstrap "gui/$(id -u)" \
  "$UDR_ROOT/state/services/generated/org.hermesudr.agentmemory.plist"
launchctl print "gui/$(id -u)/org.hermesudr.agentmemory"
```

Проверьте имя, фактически выданное `render_services.py`: пример применим именно к `name=agentmemory`. При занятом имени создайте собственное имя экземпляра и связанные адреса; не отключайте чужую службу. Другие службы регистрируйте таким же образом по их конфигурациям. MCP через stdio запускает сам Hermes; отдельные фоновые копии Serena/Zvec shim для этого не нужны.

Проверяйте журналы и готовность зависимостей перед запуском шлюза. LaunchAgent действует после входа пользователя macOS; работа до входа этим способом не подтверждается.

## 8. Модель и эмбеддинги: собственные доступы

Перед входом завершите `finalize-prepared.py`. Для BN:


Это штатный диалог Hermes `setup`. Выберите доступный вашему аккаунту способ входа. Если они недоступны, выберите поддержанную модель нужных возможностей и согласуйте ограничения GSD/UDR до работы. Наличие названия в конфигурации не доказывает доступ к модели.

Авторизацию OAuth выполняйте в собственном браузере по **новому** адресу/коду из Hermes. Исторические коды входа не использовать. Нельзя копировать чужие `auth.json` или токены. Не редактируйте вручную подписанную историю контроллера и не отключайте его при отказе авторизации.

При смене модели/размерности создайте новое поколение индекса и проверьте его до переключения.

Вспомогательная среда UDR, мост BN и независимые профили имеют собственные настройки входа. Подключайте их подтверждённым способом из включённых руководств; один успешный вход BN не означает автоматическую готовность всех исполнителей. Проверьте настоящий минимальный запрос каждого требуемого исполнителя.

## 10. Приёмка: установка, подключение и работа проверяются отдельно

Ведите собственный файл `приёмка.md`: критерий, команда/действие, ожидаемый результат, фактический результат, путь/сумма свидетельства, ограничение. Исходные отчёты в комплекте описывают прежние испытания программы; это не результаты вашей машины.

### Минимальный сквозной сценарий

1. Создайте отдельный проект и маленький файл с явным синтетическим содержимым: «Atlas: оригиналы в SQLite; before=20; after=30». Запишите его SHA-256. Не выдавайте синтетические значения за реальные измерения.
2. Через обычный Hermes, без запуска UDR/GSD, сохраните источник общей памятью. Получите его поиском и прочитайте оригинал целиком. Сверьте текст и SHA, затем результаты AgentMemory, Graphiti/Neo4j, Zvec, Cognee. Укажите фактически ответившие индексы. Индекс и оригинал — разные уровни данных.
3. Через Mirage прочитайте разрешённый файл. Попытка чтения вне разрешённой области должна быть отклонена. Через Serena получите обзор и определение символа собственного кода.
4. Создайте две задачи Beads: B зависит от A. Проверьте блокировку B, закройте A и проверьте готовность B. В Dolt сохраните синтетический набор отдельным commit; получите строку, SHA источника, ветку и commit. Свяжите задачу с версией данных.
5. Запустите GSD на вопросе о двух возможных причинах изменения показателя. Подтвердите **реальное** исполнение G/S/D, типизированные передачи, сохранение ограничений, пути продуктов. Правильный JSON и `SUCCEEDED` без содержательной проверки не доказывают корректный вывод. Не заявляйте причинность без различающего свидетельства.
6. Через UDR выполните постановку, декомпозицию, сбор локального источника, анализ, проверку, сохранение отчёта и повторное чтение. Ожидаемый расчёт: 20→30, +10 и +50%; причинность и статистическая значимость не установлены. Если отчёт не сохранён, исследование не закрывать.
7. Остановите и возобновите своё исследование. Подтвердите сохранение исходников, задач, происхождения, состояния и отчёта без повторного внешнего действия. Длительный перерыв не должен вынуждать сбрасывать исследование.
8. Проверьте большой документ адресными страницами до конца и вторую единицу с поздней поправкой. Учёт всех единиц/страниц обязателен. Предпросмотр, извлечение или квитанция доставки не равны смысловому чтению; неполное покрытие не получает `complete`.
9. В R проверьте `mean(1:5)=3`, `var(1:5)=2.5` и создайте график. Проверьте фактическое наличие изображения, а не только успешное завершение команды.
10. Через собственный Telegram повторите чтение источника, получите полный отчёт файлом `.md` и откройте его. Сверьте SHA полученного файла с сохранённым оригиналом.

Инструменты ищите по фактической схеме вашей версии. Запрашивайте `tool_describe` группами не более 10 имён. Для `--toolsets` используйте имена серверов конфигурации, например `udr`, `context`, `beads`; не придумывайте склеенные имена методов. Получение схемы не является успешным выполнением метода.

### Обязательные отказы

Проверьте адресно: недоступный обязательный контроллер; чужая область; неподтверждённый исполнитель; неверный SHA; запрещённое внешнее действие; пропущенный обязательный фрагмент; неизвестный прежний исход. Защищённое действие останавливается **до исполнения**. Наблюдающее событие не заменяет блокировку.

Общая память обслуживает обычные задачи, GSD и UDR. GSD и UDR должны сохранять независимые профили и доступный разрешённый режим при отказе другого. Первичный журнал и оригиналы авторитетны, индексы производны. Отказ индекса допускает явно ограниченный поиск; отказ обязательного контроля или первичного журнала закрывает зависимый путь.

На стандартной конфигурации общие сроки инструментов `sequential_call` и `concurrent_batch` равны 0; обязательные контроллеры и сетевые операции имеют собственные сроки. Нулевой общий срок не означает отсутствия отмены, физического предела запроса или контроля затрат. Новый владелец выбирает собственные правила расходов до платных вызовов.

Полная программа: `$BN_DEST/ACCEPTANCE.md` и `$BN_DEST/Руководства/08-…`. Не повторяйте весь набор после каждого малого изменения; проверяйте затронутый контракт и один соответствующий сквозной маршрут.

## 11. Сохранение, восстановление и откат

После собственной приёмки создайте **новую личную** точку восстановления. Публичный комплект не содержит ваших будущих данных и не заменяет этот резерв.

1. Запишите версии, пути, собственные службы, порты, модели, размерность эмбеддингов и список областей данных.
2. Завершите или штатно остановите своих писателей и дочерние задания; проверьте подтверждение остановки и учёт незавершённых исходов. Не убивайте процессы по общему имени.
3. SQLite сохраняйте согласованной копией через backup API. Neo4j Community — штатным `neo4j-admin database dump` остановленной базы. Dolt/Beads — базы, историю и конфигурации, а не только JSONL. Сохраните первичные файлы, квитанции, отчёты, ключи и настройки отдельно защищённым способом. Индексы можно перестроить только при наличии оригиналов и параметров.
4. Защитите личный архив шифрованием; ключ храните отдельно. Публичный GitHub не предназначен для будущих личных состояний и секретов.
5. Восстановите резерв в **другую** папку/APFS-том; сравните суммы, прочитайте известный оригинал, отчёт, задачу и commit; проверьте восстановленный поиск. Только после этого фиксируйте успешное восстановление.
6. Для отката остановите именно новую копию, сохраните появившиеся после точки данные и верните согласованные программы, состояния и настройки. Не смешивайте несовместимые поколения баз или векторы другой размерности. Затем проверьте контроллеры и чтение известного источника.

Остановка собственной службы LaunchAgent выполняется точным путём, например:

```bash
launchctl bootout "gui/$(id -u)" \
  "$UDR_ROOT/state/services/generated/org.hermesudr.agentmemory.plist"
```

Это пример для своей службы AgentMemory; Neo4j, Dolt, шлюз и другие процессы останавливайте их штатными средствами с проверкой фактической остановки. До восстановления никогда не удаляйте работающий корень.

## 12. Если установка остановилась

| Симптом | Следующее действие |
|---|---|
| `arm64` не подтверждён | Выйти из Rosetta / использовать подходящую архитектуру; этот комплект не запускать на Intel |
| SHA или размер не совпал | Остановить установку, сохранить сообщение, повторно получить конкретный файл в новую папку; проверки не ослаблять |
| Каталог уже существует / `Already prepared` | Не перезаписывать состояние и ключи; проверить завершённые этапы, для нового расположения распаковать новую копию |
| R-путь длинный или содержит пробелы | Выбрать короткий собственный путь до подготовки; не заменять байты двоичных библиотек произвольным поиском/заменой |
| macOS блокирует программу | Проверить происхождение/сумму/подпись, затем собственное разрешение в «Конфиденциальность и безопасность»; Gatekeeper целиком не отключать |
| `bn-gsd unavailable`, обязательный контроллер не ответил | Проверить выбранный профиль, пути, манифесты, доступ модели и журнал; не отключать контроллер и не отправлять безусловно тот же запрос, пока не выяснены эффекты |
| Порт или Telegram занят | Найти конкретный собственный процесс; выбрать свободный порт/своего бота; чужую установку не останавливать |
| Инструмент не найден | Проверить включённый MCP-сервер, реальное имя и схему; запрос описаний ≤10 имён |
| Большой ввод не помещается | Разделить на адресные конечные пакеты с полным учётом; обязательный контекст не обрезать |
| Память не вернула источник | Проверить первичный журнал, область, обработку индексов и точное чтение файла; не подменять результат пересказом прежнего контекста |
| Неизвестный исход / незавершённая квитанция | Сначала проверить фактические действия и сохранённые продукты; повтор не должен создавать дубликаты или стирать неизвестный расход |

## 13. Границы подтверждения

Исполняемая подготовка очищенного комплекта проверялась на отдельной копии macOS arm64: восстановление слоёв, новые пути и ключи, пустые состояния, закрепления, импорты и собственный R. Другой владелец проходит свою приёмку служб, моделей, прав и внешних продуктов. Наличие дистрибутивов для Linux/Windows внутри основы не означает подтверждённую работу обновлённого комплекта на этих платформах.

Эта инструкция описывает полный порядок до рабочего подключения и восстановления. Она не объявляет уже выполненными действия на вашем новом Mac, не создаёт аккаунты и не наследует согласия прежнего владельца. Результат фиксируется последовательно: **получено → проверено → подготовлено → настроено → подключено → испытано → восстановление подтверждено**.
