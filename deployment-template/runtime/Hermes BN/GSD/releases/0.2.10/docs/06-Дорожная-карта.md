## Порядок следующего обновления Hermes

1. Получить официальный исходник в отдельный каталог и явно выбрать tag/commit. Не менять действующее дерево.
2. Подготовить кандидата командой ниже. Снятие/применение заплатки и замороженная установка выполняются только там. Несовместимость закрывает переход.
3. Создать отдельный профиль кандидата; настроить его собственные ключи состояния. Вход действующего владельца при необходимости ссылочно использовать из его канонического хранилища, не размножая обновляемые токены.
4. Проверить обязательные контроллеры, прежние инструменты, CLI, шлюз, дочерние агенты и восстановленный разговор. Сохранить реальный результат и контрольные суммы кандидата.
5. Остановить собственные задания и службы, сохранить точный согласованный снимок, переключить их на испытанный кандидат и сверить импорты/версию. Профиль, состояние и ограничения сохраняются; замена только исполняемого кода не выдаётся за новый ресурс задачи.
6. При отказе вернуть согласованный снимок кода и конфигурации, сохранив состояние либо восстанавливая его вместе с соответствующей независимой опорной записью. Новые расход и полномочия не восстанавливаются произвольным старым файлом.

```bash
"$PY" "$PKG/stage_update.py" \
  --source '/absolute/path/to/official-checkout' \
  --ref EXACT_COMMIT_OR_TAG \
  --destination '/absolute/path/to/new-immutable-candidate' \
  --uv '/absolute/path/to/uv' --python '/absolute/path/to/python' \
  --baseline-overlay "$PKG/release/bn-baseline.patch"
```

Последний параметр нужен только если переносится это отдельно проверенное прежнее исправление. Проверенный кандидат того же commit не доказывает совместимость следующего неизвестного выпуска. Вместо постоянного ответвления всего Hermes поддерживаются небольшая универсальная заплатка, отдельный адаптер и проверяемая граница их совместимости.

## Дальнейшая предметная приёмка

Ограничивайте следующую работу конкретным классом задач и реальными материалами. В матрицу добавляйте источник, предъявленное постусловие, фактический продукт и проверяющего. Неподтверждённое условие сохраняйте как обязательство; не создавайте ещё один проверяющий цикл ради совпадения формата. Условия высокой ответственности открываются только после нужной независимой предметной проверки и полномочия владельца.
