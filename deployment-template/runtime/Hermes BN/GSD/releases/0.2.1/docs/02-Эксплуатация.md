# Установка, запуск, обновление и откат

Команды рассчитаны на проверенную версию Hermes. При переносе задаются собственные пути и собственная авторизация владельца. Ключи, сеансы и авторизация нынешнего владельца в распространяемый пакет не входят.

## Установка в отдельную копию

Задайте абсолютные пути; каталоги состояния, управления и обычной работы должны быть раздельными.

```sh
GSD_PACKAGE='/absolute/path/host-package'
HERMES_CORE='/absolute/path/copied/hermes-agent'
HERMES_PROFILE='/absolute/path/profile'
GSD_BUNDLE="$GSD_PACKAGE/source/GSD_Integration"
GSD_OPERATOR='/absolute/path/operator'
GSD_STATE='/absolute/path/state'
GSD_WORKSPACE='/absolute/path/workspace'
PYTHON="$HERMES_CORE/venv/bin/python"
```

В поставляемом архиве есть исходная копия Hermes `source/hermes-base-f97608f.tar.gz`, исходный GSD и контрольные суммы `SHA256SUMS`. До применения проверьте их командой `shasum -a 256 -c SHA256SUMS` из корня пакета. Новую копию можно развернуть так:

```sh
mkdir -p "$HERMES_CORE"
tar -xzf "$GSD_PACKAGE/source/hermes-base-f97608f.tar.gz" -C "$HERMES_CORE"
cd "$HERMES_CORE"
uv sync --frozen --extra dev --python 3.13
```

В новом окружении после `uv sync` интерпретатор находится в `.venv/bin/python`; скорректируйте PYTHON. При установке в существующий профиль сначала остановите все принадлежащие ему процессы. Сначала проверьте и примените отдельные изменения:

```sh
git -C "$HERMES_CORE" apply --check "$GSD_PACKAGE/release/hermes-native-controls.patch"
git -C "$HERMES_CORE" apply "$GSD_PACKAGE/release/hermes-native-controls.patch"
"$PYTHON" "$GSD_PACKAGE/runtime_guard.py" --core "$HERMES_CORE" --manifest "$GSD_PACKAGE/release/core-manifest.json"
"$PYTHON" "$GSD_PACKAGE/configure_profile.py" \
  --home "$HERMES_PROFILE" --core "$HERMES_CORE" --bundle "$GSD_BUNDLE" \
  --operator "$GSD_OPERATOR" --state "$GSD_STATE" --workspace "$GSD_WORKSPACE"
```

Последняя команда показывает конкретный план. `--apply` применяет его: создаёт отдельные ключи, подключает модуль, обязательные проверки и запрет обновления на месте. Старые настройки, соединители и источники авторизации не заменяются; сохраняется снимок настроек. Произвольные прежние исполнители окажутся заблокированными. Поэтому установку в рабочий профиль выполняют только после определения допустимого режима и проверки его инструментов.

При повторной установке отличающиеся настройки учёта не принимаются автоматически. Изменения потребуют явной миграции. Автосжатие отключается: обязательное содержание должно сохраняться через адресное состояние и разделение работы. Для нового владельца до подключения выполните собственный вход в новом профиле:

```sh
HERMES_HOME="$HERMES_PROFILE" "$PYTHON" -m hermes_cli.main model
```

Параметр `--auth-store` допустим только для явно выбранного собственного канонического хранилища: он создаёт ссылку, а не копию обновляемой авторизации.

## Запуск

```sh
HERMES_HOME="$HERMES_PROFILE" "$PYTHON" "$GSD_PACKAGE/runtime_guard.py" \
  --core "$HERMES_CORE" --manifest "$GSD_PACKAGE/release/core-manifest.json" -- \
  chat --toolsets gsd_native,gsd_integration,skills
```

Для однократного запроса добавьте `--query-file /absolute/path/request.txt --format stream-json`. Штатные форматы этой версии — `text` и `stream-json`; формата `json` нет.

`gsd_research` обрабатывает обычный вопрос и предоставленные наблюдения через настоящие G/S/D с единственной областью анализа. `gsd_catalog` ищет адреса, `gsd_contract` возвращает полный договор, `gsd_analyze` исполняет расширенный выбранный состав с явными question/scope, `gsd_work` — адресную операцию, `gsd_work_file` — независимые записи. `gsd_runtime_status` показывает общий расход; `gsd_stop` останавливает семью и запрашивает отмену живых детей. Адресное `read_file` разрешено только для обычных локальных файлов своей области; пути авторизации и ключей закрыты. Общий поиск по содержимому файлов пока закрыт.

Шлюз запускается той же проверенной командой с `gateway run`. Для локального API используйте [официальную инструкцию](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server/): собственный API_SERVER_KEY сохраняется в `.env`; адрес и порт — в `config.yaml`. Открывать его наружу для проверки не требуется. Длинный путь профиля на macOS может превысить предел Unix-сокета; применяйте короткий абсолютный путь профиля или проверенный короткий псевдоним.

## Проверка и фиксация процедуры

Модельный `gsd_case_change(commit)` закрыт. После реального `gsd_work` оператор отдельно сверяет содержание результата, его происхождение, текущее основание и адреса выходов. Артефакт сначала сохраняется исходным `update`, затем допускается фиксация:

```sh
"$PYTHON" "$GSD_PACKAGE/operator.py" --settings "$GSD_OPERATOR/settings.json" \
  commit-procedure --job-id 'J.…' --run-id '…' --payload-file '/absolute/path/commit.json' \
  --request-id 'unique-review-id' --review-reason 'Конкретная проверка постусловия и её ограничения'
```

`commit.json` имеет исходные поля `procedure_id`, `attempt_id`, `status`, `output_ids`, `expected_revision`, `postcondition_observed`, при необходимости `cost`. Требуются завершённый настоящий ребёнок, правильная процедура, текущий отпечаток входа и существующий выход. Операторская проверка не становится независимой профессиональной экспертизой без действительного компетентного исполнителя.

Другие команды управления:

```sh
"$PYTHON" "$GSD_PACKAGE/operator.py" --settings "$GSD_OPERATOR/settings.json" status --sid '…'
"$PYTHON" "$GSD_PACKAGE/operator.py" --settings "$GSD_OPERATOR/settings.json" recover
"$PYTHON" "$GSD_PACKAGE/operator.py" --settings "$GSD_OPERATOR/settings.json" attach-case --sid '…' --run-id '…'
"$PYTHON" "$GSD_PACKAGE/operator.py" --settings "$GSD_OPERATOR/settings.json" resume --family 'F.…' --reason '…'
"$PYTHON" "$GSD_PACKAGE/operator.py" --settings "$GSD_OPERATOR/settings.json" resume-case --sid '…' --run-id '…' --store-revision 1 --reason '…'
```

Редакции берутся из текущего состояния, не копируются из примера. `case-change --help` показывает исходные операции ограниченного принятия, закрытия, остановки, ремонта и пересмотра. Остановленный случай не возобновляется модельным инструментом.

Отдельный связанный запуск:

```sh
"$PYTHON" "$GSD_PACKAGE/operator.py" --settings "$GSD_OPERATOR/settings.json" \
  new-run --sid '…' --input-file '/absolute/path/new-run.json'
```

`new-run.json` содержит исходные поля `case`, `triggers`, `components`, `previous_run_id`, `expected_store_revision`, `reason`, `request_id`. Идентичность случая и область бюджета наследуются; расход старого запуска не исчезает. Это операторское решение, не способ модели начать тот же случай с новым ресурсом.

## Точный файловый допуск

```sh
"$PYTHON" "$GSD_PACKAGE/operator.py" --settings "$GSD_OPERATOR/settings.json" \
  grant-artifact --sid '…' --name report.md --content-file '/absolute/path/reviewed-report.md' \
  --ttl 300 --reason 'Проверенное точное содержимое и назначение'
```

Полученный grant_id передаётся `gsd_save_artifact` вместе с теми же именем и текстом. Разрешение привязано к семье, полным параметрам, сроку и отсутствию цели. Файл создаётся атомарно без перезаписи. Резерв разрешения сохраняется до эффекта; неизвестный исход не повторяется. Отзыв: `operator.py --settings … revoke-grant --grant-id … --reason …`. Это специальный исполнитель текстового артефакта, не универсальный допуск сетевых изменений или произвольного кода.

## Обновление

```sh
"$PYTHON" "$GSD_PACKAGE/stage_update.py" \
  --source '/absolute/path/official-local-hermes-checkout' --ref 'explicit-commit-or-tag' \
  --destination '/absolute/path/new-candidate' --uv '/absolute/path/uv' --python '/absolute/path/python3.13'
```

Команда разрешает указанный ref в точный commit, создаёт отдельный кандидат, отказывает при конфликте изменений, устанавливает замороженные зависимости и выполняет договорные испытания. Рабочий экземпляр не переключается. Новый `bn-gsd-compatibility.json` передаётся установщику через `--core-manifest`. До переключения повторяются реальные запросы поставщика и шлюза и проверяются сохранённые интеграции. При несовместимости источник не достраивается автоматически.

Прежняя поправка обнаружения инструментов Hermes BN сохранена отдельно в `release/bn-baseline.patch`. Для продолжения именно этой установки укажите `--baseline-overlay "$GSD_PACKAGE/release/bn-baseline.patch"`; для иной установки сначала проверьте её применимость. Неперенесённые пользовательские изменения нельзя считать сохранёнными только по прохождению испытаний GSD.

## Откат и восстановление

Остановите принадлежащие профилю процессы. Установщик сообщает путь снимка настроек.

```sh
"$PYTHON" "$GSD_PACKAGE/rollback_profile.py" --home "$HERMES_PROFILE" --snapshot '/absolute/path/install-snapshot'
"$PYTHON" "$GSD_PACKAGE/rollback_profile.py" --home "$HERMES_PROFILE" --snapshot '/absolute/path/install-snapshot' --apply
git -C "$HERMES_CORE" apply --reverse --check "$GSD_PACKAGE/release/hermes-native-controls.patch"
git -C "$HERMES_CORE" apply --reverse "$GSD_PACKAGE/release/hermes-native-controls.patch"
```

Изменившиеся после установки настройки не перезаписываются: нужен явный разбор. Подписанное состояние, ключи, неизвестный расход и результаты сохраняются. До обратного изменения исходников проверьте, что эта копия не обслуживает другой профиль, которому нужны добавленные проверки.

Для восстановления данных сохраняются согласованные `state.sqlite3`, `blobs/`, операторские ключи и контрольная точка. Несовпадение базы с независимо сохранённой контрольной точкой блокирует выполнение. Воспроизведено восстановление точной текущей копии; произвольный откат старого состояния с последующим списанием неизвестного расхода не реализован. Не изменяйте управляемую базу исходным CLI GSD в обход worker: это нарушает согласованность контрольной точки.
