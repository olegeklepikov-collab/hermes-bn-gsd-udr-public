# Consensus Knowledge Work Skill

Ищи научные основания через Consensus и составляй проверяемые обзоры и таблицы. Разделяй результаты отдельных исследований, предположения и выводы по совокупности данных.

## When to Use

Пользователь просит Consensus, научные источники для делового решения, академический обзор или проверку исследовательского утверждения. Для текущих новостей, оперативных сведений о компаниях и обычных веб-страниц выбирай подходящие подключённые средства поиска.

## Prerequisites

Экземпляр: `__HERMES_BN_ROOT__`.
Ожидаются сервер `consensus`, инструменты `terminal`, `read_file` и `search_files`.
Ключ хранится в собственном `data/.env` как `MCP_CONSENSUS_API_KEY`; не читай его содержимое инструментом и не показывай его в сообщениях или аргументах команд.
Настройки: `__HERMES_BN_ROOT__/Consensus/config/profiles.json`.
Источник ограничений: https://docs.consensus.app/api-reference/query-for-relevant-papers

## How to Run

1. Узнай актуальную схему сервера `consensus` через доступный поиск/описание инструментов. Используй документированные параметры; набор зависит от клиента и плана.
2. Для всех параметров REST API используй `terminal` и собственную команду `consensus-bn`. Она отправляет ключ только в заголовке на `https://api.consensus.app/v1/search`.
3. Сохраняй результаты на AgentRuntime2. Большие ответы исследуй через `read_file` и `search_files`; повторные одинаковые запросы используют собственную сохранённую копию.

```bash
consensus-bn profiles
consensus-bn search --profile business --query "research question" --output "__HERMES_BN_ROOT__/workspace/evidence.json"
consensus-bn search --profile open-access-excerpts --query "specific method, result or measured value" --output "__HERMES_BN_ROOT__/workspace/passages.json"
consensus-bn search --params /absolute/path/query.json --output /absolute/path/results.json
consensus-bn record --from-file /absolute/path/results.json --paper-id "exact DOI or Consensus URL"
```

`record` читает точную запись из сохранённой выдачи; он не запрашивает полный текст. Для принудительного обновления используй `--refresh`.

## Procedure

1. Зафиксируй вопрос, население/объект, вмешательство или фактор, сравнение, исход, период и контекст. Для делового вопроса уточняй, каким исследованиям можно переносить результат на данную организацию.
2. Начни с широкого поиска. Используй научные термины и несколько самостоятельных направлений поиска: поддерживающие, противоположные и альтернативные объяснения. Не выдавай одну выдачу за полный обзор литературы.
3. Затем применяй необходимые фильтры. `domain` — код научной дисциплины, не интернет-домен. `country` — страна исследования по ISO alpha-2. `journal_name` повышает соответствующие журналы в выдаче и не исключает остальные.
4. Период задаётся year_min/year_max и month_min/month_max; месяц требует соответствующего года. Сохраняй фактическую дату поиска.
5. `exclude_preprints=true` нужен для корпуса рецензированных работ. Статус `is_preprint` сохраняй при более широком поиске. Тип исследования может быть машинной классификацией; проверяй методы, особенно если они определяют вывод.
6. Не применяй human/controlled к любой теме автоматически. Фильтры выборки, длительности и типов исследований могут исключать записи с неполными метаданными. При пустой выдаче ослабляй один фильтр и сохраняй основание изменения.
7. Сохраняй точное название, авторов, год, журнал, DOI, URL, дизайн, выборку, контекст, измерения, результат, ограничения и уровень прочитанного материала. Неизвестные значения оставляй неизвестными.
8. Для проверки методов и чисел выбирай include_full_text_chunks=true. Ответ может содержать до 3 выдержек на статью и до 60 на запрос; null допустим. Каждую выдержку связывай с DOI, URL и её разделом.
9. Доступные выдержки происходят из открытых полных текстов. Закрытые тексты издательских партнёров, используемые сайтом Consensus, не выдаются таким способом. Выдержки не равны прочтению всей статьи.
10. Для существенного утверждения прочитай исходную публикацию через DOI/URL с подходящим подключённым средством или укажи ограничение доступа. Перед окончательной библиографией сверяй название, авторов и год с издателем или Crossref. Год первой онлайн-публикации может отличаться от года выпуска журнала; сохраняй оба, если это важно. В проверке DOI 10.3102/0034654314564881 индекс указал 2013, а издатель и Crossref — 2015: год индекса не является окончательным. Сверяй статус исправления/отзыва с издателем. Не придумывай DOI и страницы.
11. Показатель semantic_score — соответствие запросу, а не качество исследования; он доступен лишь для первых 50 результатов. Цитируемость и квартиль журнала также не заменяют оценку дизайна, смещений и применимости.
12. Пагинация начинается с page=0. Ориентируйся на page_size, next_page и is_end из ответа. Увеличенное число результатов может быть ограничено планом; всего по одному запросу не более 1000 записей. Удаляй повторы по DOI или точному URL.
13. API и MCP расходуют общий месячный запас. Обычный запрос до 100 полученных публикаций считается одним вызовом. Повторять пустые или уже сохранённые запросы без причины не следует. При 429 учитывай retry-after; при исчерпанной месячной квоте не продолжай автоматические попытки.
14. Не создавай постоянные задания наблюдения без отдельного запроса. API не содержит собственного планировщика или API Research Agent: последовательность поисков и обобщение выполняет Hermes.
15. Библиотека, коллекции, загрузка частных документов, граф цитирования, Deep Search и Research Agent доступны на сайте; не представляй их как уже подключённые операции этого REST API. Передача частных материалов требует конкретных данных и цели пользователя.

## Pitfalls

- В официальных источниках встречаются прежние лимиты и параметры. Используй текущие API/MCP plans and access и живую схему сервера.
- `/v1/quick_search` устарел; собственная оболочка использует `/v1/search`.
- Fetch описан для клиента ChatGPT. Для Hermes не имитируй другой клиент ради недоступного инструмента. При отсутствии fetch используй возвращённую библиографическую запись и проверяй DOI/публикацию.
- Заголовок или краткий takeaway не является полноценным доказательством. Указывай: прочитана аннотация, выдержки или полный текст.
- Отсутствие источника в индексе не означает отсутствия исследования. Пустая выдача не доказывает отсутствия эффекта.
- Общая оценка «консенсуса» не выводится подсчётом совпадающих takeaway. Учитывай независимость исследований, дизайн, размеры эффектов, противоречия и переносимость.

## Verification

Проверь соответствие фильтрам, фактически применённый размер страницы, повторяющиеся записи, DOI и URL. Сравни вывод с аннотацией/выдержками и обозначь границы прочтения. Для причинного утверждения оцени, позволяет ли дизайн устанавливать причинность; для сравнительной таблицы сохраняй единицы и условия измерений.
