# Подключение, обновление и откат

Все приведённые команды выполняются из корня установленного Hermes BN. На другой машине сначала задайте собственный корень и создайте собственные профиль, секреты, зарегистрированные проекты и настройки общей памяти. Переносный пакет не содержит личных данных или авторизации.

## Повторное подключение текущего выпуска

```sh
source ./environment.sh
./hermes-agent/venv/bin/python ./Cognee/operator/connect.py 1.1.8
```

Скрипт подключает отдельный выпуск памяти, обновляет три профиля, описания инструментов, контрольные суммы разрешённых переходников, согласованные правила GSD/UDR и навык. Ядро Hermes и исходники GSD/UDR не изменяются. После подключения перезапустите только шлюз BN своим действующим средством управления службой. Новый Cognee не требует отдельной постоянной сетевой службы: рабочий процесс запускается по разрешённому вызову; модельный переходник слушает только случайный адрес loopback на время операции.

## Закреплённая установка Cognee

Текущая среда создана нативно отдельным Python 3.13. Установлен Cognee 1.6.3; полный список зависимостей сохранён в `Cognee/source/requirements-pinned.txt`. Для воспроизведения в новом корне:

```sh
./hermes-agent/venv/bin/python -m venv ./Cognee/software/venv
./Cognee/software/venv/bin/python -m pip install -r ./Cognee/source/requirements-pinned.txt
```

Это воспроизводит программную среду, но не создаёт владельца, совместимость ядра, область памяти или авторизацию. Требуется действующая интеграция общей памяти с GSD/UDR и проверка нативных интерфейсов. Автоматического универсального развёртывания на произвольном Hermes пакет не обещает.

## Обновление Hermes

Сначала установите новый Hermes отдельно. Повторно проверьте интерфейсы `tool_execution/next_call`, обязательного исполнения, `SubagentLifecycleService`, наследования ограничений и MCP. Затем выполните проверки общей памяти, обязательных контроллеров, одну обработку документа, поиск с повторным чтением, GSD/UDR и Telegram. Только подтверждённую пару подключайте действующему профилю. Старый запечатанный манифест ядра нельзя просто переписать для обхода несовместимости.

Обновление Cognee также делается в новой среде: версии SDK, зависимостей и схем баз закрепляются отдельно. Не запускайте автоматическую миграцию на единственной копии состояния.

## Откат подключения

Остановите только шлюз BN, затем:

```sh
source ./environment.sh
./hermes-agent/venv/bin/python ./Cognee/operator/connect.py rollback
```

Скрипт проверяет SHA-256 предшествующей контрольной копии, восстанавливает настройки общей памяти 1.0.3, правила и три профиля; удаляет новый навык. Оригиналы, журнал и производные базы Cognee сохраняются. После этого запустите шлюз BN. Откат настроек не удаляет новые записи памяти и не заменяет первичную базу прежней копией.

## Восстановление данных

Для согласованной резервной копии остановите записи Cognee и общую память; сохраните `Memory/settings.json`, первичную `Memory/state/memory.sqlite` через SQLite backup, `Cognee/state` целиком, `Cognee/operator/knowledge-work.owl`, активный выпуск памяти и закреплённую среду. Полная частная копия также требует собственного ключа подписи общей памяти и действующей авторизации; они не входят в обезличенный пакет.

При восстановлении на другой путь исправьте абсолютные настройки и `knowledge_docs.text_path`. Прежде чем подключать действующий шлюз, выполните `PRAGMA integrity_check`, проверьте хеши оригиналов и запросите цитату из восстановленной производной базы. Проверка `checks/recovery_fallback.py` выполняла эти действия на отдельной копии и не заменяла рабочую базу.

## Воспроизводимые проверки

```sh
source ./environment.sh
cd ./Memory/releases/1.1.8
../../../hermes-agent/venv/bin/python -m unittest discover -s bn_memory -p "test_*.py" -v
```

Проверки обязательного исполнения ядра выполняются из `hermes-agent`: `venv/bin/python -m pytest tests/plugins/test_required_execution_control.py -q`. Для живой инструментальной проверки используется `Cognee/checks/native_connected.py query`: она требует действующей собственной авторизации и предварительно обработанного проверочного источника. Проверка требует непустых цитат, подтверждённых первичным текстом; одних имён инструментов недостаточно. В переносном пакете проверочный скрипт и открытые фикстуры находятся в `verification` и `fixtures`; установите их в указанные каталоги своей копии и зарегистрированного проекта. Остальные частные сценарии текущей машины перечислены в матрице.
