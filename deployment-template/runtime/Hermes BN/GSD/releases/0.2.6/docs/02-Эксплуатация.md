# Установка, запуск, управление и откат

## Требования

Подтверждённый Hermes: commit `f97608f178d1ffeca59860195ab7da295f7c8e5f`, Python 3.13.14, macOS arm64. Изоляция местного терминала использует `/usr/bin/sandbox-exec`; иной системе нужен проверенный адаптер изоляции. При его отсутствии местный путь не получает молчаливого допуска. Для R укажите установленный местный R и библиотеки.

Рабочая установка размещает расширение, корпус, состояние и ключи вне обычной рабочей папки:

```text
BN_ROOT/
  hermes-agent/                 установленный Hermes
  data/                        профиль и прежние входы
  workspace/                   обычные файлы и черновики
  GSD/releases/0.2.2/           этот пакет
  GSD/vendor/1.1.0/             source/GSD_Integration
  GSD/state/                   подписанный Store и неизменяемые входы
  GSD/operator/                ключи, настройки, опорная запись, разрешения
```

## Установка в отдельной копии

Задайте реальные абсолютные пути. Команды не подразумевают существования чужих каталогов или входов.

```bash
BN_ROOT='/absolute/path/to/Hermes BN'
PKG="$BN_ROOT/GSD/releases/0.2.2"
CORE="$BN_ROOT/hermes-agent"
PY="$CORE/venv/bin/python"
export HERMES_HOME="$BN_ROOT/data"

# До применения сохраните собственные код, профиль и окружение.
git -C "$CORE" rev-parse HEAD
git -C "$CORE" status --short
git -C "$CORE" apply --check "$PKG/release/hermes-native-controls.patch"
git -C "$CORE" apply "$PKG/release/hermes-native-controls.patch"

# Сначала план, затем тот же вызов с --apply.
"$PY" "$PKG/configure_profile.py" \
  --home "$HERMES_HOME" --core "$CORE" \
  --bundle "$BN_ROOT/GSD/vendor/1.1.0" \
  --operator "$BN_ROOT/GSD/operator" --state "$BN_ROOT/GSD/state" \
  --workspace "$BN_ROOT/workspace" --runtime-root "$BN_ROOT" \
  --r-runtime '/absolute/path/to/local-r-runtime'
```

Перед `--apply` исходный GSD должен быть извлечён из `source/GSD_Integration` в указанный каталог. Применение создаёт закрытые ключи, начальное состояние, снимок конфигурации и четыре обязательные привязки контроля, сохраняет старые подключения и выбирает GSD для CLI, приложения, HTTP, Telegram, TUI и планировщика. Повторная установка не сбрасывает состояние, ограничения или расход. Существующий вход владельца сохраняется; для новой установки войдите отдельно штатным `hermes auth`.

## Запуск и проверка

```bash
"$PY" "$PKG/runtime_guard.py" --core "$CORE" \
  --manifest "$PKG/release/core-manifest.json"
"$PY" -m hermes_cli.main chat --oneshot \
  --in "$BN_ROOT/workspace" \
  -q 'Вызови gsd_runtime_status и gsd_status; различи состояние хоста и сведения исходной поставки.'
```

Штатные программа, CLI и служба шлюза используют тот же изменённый Hermes и профиль. На текущем экземпляре запуск предусмотрен прежними `bin/hermes-bn`, `bin/hermes-bn-desktop`, `bin/hermes-bn-telegram`; имена другого пользователя могут отличаться. Для HTTP используйте штатный API Server Hermes, только `127.0.0.1`, с отдельным закрытым `API_SERVER_KEY`; ключ не записывайте в общий отчёт. Настройка: [API Server](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server/).

Синтетическая проверка Python в однократном CLI может потребовать явного `--yolo`, поскольку этот режим не задаёт интерактивных вопросов о командах. Это не отключает обязательный GSD-контроль и изоляцию ОС. Не делайте эту опцию постоянным общим значением.

## Работа агента

- Обычная содержательная задача: загрузить `bn-gsd:gsd-native-orchestration`, затем `gsd_research` с одной областью, вопросом и явными наблюдениями.
- Точный состав компонентов: `gsd_analyze`; договор исходной структуры соблюдать буквально.
- Адресная операция: `gsd_contract`, соответствующий полный навык и `gsd_work`. Для процедуры требуется готовый случай исходного движка.
- Разбиение независимых записей: `gsd_work_file`, полный файл и SHA-256; не превращать отдельные ответы в проверенный общий вывод.
- Учёт работы: прежний Beads MCP. Состояние, версии данных и научные свидетельства не заменяются заметкой задачи.
- Остановка: `gsd_stop`. Статус: `gsd_runtime_status`. Исходный `gsd_status` содержит ограничения поставщика, которые надо отличать от установленных возможностей адаптера.

## Команды владельца

Эти команды не предоставлены модели. Передача результата роли не означает принятия постусловия.

```bash
SETTINGS="$BN_ROOT/GSD/operator/settings.json"
"$PY" "$PKG/operator.py" --settings "$SETTINGS" status --sid SESSION_ID
"$PY" "$PKG/operator.py" --settings "$SETTINGS" recover
"$PY" "$PKG/operator.py" --settings "$SETTINGS" resume \
  --family FAMILY_ID --reason 'Подтверждённая причина продолжения'
"$PY" "$PKG/operator.py" --settings "$SETTINGS" attach-case \
  --sid SESSION_ID --run-id RUN_ID
"$PY" "$PKG/operator.py" --settings "$SETTINGS" commit-procedure \
  --job-id JOB_ID --run-id RUN_ID --payload-file '/absolute/path/review.json' \
  --request-id REVIEW_ID --review-reason 'Фактически проверенное постусловие и его область'
"$PY" "$PKG/operator.py" --settings "$SETTINGS" commit-external-procedure \
  --job-id JOB_ID --run-id RUN_ID --payload-file '/absolute/path/review.json' \
  --request-id REVIEW_ID --review-reason 'Фактически проверенное внешнее постусловие'
"$PY" "$PKG/operator.py" --settings "$SETTINGS" grant-tool \
  --sid SESSION_ID --name EXACT_MCP_NAME \
  --arguments-file '/absolute/path/exact-arguments.json' --ttl 300 \
  --reason 'Точное действие, согласованное владельцем'
"$PY" "$PKG/operator.py" --settings "$SETTINGS" revoke-grant \
  --grant-id GRANT_ID --reason 'Причина отзыва'
```

`grant-artifact` создаёт одноразовое разрешение на один точный текстовый файл; перезапись запрещена. `case-change`, `resume-case`, `new-run` используют исходный жизненный цикл. `migrate-state` инспектирует предусмотренную поставщиком миграцию; неподтверждённый исторический расход не восстанавливается догадкой. Изменение профиля, полномочий или исчерпанного ресурса не достигается повторным обычным запросом.

## Откат

`rollback_profile.py --snapshot SNAPSHOT` возвращает конкретный снимок установки, сохраняя GSD-состояние и ключи. `restore_cutover.py` возвращает точный код и профиль до первой установки GSD, сохраняя прежнее исправление поиска инструментов. Для второго способа нужен собственный закрытый снимок, не входящий в общий архив.

```bash
"$PY" "$PKG/restore_cutover.py" --runtime-root "$BN_ROOT" \
  --backup '/absolute/path/to/authenticated-cutover-backup'
# Применение требует --apply и явно сверенной текущей суммы config.yaml.
"$PY" "$PKG/restore_cutover.py" --runtime-root "$BN_ROOT" \
  --backup '/absolute/path/to/authenticated-cutover-backup' \
  --expected-config-sha256 REVIEWED_SHA256 --apply
```

Сначала остановите собственные активные задания и приложение. Снимок до GSD зашифрован; ключ хранится отдельно. После полного отката запускаются прежние службы. Данные GSD не удаляются; повторное подключение не обнуляет их расход. Несовпадение базы и независимой опорной записи требует восстановления согласованного снимка; автоматическое «исправление» подписи не выполняется.
