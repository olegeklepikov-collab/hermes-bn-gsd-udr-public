# Повторение проверок на своей машине

Задайте HERMES_BN_ROOT и HERMES_UDR_ROOT абсолютными путями своей установки. Все команды исполняются Python именно этого BN. Обновитель и самотест требуют нативной macOS arm64. Не запускайте модельные проверки до готовности Foundation и своих входов.

```bash
export HERMES_BN_ROOT="/свой/путь/Hermes BN"
export HERMES_UDR_ROOT="/свой/путь/Hermes UDR"
BN_PY="$HERMES_BN_ROOT/hermes-agent/venv/bin/python"
"$BN_PY" -m pytest -q tests/test_repair.py
"$BN_PY" tests/check_ocr.py
```

После проверки своих путей и ролей выполните tests/native_e2e.py. Он создаёт отдельные синтетические PDF, задачи и исследование, вызывает модель на пяти фазах и сохраняет подтверждения. Для профилей: tests/profile_probe.py bn-gsd-only и bn-udr-only. Затем штатно перезапустите только свой шлюз и выполните tests/restart_readback.py. Для проверки API задайте HERMES_REPAIR_API_URL точным местным адресом своего шлюза; tests/gateway_probe.py использует его собственный ключ из профиля, не выводя значение.

Переносимые драйверы используют переменные путей. Сохранённая приёмка относится к экземпляру разработчика; запуски с другими ключами, ОС и местными доработками проверяются отдельно. В исходном сквозном прогоне исправлялась форма операторского плана без новой генерации отчёта: фактическое чтение всех пяти фаз и окончательная передача сохранены.

В profiles-only остаётся ваша редакция OCR. Наши тесты ожидают схему результата r8; для другой местной схемы интегратор проверяет эквивалентные фактические результаты, а не подменяет неизвестные поля успехом. Неподдержанные форматы и отказ защиты сохраняются как ограничения.
