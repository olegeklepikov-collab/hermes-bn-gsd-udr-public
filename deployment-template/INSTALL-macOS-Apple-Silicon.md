# Hermes BN: полная установка на новый Mac с Apple Silicon

Дата комплекта: 20 октября 2026 года. Исполняемая подготовка проверена на macOS 26.5.1 (25F80), arm64; совместимость с более ранней macOS требует отдельной проверки. Версия инструкции: `public-2026-10-20-gsd-udr-parser-r4`. Новое обновление включает прежний r2; основу clean-r2 использовать без изменения.

Репозиторий: https://github.com/olegeklepikov-collab/hermes-bn-gsd-udr-public

Установочные архивы: https://github.com/olegeklepikov-collab/hermes-bn-gsd-udr-public/releases/tag/public-2026-10-20-gsd-udr-parser-r4

Актуальная инструкция и средства настройки: https://github.com/olegeklepikov-collab/hermes-bn-gsd-udr-public/releases/tag/public-2026-10-20-gsd-udr-parser-r4

## 1. Что именно устанавливается

Это самостоятельная нативная установка Hermes BN с GSD, UDR и общей системой памяти. Docker и WSL не используются. Комплект обезличен и не зашифрован. Он не переносит аккаунты, ключи, историю, исследовательские материалы, разрешения и подтверждение работоспособности прежнего владельца.

Файлы репозитория — исходники, документация и средства развёртывания. Полные исполняемые среды находятся в материалах выпуска. Одного скачивания исходников или `git clone` недостаточно.

Обязательны два согласованных слоя:

| Слой | Итоговый файл | Размер | SHA-256 |
|---|---|---:|---|
| Очищенная основа | `Hermes-BN-GSD-and-UDR-Complete-new-user-20261014-clean-r2.tar.zst` | 17 801 925 827 байт | `cbf18ffe88011c66fea0498068c2119ad3bacad376a35bd6fbe2f9e9b7f9fce1` |
| Обновление parser-r4 | `Hermes-BN-GSD-and-UDR-new-user-update-20261020-r4.tar.zst` | Точный размер в recovery-set.json | Точная SHA-256 в recovery-set.json |

Основа опубликована десятью частями; обновление — одним файлом. Общий объём и точная сумма нового обновления определяются recovery-set.json; сумму старого r2 для нового архива не использовать. Программа `restore.py` проверяет каждую часть, порядок, итоговый размер и SHA-256. Старую основу без `clean-r2`, полный личный архив и прежние обновления сюда не подмешивать.

## 2. Подготовка Mac

1. В меню Apple → «Об этом Mac» проверьте процессор Apple M1/M2/M3/M4 или другой Apple Silicon. В Терминале `uname -m` должен вернуть `arm64`. На Mac Intel этот двоичный комплект не применять. Не запускайте Терминал через Rosetta.
2. Рабочие данные разместите на APFS. exFAT/NTFS подходят для перевозки архивов, но не для рабочих баз и исполняемой установки с правами и символическими ссылками.
3. Практический запас — не менее 150 ГБ свободного места на время установки. Это резерв для частей, собранных архивов, распакованной основы, обновления и рабочих данных, а не измеренное минимальное требование. Для крупных корпусов нужен дополнительный объём. 16 ГБ памяти — исходный ориентир; параллельные индексы и большие исследования требуют собственного измерения нагрузки.
4. Используйте отдельный каталог и текущую обычную учётную запись macOS. Существующие Hermes, Homebrew, R, Zotero и их данные не заменять автоматически. Учётная запись администратора потребуется только для штатных системных установщиков.
5. На новом Mac установите инструменты командной строки Apple, если их ещё нет:

```bash
xcode-select -p
```

Если команда сообщает об отсутствии инструментов:

```bash
xcode-select --install
```

Завершите системный диалог. Сведения Apple: [документация Xcode](https://developer.apple.com/xcode/resources/). Затем проверьте:

```bash
uname -s
uname -m
sw_vers
python3 --version
git --version
/usr/bin/curl --version
```

Для начальных средств требуется Python не ниже 3.9. Если `python3` отсутствует, установите Python 3 с [официальной страницы Python для macOS](https://www.python.org/downloads/macos/) и откройте новое окно Терминала. Внутри комплекта собственный Python; системный нужен для начальной загрузки и проверки.

Для краткости далее используются отдельные переменные `BN_KIT`, `BN_DEST`, `BN_ROOT`, `UDR_ROOT`. Переменные `HOME` и `CODEX_HOME` изменять нельзя.

## 3. Получение публичного комплекта

В новом окне Терминала:

```bash
umask 077
mkdir -p "$HOME/HermesInstall"
cd "$HOME/HermesInstall"
git clone --depth 1 --branch public-2026-10-20-gsd-udr-parser-r4 \
  https://github.com/olegeklepikov-collab/hermes-bn-gsd-udr-public.git kit
BN_KIT="$HOME/HermesInstall/kit"
cd "$BN_KIT"
shasum -a 256 -c SHA256SUMS
python3 restore.py --download \
  --parts-dir "$HOME/HermesInstall/parts" \
  --output-dir "$HOME/HermesInstall/archives"
```

`SHA256SUMS` проверяет внешние средства установки, руководство и программы распаковки; части и архивы проверяются отдельно по `recovery-set.json`. Исходники закреплены Git и собственным манифестом `deployment-template/SOURCE-MANIFEST-SHA256.json`. Авторизация GitHub, GitHub CLI и ключ расшифрования не нужны. Загрузка может занять значительное время. Успех — сообщение о проверенном полном комплекте «основа + обновление». Если существующий файл не совпал с суммой, программа останавливается и не перезаписывает его. Выберите новый каталог либо отдельно разберите повреждённый файл; проверку сумм не отключать.

Альтернатива без `git clone`: на странице репозитория выберите Code → Download ZIP, распакуйте и задайте `BN_KIT` фактическим абсолютным путём этой папки. Материалы выпуска всё равно нужны. После распаковки ZIP восстановите право исполнения командой `chmod +x "$BN_KIT/restore-tools/zstd"`; сценарий `restore.sh` вызывается через `bash`. При ручной загрузке положите десять частей в `parts/base/`, файл обновления в `parts/update/`, затем выполните `restore.py` без `--download` с явными путями.

Загруженная часть проверяется до включения в итоговый архив. Уже собранный совпадающий архив используется повторно. Программа не продолжает произвольно повреждённый `.partial`: сначала разберите причину остановки. Совпадение SHA подтверждает соответствие опубликованному комплекту; само по себе оно не заменяет подпись поставщика.

### Если установка r2 уже работает

Не скачивайте архивы заново и не распаковывайте их поверх данных. Получите отдельную новую папку только с инструкцией и средствами оператора:

```bash
git clone --depth 1 --branch public-2026-10-20-gsd-udr-parser-r4 \
  https://github.com/olegeklepikov-collab/hermes-bn-gsd-udr-public.git \
  "$HOME/HermesInstall/kit-r3"
BN_KIT="$HOME/HermesInstall/kit-r3"
```

Каталог `kit-r3` должен быть новым. Задайте `BN_DEST` и `BN_ROOT` фактическими путями своей уже установленной копии, затем используйте маршрут работающего экземпляра в разделе 9. Подготовительные программы создания новых состояний повторно не выполняются.

## 4. Распаковка и применение обновления

Пример назначения — `$HOME/hbn`. Это должна быть новая, ещё не существующая папка. Если домашний путь содержит пробелы или слишком длинный для R, выберите иной собственный короткий путь на APFS; ограничения ниже проверяются до подготовки.

```bash
BN_DEST="$HOME/hbn"
test ! -e "$BN_DEST"
test ! -e "$HOME/HermesInstall/update-r2"

bash "$BN_KIT/restore-tools/restore.sh" \
  "$HOME/HermesInstall/archives/Hermes-BN-GSD-and-UDR-Complete-new-user-20261014-clean-r2.tar.zst" \
  "$BN_DEST"

python3 "$BN_DEST/verify.py" "$BN_DEST"

bash "$BN_KIT/restore-tools/restore.sh" \
  "$HOME/HermesInstall/archives/Hermes-BN-GSD-and-UDR-new-user-update-20261020-r4.tar.zst" \
  "$HOME/HermesInstall/update-r2"

python3 "$BN_KIT/apply-update.py" \
  --base-root "$BN_DEST" \
  --update-root "$HOME/HermesInstall/update-r2"
```

Продолжайте только после успешного завершения каждой команды. При проверке основы ожидается `mismatches: 0`. Применение обновления само проверяет полезные файлы, полный конечный манифест, права, ссылки и лишние пути. Сохраняйте `RESTORE-APPLIED.json`.

Основа и распакованное обновление должны быть отдельными соседними каталогами; обновление нельзя размещать внутри основы. Эти действия не запускают программы и службы. Встроенный `restore-tools/zstd` позволяет распаковать комплект без установки Homebrew.

До подготовки можно отдельно повторить проверку при наличии конкретной ошибки или подозрения:

```bash
python3 "$BN_KIT/apply-update.py" \
  --base-root "$BN_DEST" \
  --update-root "$HOME/HermesInstall/update-r2" --verify-only
```

Не запускайте эту проверку неизменного архива после подстановки собственных путей, входа в аккаунты или создания рабочих данных: такие изменения ожидаемо отличаются от заводского манифеста. Для установленной системы действуют новые местные манифесты.

## 5. Нативный R.app и системные зависимости

R.app — графическое приложение `/Applications/R.app`; его вычислительная основа — `/Library/Frameworks/R.framework`. Это отдельный компонент от изолированных сред R BN/UDR.

1. Найдите поставленный пакет:

```bash
find "$BN_DEST/system-software" -name 'R-4.6.1-arm64.pkg' -print
```

2. Проверьте подпись найденного файла: `pkgutil --check-signature /полный/путь/R-4.6.1-arm64.pkg`. Откройте пакет через Finder или `open /полный/путь/R-4.6.1-arm64.pkg`.
3. Прочитайте лицензию и завершите установку в системном окне. Пароль администратора вводите только туда. Официальный источник: https://cran.r-project.org/bin/macosx/ . Если уже используется другая версия R, сначала решите вопрос совместимости; не заменяйте её молча.
4. Проверьте:

```bash
/Library/Frameworks/R.framework/Resources/bin/R --version
open /Applications/R.app
```

Serena использует `R/serena-bin/R` и отдельную библиотеку `languageserver` 0.3.20, а не произвольную библиотеку пользователя. 42 двоичных пакета macOS arm64 и их исходники включены. На иной версии R/ОС нужна отдельная сборка и проверка. Положительное нахождение входящих ссылок R в исходной приёмке не подтверждено; обзор и чтение определения символа проверены.

В комплекте также есть системные дистрибутивы, закрепления и рецепты зависимостей. Homebrew при необходимости: https://brew.sh/ . Не копируйте весь `/opt/homebrew` поверх существующего: сначала сопоставьте `DISTRIBUTIONS.json`, каталоги `system-software`, `shared-software`, `distribution` и уже установленные версии. Для Neo4j требуется Java 21; точный путь задаётся в собственной службе. Архив не включает macOS и не обещает полностью автономную установку инструментов Apple.

## 6. Подготовка нового независимого экземпляра

Сначала задайте пути. Они должны оставаться неизменными после подготовки:

```bash
BN_ROOT="$BN_DEST/runtime/Hermes BN"
UDR_ROOT="$BN_DEST/runtime/Hermes UDR"
BN_R="$HOME/hbr"
UDR_R="$HOME/hur"
UDR_BOOT="$HOME/hub"
```

Каталоги `BN_R`, `UDR_R` и `UDR_BOOT` не должны существовать. R-пути должны быть без пробельных символов. Путь `BN_R/env` должен занимать не более 49 байтов UTF-8; для UDR действует проверка длины закреплённой двоичной среды. Проверка примера:

```bash
python3 - "$BN_R" "$UDR_R" <<'PY'
import sys
for path in sys.argv[1:]:
    if any(c.isspace() for c in path):
        raise SystemExit('Выберите пути R без пробелов')
if len((sys.argv[1]+'/env').encode())>49:
    raise SystemExit('Сократите путь BN_R: вместе с /env не более 49 байтов')
print('Начальная проверка путей пройдена')
PY
```

Выполните последовательно, останавливаясь при первой ошибке:

```bash
cd "$BN_DEST"
python3 deployment/prepare.py \
  --r-runtime "$BN_R" --init-local-databases

python3 deployment/prepare-udr.py \
  --r-runtime "$UDR_R" --timezone UTC \
  --host-bootstrap "$UDR_BOOT"

"$BN_ROOT/hermes-agent/venv/bin/python" deployment/prepare-memory.py
```

**До финализации:** выполните разделы 9.1–9.6: исправление оставшихся путей/часового пояса, собственные ключи или OAuth MCP, выбор методов и каналов, независимые профили. Недоступные подключения оставьте выключенными. Вход модели пока не выполняйте. Затем вернитесь в этот каталог и запечатайте итоговую конфигурацию:

```bash
cd "$BN_DEST"
"$BN_ROOT/hermes-agent/venv/bin/python" deployment/finalize-prepared.py
```

Вместо UTC можно указать свою часовую зону, например `Europe/Moscow`. Если решено передавать техническую почту Crossref/NCBI, передайте собственный `--contact-email` соответствующим подготовительным программам. Чужие адреса не использовать.

Первые этапы перемещают собственные среды R, подставляют пути, создают пустые Beads/Dolt, новые ключи GSD/UDR/памяти, независимые состояния и профили. Последний этап согласует местные контрольные суммы после всех подстановок. Он обязателен **до авторизации**: при обнаружении уже сохранённого входа новый профиль не запечатывается как чистый.

Подтверждения лежат в `deployment/prepared.json`, `GSD-prepared.json`, `UDR-prepared.json`, `Memory-prepared.json`, `FINALIZED.json`. Ожидаемые признаки: новые ключи и состояния; `services_started: false`, `accounts_authorized: false`. Это результат подготовки, ещё не работающая исследовательская платформа.

При частичной ошибке не удаляйте защитные отметки и не запускайте заново создание ключей поверх существующих. Сохраните ошибку и квитанции, устраните указанную причину; продолжайте лишь незавершённый этап, если его входы подтверждены. Для смены расположения используйте новое чистое извлечение.

## 7. Проверка подписанной пары и подготовка служб

Исходные подписанные Research/Foundation внутри комплекта не переписаны. Их проверяют по поставленным ключу, манифесту и подписям до первого рабочего использования. Наличие локального SHA не следует называть подписью поставщика. Исходный commit Hermes не имеет подтверждённой подписи выпуска.

Откройте следующую точную исходную последовательность внутри установки:

1. `$UDR_ROOT/source/docs/setup/README.md`.
2. `$UDR_ROOT/source/docs/setup/HERMES_KNOWLEDGE_WORK_PLATFORM_SPEC.md`, `$UDR_ROOT/source/docs/setup/HERMES_ZERO_TO_DEPLOYMENT_ROADMAP.md`, `$UDR_ROOT/source/docs/setup/HERMES_DEPLOYMENT_AGENT_HANDOFF_PROMPT.md`.
3. Руководства `$UDR_ROOT/source/docs/setup/ru/01-platform-and-hermes.md` … `11-mirage.md` по порядку.
4. Текущие `$BN_DEST/CURRENT-SETUP.md`, `CURRENT-VERSIONS.json` и `$BN_DEST/Руководства/06-Службы память GSD UDR.md`, `07-Аккаунты и защищённый ввод.md`, `08-Приёмка и восстановление.md` уточняют местную конфигурацию и приёмку.

Существующие программы уже включены; команды исходных руководств по скачиванию/установке применяются только к действительно отсутствующим компонентам. Не заменяйте установленную закреплённую пару более новыми пакетами автоматически.

## 9. Поисковые службы для всего Hermes BN, GSD и UDR

### 9.1. Результат и порядок подключения

Поисковые службы подключаются к **основному реестру инструментов Hermes BN**, а не только к UDR. Обычный диалог, GSD и управляемый UDR используют этот реестр в пределах собственных ролей и разрешений. UDR сохраняет план, источники и состояние исследования; он не заменяет поиск и не является обязательной обёрткой каждого обращения к сервису.

Различайте четыре результата:

1. **Настроен доступ:** собственный ключ или OAuth, правильный адрес и область аккаунта.
2. **Подключён инструмент:** MCP и нужный способ API/CLI действительно доступны в выбранном профиле и канале.
3. **Допущено исполнение:** совпадают закреплённое подключение, разрешённые методы и ограничения исполнителя.
4. **Проверена работа:** выполнены поиск, чтение источника, сохранение, обратное чтение и нужный прикладной маршрут.

Успешная авторизация или `mcp test` не заменяет остальные результаты.

**Сначала проверьте переносимость:** в комплекте r2 четыре местных переходника могут сохранять `__TIMEZONE__`, а `PYTHONPATH` Tavily — старое расположение. Перед правкой подключений выполните план:

```bash
"$BN_ROOT/hermes-agent/venv/bin/python" \
  "$BN_KIT/install-support/configure-search-portability.py" \
  --root "$BN_DEST" --timezone UTC
```

Выберите свою часовую зону вместо UTC. Проверьте перечисленные пути и возьмите `plan_sha256`, затем примените **этот** план:

```bash
"$BN_ROOT/hermes-agent/venv/bin/python" \
  "$BN_KIT/install-support/configure-search-portability.py" \
  --root "$BN_DEST" --timezone UTC --apply \
  --expected-plan-sha256 'ЗНАЧЕНИЕ_ИЗ_ПЛАНА'
```

Средство меняет только известную подстановку в `Crossref/api.py`, `OpenAlex/api.py`, `PubMed/api.py`, `SemanticScholar/api.py`, профильные пути Tavily и согласованные записи их контрольных сумм. Оно не создаёт аккаунты/базы/ключи и не запускает службы. Исходные файлы, точные старые/новые суммы и сопоставление с резервными файлами сохраняются в `deployment/search-portability-checkpoints/`. При повторе без изменений получается пустой план. При неизвестном изменении допущенного кода — отказ. Для уже работающей копии сначала штатно остановите затронутые процессы. Если раньше уже правилась запись Tavily, сначала рассмотрите и примите её изменение по 9.7; не маскируйте его исправлением переноса.

При ошибке посреди файловой записи сохраняйте контрольную точку и восстанавливайте только перечисленные в её `plan.json` файлы по `backup_file`, сверяя `before_sha256`; состояния исследований не затрагиваются. Это местное исправление целевого экземпляра, а не новый подписанный выпуск поставщика.

**Новая установка:** после `prepare.py`, `prepare-udr.py` и `prepare-memory.py` выполните настройку из 9.2–9.6; затем вернитесь к финализации в разделе 6. Авторизация MCP может выполняться в этот момент, а вход модели — после финализации. Это разные хранилища. Если сервис недоступен или аккаунта нет, оставьте его выключенным и запишите причину. После входа модели выполните приёмку 9.10–9.12.

**Уже работающая собственная копия:** сохраните конфигурацию, штатно завершите затрагиваемые задания и остановите свой шлюз. Добавьте подключение, настройте методы/каналы и выполните точечный допуск по 9.7. Не запускайте повторно создание пустых баз, `activate-gsd.py` или `finalize-prepared.py` поверх авторизованного рабочего экземпляра. История, неизвестные исходы и расходы сохраняются.

**Отдельная автономная UDR:** её профиль имеет собственную настройку. Подключение BN не авторизует её автоматически. Для управляемого UDR внутри BN второго комплекта ключей не требуется: поиск выполняет действующий узел BN. Самостоятельный профиль UDR настраивается дополнительно только если он действительно используется.

Обоснованный исходный набор: один общий поиск с чтением, второй независимый поставщик для сверки и средства профильной библиографии. Для широкого использования доступны следующие группы:

| Группа | Службы и назначение |
|---|---|
| Общий поиск и чтение | Tavily, Exa, Firecrawl, Keenable, Parallel Search |
| Сложные сайты, извлечение и задания | Firecrawl, Nimble, Parallel Task, расширенные API Tavily/Exa/Keenable |
| Научное обнаружение и метаданные | Crossref, OpenAlex, Semantic Scholar, PubMed/PMC, Consensus |
| Научный полный текст и связи | Scite, Undermind, AlphaXiv; наличие доступа и полноты текста проверяется отдельно |
| Проверка библиографии и структуры области | Pendar, Scholar Sidekick, Crossref, OpenAlex |
| Русскоязычные площадки | russianresearch: внешнее обнаружение через настоящего поставщика и предоставленные файлы |
| Лицензируемый дополнительный источник | Web of Science — только после собственного разрешённого доступа |
| Сохранение и последующая работа | Zotero, общая память, Beads/Dolt, ASReview; расчёты — R/Wolfram |

Не требуется покупать все службы. Однако заявленный план исследования должен учитывать фактически доступные источники. Недоступный специализированный источник отмечается пробелом, а не скрыто заменяется общей поисковой выдачей.

### 9.2. Профиль, ключи и защищённый ввод

Работайте в Терминале своей установки. Вспомогательная функция ниже запускает CLI **в явно выбранном профиле**. Обычный `bin/hermes-bn` загружает основной `environment.sh`, поэтому для независимого профиля одного предварительного `export HERMES_HOME=...` перед этим обёрточным файлом недостаточно.

```bash
bn_profile() (
  bn_target_profile="$1"
  shift
  source "$BN_ROOT/environment.sh"
  export HERMES_HOME="$bn_target_profile"
  export HERMES_SHARED_AUTH_DIR="$HERMES_HOME/shared"
  exec "$BN_ROOT/hermes-agent/venv/bin/python" -m hermes_cli.main "$@"
)

bn_profile "$BN_ROOT/data" config path
bn_profile "$BN_ROOT/data" mcp list
```

Перед сохранением убедитесь, что путь относится к новой собственной установке. Не используйте домашний профиль `~/.hermes` по случайности.

Для основного профиля API-ключи сохраняются в `$BN_ROOT/data/.env` через штатную функцию Hermes. Значения не передаются аргументами команд и не выводятся. Запускайте следующий блок только в интерактивном Терминале; повторяйте для нужного поставщика:

```bash
(
  source "$BN_ROOT/environment.sh"
  "$BN_ROOT/hermes-agent/venv/bin/python" - <<'PY'
import getpass, re
from hermes_cli.config import save_env_value, get_env_value
allowed = {
    'FIRECRAWL_API_KEY','EXA_API_KEY','TAVILY_API_KEY',
    'KEENABLE_API_KEY','NIMBLE_API_KEY','PARALLEL_API_KEY',
    'MCP_CONSENSUS_API_KEY'
}
with open('/dev/tty','r+') as tty:
    tty.write('Имя переменной ключа из таблицы: '); tty.flush()
    name = tty.readline().strip()
    if name not in allowed:
        raise SystemExit('Неизвестная переменная; ничего не записано')
    if get_env_value(name):
        raise SystemExit('Ключ уже задан; сохранён существующий доступ')
    value = getpass.getpass('Ключ, ввод скрыт: ', stream=tty).strip()
    if not value or re.search(r'[\s\x00-\x1f\x7f]', value):
        raise SystemExit('Нужен ключ без пробелов и управляющих символов')
    save_env_value(name, value)
print('Ключ сохранён; значение не выводится')
PY
)
```

Уберите ключ из буфера обмена после сохранения. `.env`, файлы токенов и собственные квитанции не добавляются в публичный Git. Не используйте `config get --raw`, `printenv`, отладочный вывод HTTP-заголовков или ключ в адресе MCP. Если локальный интерфейс показывает готовую команду с ключом, перенесите только значение в защищённое поле.

Для другого собственного профиля используйте такой же процесс с его `HERMES_HOME` и `HERMES_SHARED_AUTH_DIR`, задаваемыми **после** `source environment.sh`. Вход OAuth выполняется отдельно для соответствующего профиля. Копирование токенов между владельцами запрещено. Изолированные роли одного владельца могут иметь согласованный доступ к его общим локальным переходникам; это не означает общей авторизации между разными пользователями.

### 9.3. Подключения MCP: адрес, авторизация и методы

В поставке подключения перечислены в `$BN_ROOT/data/config.yaml`, раздел `mcp_servers`, и изначально выключены. Правьте **существующую запись**, сохраняя остальные серверы, параметры и ограничения:

```bash
bn_profile "$BN_ROOT/data" config edit
```

Не заменяйте целиком `config.yaml` примером из интернета: это удалит настройки памяти, GSD и UDR. Не переименовывайте серверы произвольно — имена входят в политики и правила происхождения.

#### Ключевые подключения HTTP

| Имя сервера в комплекте | Адрес | Заголовок со ссылкой на защищённую переменную |
|---|---|---|
| `firecrawl` | `https://mcp.firecrawl.dev/v2/mcp` | `Authorization: "Bearer ${FIRECRAWL_API_KEY}"` |
| `exa` | `https://mcp.exa.ai/mcp?tools=web_search_exa,web_fetch_exa,web_search_advanced_exa,agent_run` | `x-api-key: "${EXA_API_KEY}"` |
| `keenable` | `https://api.keenable.ai/mcp` | `X-API-Key: "${KEENABLE_API_KEY}"` |
| `keenable-select` | `https://select.keenable.ai/mcp` | `X-API-Key: "${KEENABLE_API_KEY}"` |
| `nimble` | `https://mcp.nimbleway.com/mcp` | `Authorization: "Bearer ${NIMBLE_API_KEY}"` |
| `parallel-search` | `https://search.parallel.ai/mcp?mode=fast` | `Authorization: "Bearer ${PARALLEL_API_KEY}"` для собственного ключа |
| `parallel-task` | `https://task-mcp.parallel.ai/mcp` | `Authorization: "Bearer ${PARALLEL_API_KEY}"` |
| `consensus` | `https://mcp.consensus.app/mcp` | `Authorization: "Bearer ${MCP_CONSENSUS_API_KEY}"` в предусмотренном варианте комплекта |

Пример **содержимого существующей записи**, а не замены всего файла:

```yaml
mcp_servers:
  firecrawl:
    url: https://mcp.firecrawl.dev/v2/mcp
    headers:
      Authorization: "Bearer ${FIRECRAWL_API_KEY}"
    enabled: true
    lazy: true
    connect_timeout: 60
    timeout: 180
```

`${...}` остаётся буквальной ссылкой в YAML; при исполнении она разрешается из собственного профиля. Для остальных строк меняются имя сервера, адрес и заголовок по таблице. Сохраните предусмотренные `tools.include` / `tools.exclude` и сроки из своей записи. Не совмещайте ключ и OAuth без основания.

Альтернатива для **нового отсутствующего** сервера с обычным Bearer:

```bash
bn_profile "$BN_ROOT/data" mcp add ИМЯ --url АДРЕС --auth header
```

CLI запросит ключ скрыто и сохранит его как `MCP_<ИМЯ>_API_KEY` со своей ссылкой в заголовке. Это **другая переменная**, чем ключ прямого API. Для Exa `x-api-key` и Keenable `X-API-Key` этот общий Bearer-диалог не следует применять автоматически. Для уже имеющейся записи не создавайте одноимённый дубликат.

#### OAuth

| Имя | Адрес из поставки | Действие |
|---|---|---|
| `scite` | `https://api.scite.ai/mcp` | `auth: oauth`, затем отдельный вход Scite |
| `undermind` | `https://mcp.undermind.ai/mcp` | `auth: oauth`, затем вход в свой аккаунт |
| `alphaxiv` | `https://api.alphaxiv.org/mcp/v1` | `auth: oauth`, затем подтверждение своего аккаунта |
| `pendar` | `https://pendar.ai/mcp` | `auth: oauth`, собственные права исследовательских инструментов |
| `openalex` | `https://mcp.openalex.org/mcp` | `auth: oauth`, собственные разрешения исследования |

В существующей записи включите `enabled: true`, задайте `auth: oauth`, сохраните параметры `oauth` и выбранные методы, замените человекочитаемое `client_name` на обозначение своей установки. Затем, например:

```bash
bn_profile "$BN_ROOT/data" mcp login scite
bn_profile "$BN_ROOT/data" mcp test scite
```

Повторите для выбранных серверов. Браузер и новое подтверждение принадлежат новому владельцу. Если вход предлагает продолжить без обязательной авторизации, откажитесь. `401`/`403`, платный план или недоступная выдача не исправляются снятием контроля.

Firecrawl отдельно документирует OAuth по `https://mcp.firecrawl.dev/v2/mcp-oauth`; для Exa и Parallel также доступны собственные OAuth-варианты. Переход на них меняет запись подключения и требует её повторного допуска. Исходная конфигурация и API-ключи остаются рабочим самостоятельным вариантом. [Firecrawl MCP](https://docs.firecrawl.dev/mcp-server), [Exa MCP](https://github.com/exa-labs/exa-mcp-server), [Parallel Task MCP](https://docs.parallel.ai/integrations/mcp/task-mcp).

### 9.4. Полный набор возможностей и маршруты применения

Ниже указан набор интеграции, а не обещание доступности каждой операции на любом тарифе. Фактическую схему получают через MCP или `catalog` соответствующего CLI. Полные сохранённые схемы и примеры — `$BN_DEST/documentation/шаблоны/`, исходные ограничения — `documentation/интеграции/`.

#### Firecrawl

Подключите `firecrawl`, проверьте поиск, чтение и карту. Основные методы: `firecrawl_search`, `firecrawl_scrape`, `firecrawl_map`; для корпуса — `firecrawl_crawl` и `firecrawl_check_crawl_status`. Дополнительно доступны задания `firecrawl_agent`/`firecrawl_agent_status`, разбор `firecrawl_parse`, инструменты научного поиска/чтения, браузерные действия и наблюдение за изменениями, если они возвращаются текущей схемой.

API/CLI `$BN_ROOT/bin/firecrawl-bn` дополняет MCP форматами и пакетными операциями. Создание браузерного сеанса, исполнение действий, создание/изменение наблюдения и отправка содержимого — отдельные действия, которым не следует давать автоматическое разрешение только ради поиска. Чтение каждой страницы проверяйте по ошибкам и полноте; успешное задание не означает успешные все страницы. [Официальная справка](https://docs.firecrawl.dev/mcp-server).

#### Exa

Включите все четыре нужных метода **в одном параметре `tools`** адреса: `web_search_exa`, `web_fetch_exa`, `web_search_advanced_exa`, `agent_run`. Параметр заменяет набор по умолчанию, поэтому указание только расширенного поиска может убрать обычный поиск/чтение. Расширенный поиск нужен для точных доменов, дат, типа материала и фрагментов; чтение выполняется отдельно по найденным URL.

`agent_run` — отдельный исследовательский процесс поставщика, не роль G/S/D и не локальный сборщик UDR. Прямой API `$BN_ROOT/bin/exa-bn` предусмотрен для дополнительных операций, структурированных заданий, обогащения и пакетной работы по поставленной схеме. Сохраняйте ID, состояние и фактический расход; результат модели поставщика не считается независимо проверенным. [Официальный каталог MCP](https://github.com/exa-labs/exa-mcp-server).

#### Tavily

Основной вариант комплекта — **местный полный MCP**, а не только удалённый сервер. Он даёт `tavily_search`, `tavily_extract`, `tavily_map`, `tavily_crawl`, `tavily_research`, `tavily_get_research`, `tavily_research_stream`, `tavily_usage`, `tavily_logs`. Для поиска доступны `general`/`news`/`finance`, глубина, даты, домены и дополнительные поля по текущей схеме.

Проверяйте `failed_results` извлечения. Для обзора сайта используйте карту, затем ограниченный обход; для исследовательского задания сохраняйте `request_id` и опрашивайте прежнее задание, а не создавайте повтор при каждом ожидании. Расход/журналы доступны владельцу и не равны источникам исследования. Удалённый Tavily MCP — альтернативный транспорт с собственным набором; его подключение не доказывает наличие всех девяти методов местного переходника. [Официальный MCP](https://docs.tavily.com/documentation/mcp).

#### Keenable и SELECT

`keenable` предоставляет поиск `search_web_pages`, чтение `fetch_page_content` и другие заявленные текущей схемой операции. `keenable-select` — отдельное подключение для табличного извлечения через SELECT; это не доступ к вашим местным SQLite/Dolt и не разрешение произвольного SQL.

Прямой API/CLI `$BN_ROOT/bin/keenable-bn` дополняет MCP. Проверьте поиск, точное чтение, затем одну таблицу по двум публичным страницам с сохранёнными URL. Публикация отчёта/ссылки, если доступна, является отдельным внешним действием; в обычную проверку чтения не входит. Официальные варианты MCP/CLI/REST: [справка Keenable](https://docs.keenable.ai/). Не запускайте `configure-mcp --all`, меняющий чужие обнаруженные клиенты, ради отдельной установки BN.

#### Nimble

Основное подключение `nimble` даёт веб-поиск, извлечение, шаблоны и исследовательские задания по текущей схеме и своему доступу. `nimble-docs` ищет **только справку Nimble**. Не представляйте второй сервер как альтернативный поисковик по сети.

Поиск и полный текст различаются: поля/уровни результата берутся из действующей схемы, полный текст запрашивается отдельно, когда это требуется. У задания сохраняйте идентификаторы и конечное состояние; постановка в очередь не является завершением. Создание/изменение шаблона, удаление агента и другие изменяющие методы остаются выключенными до отдельной потребности. Прямой `$BN_ROOT/bin/nimble-bn` дополняет MCP; перед использованием шаблона проверьте его актуальную схему и выход. [Официальная документация](https://docs.nimbleway.com/).

#### Parallel Search и Task

Подключения разные: `parallel-search` — поисковая выдача и доступные операции чтения; `parallel-task` — задания глубокого исследования/обогащения и их результаты. Search имеет отдельный публичный вариант, Task требует собственного доступа. Не считайте успешный Search подтверждением Task. [Search MCP](https://docs.parallel.ai/integrations/mcp/search-mcp), [Task MCP](https://docs.parallel.ai/integrations/mcp/task-mcp).

Комплект также содержит `$BN_ROOT/bin/parallel-bn`: собственный ключ, изолированное состояние CLI и профили для дополнительных API. Наборы заданий, структурированное исследование, FindAll, наблюдения и другие семейства выбираются по поставленной версии/схеме. Они не становятся инструментами модели только потому, что есть команда CLI. Для доступного модели MCP проверьте реальный список; для CLI вызова — отдельный допуск команды и области файлов. Асинхронное задание продолжается по прежнему ID; продолжение UDR хранит эту связь после перерыва.

#### Consensus

Подключите `consensus`, проверьте метод `search`, затем фильтры по годам, типу исследования, области и рецензированию, которые действительно возвращает схема. Название, DOI и год сопоставляйте с Crossref/PubMed/издателем. Аннотация, выдержки и полный текст — разные уровни чтения; отсутствие выдержек полного текста фиксируется прямо.

`$BN_ROOT/bin/consensus-bn` использует собственные профили и параметры API. Для прямого API требуется собственный `Consensus/config/access.json` с реальным `credential_env` и пределами вашего плана; наличие ключа MCP само по себе его не создаёт. При отсутствии этих подтверждённых данных используйте проверенный MCP и отмечайте прямой путь как не настроенный. [Документация Consensus](https://docs.consensus.app/).

#### Scite

OAuth подключает `scite`. Исследовательское ядро: `search_literature`, `read_fulltext`, `citation_graph`, `bibliography`, `report_citations`, `citation_report`. Дополнительные семейства поставки: патенты, гранты, клинические исследования, препараты, медицинские устройства, сообщения о безопасности, коллекции/заметки/файлы.

Доступность каждого семейства проверяется отдельно; библиотека/коллекции и загрузка файлов не включаются молча вместе с поиском. После чтения полезно зарегистрировать использованные записи через `report_citations` и проверить `citation_report`. Категории `supporting`/`contrasting`/`mentioning` описывают классификацию контекста Scite, не научную приёмку. Переход на MCP не исправляет недоступный тариф и не подтверждает REST API. [Сервис](https://scite.ai/), точные выбранные методы — `Scite/config/mcp-selected.json`.

#### Undermind

После OAuth выберите/создайте **своё** рабочее пространство. Инструменты обнаружения: `search_papers`, `find_papers_by_author`, `lookup_papers_by_metadata`, `get_paper_info`. Целевое чтение PDF — `read_pdfs`, ссылки на доступные PDF — `get_pdf_download_links`.

Глубокий поиск: `launch_deep_search`, `inspect_deep_searches`, `display_deep_search_results`, `display_references`. Операции папок, файлов, добавления/перемещения/отметки работ отделяются от чтения. Pro в браузере не доказывает доступность каждого режима MCP; проверьте выбранный режим своим аккаунтом. Полнотекстовый поиск и вопрос к PDF не означают чтения всей статьи. [Сервис](https://www.undermind.ai/), контракт — `Undermind/config/mcp-selected.json`.

#### AlphaXiv

После OAuth подключите `discover_papers`, `get_paper_content`, `answer_pdf_queries`, поиск/разрешение исследователей и доступные операции чтения библиотеки/заметок. Для ответов по статье фиксируйте arXiv ID, версию, страницы и источник: `get_paper_content(fullText=false)` может возвращать обзор ИИ, который нельзя выдавать за исходный текст.

Папки, сохранение/перемещение работ, личные метаданные и подписки доступны владельцу отдельно от исследовательского чтения. Создайте свою закрытую исследовательскую папку, если нужна библиотека; не переносите чужие её ID. [Вход](https://www.alphaxiv.org/signin), набор методов — `AlphaXiv/config/mcp-selected.json`.

#### Crossref

Местный `crossref` подключается без обязательного ключа. Основной набор: `works_search`, `work_get`, `works_batch`, `bibliographic_match`, `doi_agency`, `doi_exists`, ссылки/отношения/исправления, финансирование и лицензии, поиск сущностей и сводные поля. Дополнительный набор — преобразование метаданных, стили и экспорт, XML/OpenURL и справочное обнаружение наборов/OAI по схеме.

Проверьте точный DOI и отличайте `published`, `published-online`, `published-print`, `created`, `deposited`, `indexed`. Метаданные издателя не являются доказательством прочитанного полного текста или достоверности научного вывода. [Правила API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/).

#### OpenAlex: два дополняющих варианта

Официальный `openalex` после своего OAuth: `search_works`, `get_work`, `resolve_references`, `list_citations`, сущности, группировки/анализ, ключевые слова и поддержанные операции запросов. Методы изменения авторского профиля не добавляйте для обычного исследования.

Местный `openalex-api` со своим ключом: сущности и пакетное получение, смысловой поиск, аннотации, связи/метрики, запросы/классификация, загрузка содержимого, `content_structure`, `read_content`, `read_pdf_pages`, `render_pdf_page`, экспорт и сохранение запросов. Содержание PDF и GROBID TEI различаются. Иллюстрацию/таблицу сверяйте по изображению исходной страницы; индексная связь цитирования не означает поддержку вывода. [Свой API-доступ](https://openalex.org/settings/api).

#### Semantic Scholar

Местный `semanticscholar`: поиск/массовый поиск, совпадение названия, карточки и пакетное получение работ/авторов, ссылки и цитирования, рекомендации, фрагменты, сведения о выпусках наборов и различиях. Сначала `service_status`, затем один небольшой `paper_bulk_search` или поиск точного DOI/названия.

Без ключа допустима только фактически доступная публичная выдача. При `429` остановите этот путь и соблюдайте паузу; не запускайте десятки одинаковых попыток. Заявку на ключ не подавайте повторно автоматически. Запись о наборе данных не означает, что набор скачан и прочитан. [Официальный API](https://www.semanticscholar.org/product/api).

#### PubMed и PMC

Местный `pubmed`: поиск, сведения о базе/истории запроса, краткие и полные библиографические записи, связи, исправление поискового термина, сопоставление цитаты и экспорт. PMC: метаданные/лицензия/версия, структура разделов, адресное чтение, таблицы и статус PDF.

Проверьте PMID/PMCID/DOI одной статьи, прочитайте аннотацию, затем одну доступную таблицу PMC с подписью/примечаниями. Библиографический год и дата электронной публикации могут отличаться; сохраните оба. Лицензия и доступность текста проверяются отдельно. Ключ необязателен для исходной установки; технический контакт — собственный. [NCBI](https://www.ncbi.nlm.nih.gov/).

#### Pendar и Scholar Sidekick

`pendar` после OAuth предоставляет шесть инструментов: `verify_paper`, `survey_literature`, `graph_hopper`, `audit_bibliography`, `profile_researcher`, `find_venues`. Это проверка/структурирование области; `abstract_snippet` не является полной аннотацией. Проверьте один DOI до запуска большого обзора. [Сервис](https://pendar.ai/).

`scholarsidekick`: `verifyCitation`, `auditBibliography`, `checkRetraction`, `checkOpenAccess`, `resolveIdentifier`, `formatCitation`, `exportCitation`. В проверке метаданных явно используйте `screenWithLlm=false`, если модельный разбор не настроен и не нужен. Форматированную ссылку сверяйте с метаданными: форматировщик может пропустить номер статьи. DOI-совпадение не подтверждает изложенные в статье выводы. Адрес MCP: `https://scholar-sidekick.com/api/mcp`.

#### Русскоязычные площадки и Web of Science

`russianresearch` объединяет план запросов, обнаружение кандидатов, DOI-разрешение и чтение законно предоставленных документов. Для eLIBRARY/DisserCat/КиберЛенинки прямой доступ по умолчанию не заявляется. В отчёте указывайте настоящий поисковый сервис, например Tavily с ограничением домена. Отдельно подтверждайте открытие оригинальной страницы, автора, год и полноту файла.

`webofscience` в исходной конфигурации предоставляет `service_status`, `capability_catalog`, `query_plan`, `access_request`. Это подготовка подключения, а не действующий поиск по базе. Получите собственный продукт/ключ и необходимое разрешение Clarivate для работы с LLM; чужие согласия не применяются. До разрешения оставьте рабочий поиск закрытым и используйте доступные источники с точным указанием ограничения. [Clarivate Developer](https://developer.clarivate.com/).

### 9.5. Методы, каналы и навыки Hermes

После сохранения доступа получите каталог и выберите нужные методы:

```bash
bn_profile "$BN_ROOT/data" mcp test tavily
bn_profile "$BN_ROOT/data" mcp configure tavily
bn_profile "$BN_ROOT/data" tools list --platform cli
bn_profile "$BN_ROOT/data" tools list --platform telegram
```

Через `mcp configure` выбирается реальный набор сервера. Начните с поиска/чтения, затем добавляйте карты, обход, задания и анализ расхода по потребности. Создание коллекций, публикации, изменения наблюдений, загрузки частных файлов и удаления — отдельные операции.

Пример включения конкретных операций в каналах:

```bash
bn_profile "$BN_ROOT/data" tools enable \
  tavily:tavily_search tavily:tavily_extract --platform cli
bn_profile "$BN_ROOT/data" tools enable \
  tavily:tavily_search tavily:tavily_extract --platform telegram
```

Для реально используемых `gui`, `api_server`, `tui`, `cron` повторите настройку канала и проверку его фактического списка. Не включайте незадействованные каналы автоматически. Имена инструментов в сообщениях и в `tool_describe` берутся из полученного реестра, а не конструируются склеиванием слов. Сервер `parallel-search` и зарегистрированное имя инструмента могут иметь разное написание; смотрите схему.

В основном профиле должны быть доступны поставленные навыки `firecrawl-knowledge-work`, `exa-knowledge-work`, `tavily-knowledge-work`, `keenable-knowledge-work`, `nimble-knowledge-work`, `parallel-knowledge-work` и профильные научные навыки, если они присутствуют в фактическом каталоге. Проверьте `data/skills` и `skills_list`. Навык задаёт порядок работы, но не устанавливает сервер, не сохраняет ключ и не предоставляет разрешение на внешний эффект.

Если выбран нативный инструмент Hermes `web_search`/`web_extract`, настройте его поставщика через штатный `hermes tools` и проверьте **этот** маршрут отдельно. Наличие `tavily_search` через MCP не доказывает настройку встроенного `web_search`; обратное также неверно. Не скрывайте реального поставщика за общим именем.

Все изменения адресов, заголовков-ссылок, исполняемых путей, выбранных методов и каналов завершайте **до** допуска 9.7 или финализации новой установки. Последующее изменение самой MCP-записи требует повторной сверки; штатное обновление значения ключа по неизменной ссылке не превращается автоматически в новое подключение.

### 9.6. Независимые профили и управляемый UDR

Проверьте профили отдельно:

| Профиль | Что проверяется |
|---|---|
| `$BN_ROOT/data` | Обычный Hermes BN, совместная работа GSD/UDR и собственные каналы |
| `$BN_ROOT/data/profiles/bn-gsd-only` | Доступные источники и общая память при независимом GSD, без зависимости от UDR |
| `$BN_ROOT/data/profiles/bn-udr-only` | Доступные источники и общая память при независимом UDR, без обязательного запуска GSD |
| `$UDR_ROOT/profile` | Только если используется самостоятельная среда UDR; отдельная модель/авторизация/инструменты |

Не копируйте весь основной YAML поверх независимого: это вернёт отключённый модуль и сломает независимость. Переносите только осознанно выбранную запись `mcp_servers`, нужные ссылки на собственные секреты и настройки требуемого канала. Для местных серверов проверьте абсолютный путь; для Tavily — `env.HERMES_HOME` и `PYTHONPATH`. OAuth выполняйте в целевом профиле через `bn_profile`.

Пример проверки второго профиля:

```bash
bn_profile "$BN_ROOT/data/profiles/bn-gsd-only" mcp list
bn_profile "$BN_ROOT/data/profiles/bn-gsd-only" mcp test tavily
bn_profile "$BN_ROOT/data/profiles/bn-gsd-only" tools list --platform cli
```

На новой установке окончательная финализация запечатывает подготовленные профили. На рабочей — применяйте 9.7 к каждому затронутому профилю с активным GSD. Если GSD в профиле не включён, средство допуска только сообщает, что такой допуск не требуется; это не успешная проверка UDR или памяти.

В управляемом UDR главным исполнителем остаётся Hermes BN: `mcp__udr__udr_research` начинает/ведёт исследование, а поисковые инструменты работают в обычном реестре BN. Сначала прочитайте план/профиль, потом выбирайте поставщиков. В самостоятельном режиме UDR список MCP и разрешений настраивается его собственным CLI, а не изменением только BN. Наличие `integration_mode: foundation` не даёт новых инструментов и полномочий.

### 9.7. Точечный допуск изменения подключения в работающем GSD

GSD связывает известный сервер с точной исходной MCP-записью. После её изменения может появиться `MCP source transport/config changed; owner admission required`. Это не ошибка API поставщика. Обновить нужно согласованный допуск оператора, сохранив обязательный контроль.

В публичном комплекте инструкции есть `install-support/admit-mcp-transport.py`. Это **отдельное средство оператора**, не инструмент модели. Оно:

- принимает только уже настроенный, включённый сервер, известный действующей политике;
- проверяет целостность политики и ранее закреплённых местных адаптеров;
- сначала показывает план без изменения файлов;
- применяет только одну запись `mcp_transport_digests[server]` после явного принятия двух контрольных сумм;
- сохраняет защищённую резервную копию настроек и квитанцию;
- не расширяет список методов, не меняет ключи, состояние, бюджеты, контроллеры или код.

Проверочные сценарии этих двух средств доступны без сетевых вызовов и без настоящих аккаунтов:

```bash
"$BN_ROOT/hermes-agent/venv/bin/python" "$BN_KIT/install-support/check-admission.py"
"$BN_ROOT/hermes-agent/venv/bin/python" "$BN_KIT/install-support/check-portability.py"
```

Они работают с временными вымышленными файлами; их успех не заменяет приёмку настоящего сервиса на вашем Mac.

Шаги владельца в своём Терминале, например для Tavily:

```bash
"$BN_ROOT/hermes-agent/venv/bin/python" \
  "$BN_KIT/install-support/admit-mcp-transport.py" \
  --home "$BN_ROOT/data" --server tavily
```

До принятия проверьте в собственном редакторе: выбранный профиль; официальный адрес/исполнитель; ссылки на секреты; методы; отсутствие чужих путей; завершение старых заданий. Из плана возьмите `config_sha256` и `settings_sha256`, затем выполните:

```bash
"$BN_ROOT/hermes-agent/venv/bin/python" \
  "$BN_KIT/install-support/admit-mcp-transport.py" \
  --home "$BN_ROOT/data" --server tavily --apply \
  --expected-config-sha256 'ЗНАЧЕНИЕ_config_sha256_ИЗ_ПЛАНА' \
  --expected-settings-sha256 'ЗНАЧЕНИЕ_settings_sha256_ИЗ_ПЛАНА'
```

Повторите адресно для остальных изменённых известных серверов/профилей. При новом сервере, новом имени метода, ошибке целостности кода или несовместимой схеме средство отказывает: нужна отдельная рассмотренная адаптация политики, а не снятие проверки. Не переписывайте весь список контрольных сумм по принципу «доверять текущему всему».

Затем штатно перезапустите свою затронутую среду, создайте новую проверочную задачу/сессию и выполните настоящий вызов. Старую незавершённую операцию сначала сопоставьте с её фактическими эффектами; повторное сообщение не является универсальным восстановлением.

### 9.8. Дочерние исполнители UDR и роли G/S/D

Подключение для **всего агента** не означает передачу всех прав каждому дочернему исполнителю. Родитель собирает и регистрирует источники, задаёт адресные входы и ограничения; G/S/D выполняют свои роли, а сборщик UDR имеет узкую поверхность чтения.

Текущий разрешённый набор сборщика определяется `$UDR_ROOT/operator/bn-bridge/worker_policy.py`. В поставке он включает:

| Источник | Допущенные операции сборщика |
|---|---|
| Exa | `web_search_exa`, `web_search_advanced_exa`, `web_fetch_exa` |
| Tavily | `tavily_search`, `tavily_extract`, `tavily_map` |
| Keenable | `search_web_pages`, `fetch_page_content` |
| Parallel Search | `web_search` зарегистрированного сервера |
| Firecrawl | поиск, чтение без `actions`, карта, выбранное научное обнаружение/чтение |
| Consensus | `search` |
| Scite | `search_literature`, `citation_graph`, `read_fulltext`, выбранные патенты/клинические записи |
| Undermind | `get_paper_info`, `search_papers`, поиск автора/метаданных, `read_pdfs` |
| AlphaXiv | `discover_papers`, `get_paper_content`, `answer_pdf_queries` |
| OpenAlex MCP | поиск работ/сущностей, карточки, ссылки и цитирования |
| PubMed/PMC | поиск, аннотация/запись, метаданные/чтение/таблица PMC |
| Crossref | поиск/карточка, библиографическое совпадение, ссылки/отношения |

Nimble, SELECT, Parallel Task, Pendar, Scholar Sidekick, Semantic Scholar и другие методы могут быть доступны **родителю**, но этим перечнем не разрешаются сборщику автоматически. Для них родитель делает ограниченный запрос и передаёт сохранённый результат, либо проводится отдельная проверенная адаптация поверхности роли. Отсутствие допуска не обходится переименованием метода или общим `tool_call`.

При `source_domains` сборщик допускает только интерфейсы с проверяемым жёстким ограничением домена: например Tavily `include_domains`, Exa `includeDomains`, Keenable `site`; чтение — только разрешённых URL. Обычный общий поиск без такого параметра в этом режиме закрывается. Не подменяйте доменный фильтр текстом «site:» без проверки фактического контракта.

`bn_parallel_search` при активном GSD выполняет простые независимые запросы через штатный `web_search`; это не универсальный параллельный вызов всех MCP; `bn_udr_team` — для сохранённых дочерних задач с Beads, зависимостями, адресными входами и продуктами. Не создавайте второй самостоятельный цикл агентов поставщика внутри каждого сборщика. Глубокие задания Exa/Tavily/Nimble/Parallel ведёт родитель с сохранёнными ID. Результат внешнего агента проходит обычную проверку источников и G/S/D, не считается автоматически принятым.

### 9.9. От результата поставщика к общей памяти и базе исследования

Для каждого исследования создайте отдельную папку проекта с `00-постановка.md`, `01-план.md`, `02-журнал-поиска.md`, `03-реестр-источников.md`, `04-наблюдения-и-проверки.md`, `05-отчёт.md` и каталогами оригиналов/выгрузок. Идентификатор проекта и область памяти должны совпадать с выбранной задачей; исходники разных владельцев не смешиваются.

В журнале сохраняйте:

- настоящий поставщик, сервер/метод и время запроса;
- поисковую строку, фильтры, язык, даты, страницы выдачи и правила исключения;
- ID внешнего задания и его состояние, если запрос асинхронный;
- исходный и конечный URL, дату/версию материала, тип и лицензию;
- путь оригинала, SHA-256 байтов, адрес прочитанного фрагмента/страницы;
- фактический уровень: выдача, метаданные, аннотация, извлечение, прочитанный фрагмент или проверенное полное покрытие;
- ошибки/недоступность, ограничения выборки, расход и результат проверки.

При UDR регистрируйте оригиналы и точные фрагменты его штатными инструментами `source`/`fetch`/`note`/`read` по реальной схеме. Не добавляйте несуществующие поля в вызов; расширенную информацию о происхождении храните отдельной записью проекта. Затем сохраняйте нужный оригинал/квитанцию через общую память. SQLite/первичный журнал авторитетны; Graphiti/Neo4j, Zvec, Cognee и AgentMemory не создают независимое подтверждение того же источника.

Массовый сбор требует учёта всех единиц: URL/файлы/страницы/таблицы/вложения, ошибки и непрочитанные остатки. Повтор одной страницы не покрывает другую. Непоместившийся обязательный текст делится адресно и дочитывается; не заменяется предпросмотром. Выгрузка из поиска — ещё не корпус прочитанных публикаций.

После отбора можно использовать Zotero для библиографии/файлов и ASReview для приоритизации просмотра. Запись в библиотеку, изменение отбора и импорт в Dolt выполняются в своей области с версией/происхождением. R/Wolfram проверяют расчёты; они не исправляют нерепрезентативную выборку отзывов и не превращают частоту поисковых результатов в распространённость среди населения.

### 9.10. Приёмка каждого сервиса

Для каждого реально используемого пути заполните собственную строку:

| Поле | Что записать |
|---|---|
| Дата, версия, профиль/канал | Конкретная целевая установка, а не исходный отчёт разработчика |
| Транспорт и доступ | MCP / API / CLI, способ входа, свой аккаунт без значения ключа |
| Каталог и разрешения | Реальные методы; доступные родителю/сборщику; допуск GSD |
| Поиск | Один ограниченный запрос, точные параметры, ID/URL результата |
| Чтение | Один оригинальный URL/PDF, реально возвращённые фрагменты и ошибки |
| Сохранение/повтор | Путь, SHA, повторное чтение из проекта/UDR/памяти |
| Прикладной режим | Проверен / недоступен / не испытан — для обхода, исследования, таблиц, экспорта отдельно |
| Ограничения | План/квота/429/платный текст/неполнота/несовместимый метод |

Достаточные начальные проверки:

| Сервис | Начальная проверка | Дополнительная проверка нужного режима |
|---|---|---|
| Firecrawl | Найти и прочитать официальную публичную страницу | Карта/малый обход; статус каждой страницы; разбор одного собственного документа |
| Exa | Расширенный поиск по одному домену, затем `web_fetch_exa` | Одно структурированное задание с сохранённым ID и источниками |
| Tavily | Search → Extract, проверить `failed_results` | Map/ограниченный Crawl; Research → прежний ID → конечный результат |
| Keenable | Поиск → чтение двух страниц | SELECT-таблица с URL; публикацию не включать в проверку чтения |
| Nimble | Поиск → отдельный запрос полного содержания | Один свой шаблон или задание; дождаться результата и проверить схему |
| Parallel | Search отдельно от Task | Одно малое Task-задание, опрос/результат и происхождение |
| Consensus | Поиск точного названия/DOI | Различить аннотацию и фактически доступные выдержки полного текста |
| Scite | DOI → метаданные/фрагмент → три контекста цитирования | `report_citations` → `citation_report`; отдельное выбранное предметное семейство |
| Undermind | Метаданные → `read_pdfs` по конкретной таблице/странице | Свой полнотекстовый/глубокий поиск с ID и списком реально найденных работ |
| AlphaXiv | arXiv ID → `answer_pdf_queries` | Сверить версию/страницы и отличить обзор от исходного текста |
| Crossref | `work_get` по DOI, сравнить даты | Ссылки/исправления, один экспорт BibTeX/RIS по фактической схеме |
| OpenAlex | MCP поиск/связи; отдельно API `service_status` | Легально доступный PDF: структура, текст страницы, изображение таблицы |
| Semantic Scholar | Статус режима → одно точное совпадение | Цитирования/рекомендации; при 429 остановиться |
| PubMed/PMC | PMID/PMCID/DOI → аннотация | Метаданные лицензии/версии → таблица с подписью и примечанием |
| Pendar | `verify_paper` одного DOI | Нужный из пяти других инструментов; фрагмент не называть полным текстом |
| Scholar Sidekick | `verifyCitation`, затем `formatCitation` | Отзыв/исправление и открытая версия; проверить полноту оформления |
| russianresearch | Отдельная выдача по трём доменам | Свой предоставленный файл; происхождение настоящего поставщика |
| Web of Science | Только фактическое состояние доступа | Реальный поиск после собственного разрешения и настройки продукта |

Не запускайте весь платный набор ради отметки «подключено». Сначала малый проверочный запрос, затем только нужные исследованию режимы. Неиспытанный метод так и помечается. Сохранённая схема или правильная структура ответа не является смысловой приёмкой.

### 9.11. Четыре сквозных маршрута

После проверки поставщиков подтвердите их интеграцию по отдельности:

1. **Обычный BN:** в новом обычном диалоге без запуска GSD/UDR выполните поиск и чтение официальной страницы, сохраните и повторно прочитайте её. Сообщите настоящий сервис и уровень чтения. Это доказывает доступ всего агента, а не только специализированного режима.
2. **GSD:** передайте адресные проверенные источники; выполните реальных G/S/D с сохранёнными продуктами и ограничениями. Не заставляйте G читать весь корпус заново ради каждого шага. Проверьте независимый профиль без UDR.
3. **UDR и дочерний сборщик:** начните маленькое исследование, создайте две независимые задачи Beads и проверяющую зависимую задачу; запустите только допущенные методы. Сверьте фактическую выдачу/прочитанный текст, полный продукт сборщика и сохранённый отчёт. Проверьте UDR-профиль без запуска GSD.
4. **Telegram:** в своём боте выполните поиск/чтение и получите полный сохранённый `.md`-отчёт файлом. Откройте файл, сопоставьте SHA. Успех CLI не заменяет этот маршрут.

Отдельно проверьте продолжение UDR после штатной остановки и перерыва: те же проект/задача, старые источники и ID внешних заданий, сохранённые ограничения, обратное чтение и отчёт. Истечение токена требует нового собственного входа, а не удаления исследования. Если неизвестно, завершился ли внешний запрос, сначала узнайте состояние по прежнему ID.

### 9.12. Отказы, обратимость и обновление

| Отказ | Что исправлять |
|---|---|
| `401` / OAuth истёк | Свой доступ и целевой профиль; затем один проверочный запрос |
| `403` / метод требует план | Права/продукт; не отключать контроль и не подменять отсутствующий результат |
| `429` | Пауза по ответу сервиса и снижение частоты; без бесконечных повторов |
| Сбой обязательного контроллера | Его регистрация, закрепления и журнал; API-ключ не является универсальным исправлением |
| `source transport/config changed` | План/точечный допуск 9.7 после рассмотрения изменения |
| `not_found` инструмента | Реальный каталог, имя сервера/метода, выбор методов, профиль и канал |
| Сборщик отклонён | Его реальная разрешённая поверхность и ограничения домена; родительский доступ не наследуется целиком |
| Асинхронная очередь | Сохранённый ID и опрос прежнего задания, а не новое создание |
| Только фрагмент в Telegram | Сохранить полный отчёт и отправить согласованный файл, затем проверить получение |
| Отсутствует прямой API/CLI | Отдельно настроить его реквизиты/конфигурацию; MCP сам этого не доказывает |

При откате остановите только затронутую свою среду, сохраните новые материалы, верните согласованные запись MCP и её допуск из своей квитанции/резервной копии. Не восстанавливайте только старый допуск при новом адресе. Не удаляйте первичные источники, неизвестные исходы, Beads-задачи или историю ради снятия ошибки.

При изменении поставщиком схемы обновляйте только затронутый адаптер/каталог и проверки его контрактов. Временная недоступность сервиса допускает явно ограниченную работу других источников; отказ обязательного контроля сохраняет закрытый зависимый путь. Новая инструкция не требует повторного скачивания 18,7 ГБ неизменённых установочных архивов.

Адреса и исходные наборы взяты из обезличенной поставки, CLI Hermes 0.22.2 и действующих политик этого комплекта. Официальная справка Firecrawl, Exa, Tavily, Parallel и Keenable дополнительно сверена 17 октября 2026 года. Для остальных служб таблица является исходным контрактом поставки; текущую доступность и набор подтверждает реальная схема MCP на целевой машине. Открытие MCP-адреса браузером не заменяет протокольную проверку сервера.

## 10. Приёмка: установка, подключение и работа проверяются отдельно

Ведите собственный файл `приёмка.md`: критерий, команда/действие, ожидаемый результат, фактический результат, путь/сумма свидетельства, ограничение. Исходные отчёты в комплекте описывают прежние испытания программы; это не результаты вашей машины.

### Минимальный сквозной сценарий

1. Создайте отдельный проект и маленький файл с явным синтетическим содержимым: «Atlas: оригиналы в SQLite; before=20; after=30». Запишите его SHA-256. Не выдавайте синтетические значения за реальные измерения.
2. Через обычный Hermes, без запуска UDR/GSD, сохраните источник общей памятью. Получите его поиском и прочитайте оригинал целиком. Сверьте текст и SHA, затем результаты AgentMemory, Graphiti/Neo4j, Zvec, Cognee. Укажите фактически ответившие индексы. Индекс и оригинал — разные уровни данных.
3. Через Mirage прочитайте разрешённый файл. Попытка чтения вне разрешённой области должна быть отклонена. Через Serena получите обзор и определение символа собственного кода.
4. Создайте две задачи Beads: B зависит от A. Проверьте блокировку B, закройте A и проверьте готовность B. В Dolt сохраните синтетический набор отдельным commit; получите строку, SHA источника, ветку и commit. Свяжите задачу с версией данных.
5. Запустите GSD на вопросе о двух возможных причинах изменения показателя. Подтвердите **реальное** исполнение G/S/D, типизированные передачи, сохранение ограничений, пути продуктов. Правильный JSON и `SUCCEEDED` без содержательной проверки не доказывают корректный вывод. Не заявляйте причинность без различающего свидетельства.
6. Через UDR выполните постановку, декомпозицию, сбор локального источника, анализ, проверку, сохранение отчёта и повторное чтение. Ожидаемый расчёт: 20→30, +10 и +50%; причинность и статистическая значимость не установлены. Если отчёт не сохранён, исследование не закрывать.
7. Остановите и возобновите своё исследование. Подтвердите сохранение исходников, задач, происхождения, состояния и отчёта без повторного внешнего действия. Длительный перерыв не должен вынуждать сбрасывать исследование.
8. Проверьте большой документ адресными страницами до конца и вторую единицу с поздней поправкой. Учёт всех единиц/страниц обязателен. Предпросмотр, извлечение или квитанция доставки не равны смысловому чтению; неполное покрытие не получает `complete`.
9. В R проверьте `mean(1:5)=3`, `var(1:5)=2.5` и создайте график. Проверьте фактическое наличие изображения, а не только успешное завершение команды.
10. Через собственный Telegram повторите чтение источника, получите полный отчёт файлом `.md` и откройте его. Сверьте SHA полученного файла с сохранённым оригиналом.

Инструменты ищите по фактической схеме вашей версии. Запрашивайте `tool_describe` группами не более 10 имён. Для `--toolsets` используйте имена серверов конфигурации, например `udr`, `context`, `beads`; не придумывайте склеенные имена методов. Получение схемы не является успешным выполнением метода.

### Обязательные отказы

Проверьте адресно: недоступный обязательный контроллер; чужая область; неподтверждённый исполнитель; неверный SHA; запрещённое внешнее действие; пропущенный обязательный фрагмент; неизвестный прежний исход. Защищённое действие останавливается **до исполнения**. Наблюдающее событие не заменяет блокировку.

Общая память обслуживает обычные задачи, GSD и UDR. GSD и UDR должны сохранять независимые профили и доступный разрешённый режим при отказе другого. Первичный журнал и оригиналы авторитетны, индексы производны. Отказ индекса допускает явно ограниченный поиск; отказ обязательного контроля или первичного журнала закрывает зависимый путь.

На стандартной конфигурации общие сроки инструментов `sequential_call` и `concurrent_batch` равны 0; обязательные контроллеры и сетевые операции имеют собственные сроки. Нулевой общий срок не означает отсутствия отмены, физического предела запроса или контроля затрат. Новый владелец выбирает собственные правила расходов до платных вызовов.

Полная программа: `$BN_DEST/ACCEPTANCE.md` и `$BN_DEST/Руководства/08-…`. Не повторяйте весь набор после каждого малого изменения; проверяйте затронутый контракт и один соответствующий сквозной маршрут.

## 11. Сохранение, восстановление и откат

После собственной приёмки создайте **новую личную** точку восстановления. Публичный комплект не содержит ваших будущих данных и не заменяет этот резерв.

1. Запишите версии, пути, собственные службы, порты, модели, размерность эмбеддингов и список областей данных.
2. Завершите или штатно остановите своих писателей и дочерние задания; проверьте подтверждение остановки и учёт незавершённых исходов. Не убивайте процессы по общему имени.
3. SQLite сохраняйте согласованной копией через backup API. Neo4j Community — штатным `neo4j-admin database dump` остановленной базы. Dolt/Beads — базы, историю и конфигурации, а не только JSONL. Сохраните первичные файлы, квитанции, отчёты, ключи и настройки отдельно защищённым способом. Индексы можно перестроить только при наличии оригиналов и параметров.
4. Защитите личный архив шифрованием; ключ храните отдельно. Публичный GitHub не предназначен для будущих личных состояний и секретов.
5. Восстановите резерв в **другую** папку/APFS-том; сравните суммы, прочитайте известный оригинал, отчёт, задачу и commit; проверьте восстановленный поиск. Только после этого фиксируйте успешное восстановление.
6. Для отката остановите именно новую копию, сохраните появившиеся после точки данные и верните согласованные программы, состояния и настройки. Не смешивайте несовместимые поколения баз или векторы другой размерности. Затем проверьте контроллеры и чтение известного источника.

Остановка собственной службы LaunchAgent выполняется точным путём, например:

```bash
launchctl bootout "gui/$(id -u)" \
  "$UDR_ROOT/state/services/generated/org.hermesudr.agentmemory.plist"
```

Это пример для своей службы AgentMemory; Neo4j, Dolt, шлюз и другие процессы останавливайте их штатными средствами с проверкой фактической остановки. До восстановления никогда не удаляйте работающий корень.

## 12. Если установка остановилась

| Симптом | Следующее действие |
|---|---|
| `arm64` не подтверждён | Выйти из Rosetta / использовать подходящую архитектуру; этот комплект не запускать на Intel |
| SHA или размер не совпал | Остановить установку, сохранить сообщение, повторно получить конкретный файл в новую папку; проверки не ослаблять |
| Каталог уже существует / `Already prepared` | Не перезаписывать состояние и ключи; проверить завершённые этапы, для нового расположения распаковать новую копию |
| R-путь длинный или содержит пробелы | Выбрать короткий собственный путь до подготовки; не заменять байты двоичных библиотек произвольным поиском/заменой |
| macOS блокирует программу | Проверить происхождение/сумму/подпись, затем собственное разрешение в «Конфиденциальность и безопасность»; Gatekeeper целиком не отключать |
| `bn-gsd unavailable`, обязательный контроллер не ответил | Проверить выбранный профиль, пути, манифесты, доступ модели и журнал; не отключать контроллер и не отправлять безусловно тот же запрос, пока не выяснены эффекты |
| Порт или Telegram занят | Найти конкретный собственный процесс; выбрать свободный порт/своего бота; чужую установку не останавливать |
| Инструмент не найден | Проверить включённый MCP-сервер, реальное имя и схему; запрос описаний ≤10 имён |
| Большой ввод не помещается | Разделить на адресные конечные пакеты с полным учётом; обязательный контекст не обрезать |
| Память не вернула источник | Проверить первичный журнал, область, обработку индексов и точное чтение файла; не подменять результат пересказом прежнего контекста |
| Неизвестный исход / незавершённая квитанция | Сначала проверить фактические действия и сохранённые продукты; повтор не должен создавать дубликаты или стирать неизвестный расход |

## 13. Границы подтверждения

Исполняемая подготовка очищенного комплекта проверялась на отдельной копии macOS arm64: восстановление слоёв, новые пути и ключи, пустые состояния, закрепления, импорты и собственный R. Эта инструкция описывает полный порядок до рабочего подключения и восстановления. Она не объявляет уже выполненными действия на вашем новом Mac, не создаёт аккаунты и не наследует согласия прежнего владельца. Результат фиксируется последовательно: **получено → проверено → подготовлено → настроено → подключено → испытано → восстановление подтверждено**.


## 14. Безопасный разбор PDF и больших документарных баз — parser-r4

Новое обновление r4 накладывается непосредственно на согласованную основу 14 октября. Отдельное обновление r2 не нужно: оно уже включено. Подробный маршрут, форматы, контрольные точки и границы: [SAFE-DOCUMENT-PARSING.md](https://github.com/olegeklepikov-collab/hermes-bn-gsd-udr-public/blob/main/deployment-template/SAFE-DOCUMENT-PARSING.md).

После prepare-memory.py должен появиться deployment/Parser-prepared.json. Он создаётся configure-parser.py для новой среды. finalize-prepared.py требует этот файл и Memory 1.3.0. До настоящих документов выполните:

```sh
BN_DIR="$PWD/runtime/Hermes BN"
"$BN_DIR/hermes-agent/venv/bin/python" deployment/parser-selftest.py --work "$PWD/parser-selftest-new"
```

Проверка не требует внешних ключей: PDF на 1 001 страницу, поздний маркер, продолжение, повтор без нового процесса и отказ повреждённого PDF. Затем проверьте реальное чтение и входящий документ Telegram со своим аккаунтом.

Рабочий путь: document_catalogue → повторять document_extract до extracted → все страницы document_describe → все фрагменты document_read → document_status по каждому обязательному этапу. Обычный read_file документа направляет в этот путь; незащищённое и стороннее преобразование как запасной маршрут запрещено.

Для UDR после document_extract используйте action=intake с corpus_id и doc_id, повторяя next_action=intake до registration_complete=true. Сетевой fetch сохраняет original.bin и использует тот же изолированный обработчик; продолжение — action=parse с retrieval_id. Сетевой загрузчик SDK имеет отдельный предел 50 МБ; более крупные предоставленные файлы принимайте местным корпусом.

Нет общего предела числа страниц или строк: работа разбивается на ограниченные шаги. Сохраняются ограничения памяти, времени шага и свободного диска. Неподдержанные форматы, шифрование, повреждение и неразобранные вложения явно остаются пробелами. SQL, макросы, формулы, ссылки и команды из оригинала не выполняются. Извлечение, регистрация, чтение конкретной ролью и предметное принятие проверяются отдельно.
