# Чистая нативная установка: Linux x86-64

Базовая целевая система — Ubuntu 24.04 или совместимая по библиотекам. Docker/WSL не используются. Выполнение на Linux этой архивной работой не удостоверено; ниже установка и критерии её подтверждения.

1. Проверьте внешний SHA-256 архива. Нативные age/zstd для распаковки находятся в distribution/native; tar/libarchive — системный инструмент. Для new-user достаточно zstd. Из большого архива можно сначала извлечь README, Руководства, distribution, deployment и CROSS-PLATFORM-SOURCES.zip; macOS runtime не запускайте.
2. Распакуйте CROSS-PLATFORM-SOURCES.zip в новый закрытый каталог и проверьте SOURCE-MANIFEST-SHA256.json. Пакет содержит программные исходники/шаблоны без Mac venv/node_modules и личных состояний. Создавайте Linux-среды заново.
3. Системные prerequisites: git, curl, CA certificates, tar/unzip/xz, build-essential, Python venv, sqlite3, libmagic, poppler-utils; для сборки R — gcc/gfortran, make, readline, zlib/bzip2/xz, PCRE2, libcurl/OpenSSL и XML-заголовки. На Ubuntu:

```bash
sudo apt-get update
sudo apt-get install git curl ca-certificates unzip xz-utils build-essential gfortran python3-venv sqlite3 libsqlite3-dev libmagic1 poppler-utils libreadline-dev libcurl4-openssl-dev libssl-dev libxml2-dev libpcre2-dev
```

Системные пакеты Ubuntu зависят от редакции ОС и репозитория; они не выдаются за уже исполненную часть слепка macOS.
4. distribution/native/linux-x86_64 содержит Python 3.13.14/3.13.15, 3.12.14 и 3.11.16, uv, Node 24.18.0, Java 21, Beads 1.1.0, Dolt 2.2.1/2.4.2, iii, Collector, SQLite и другие нативные средства. Сверьте их manifest до распаковки. Не смешивайте два Dolt в одном пути: BN использует 2.4.2, Foundation — закреплённый 2.2.1.
5. Для каждого окружения из distribution/environments.json создайте отдельную venv с указанной версией Python и установите закреплённые зависимости из distribution/python-packages. Не переносите Mac .so. На Linux CPU-вариант Torch 2.14.1+cpu включён отдельно и удовлетворяет закреплению 2.14.1; он не требует CUDA. GPU-вариант требует собственных драйверов и дополнительных CUDA-пакетов, не является маршрутом по умолчанию.
6. Hermes устанавливается штатно из включённого исходника в editable-режиме: обычные wheel/sdist проект запрещает. Не включайте фиктивный HERMES_NIX_BUILD. Установите build-зависимости setuptools/wheel из пакета, затем `uv pip install --no-index --find-links ПАПКА_ПАКЕТОВ --no-build-isolation --no-deps --python ВАШ_PYTHON -e ПУТЬ_ИСХОДНИКА`. Сначала зависимости по закреплённому перечню, потом сам исходник. Импорт и CLI проверяются до подключения.
7. R: исходники 4.6.1 и 4.5.3, 247 внешних R-пакетов и встроенные базовые пакеты включены. Для BN рекомендуется отдельный R 4.6.1; сохранённые Mac библиотеки не используются. Сборка в новый префикс: распаковать R source, `./configure --prefix=НОВЫЙ_ПРЕФИКС --enable-R-shlib`, `make`, `make install`; затем установить исходные пакеты R с зависимостями в собственную library. Rtools относится только к Windows. Фиксируйте реально использованные компиляторы и системные библиотеки.
8. Java для пассивного XLS — именно JDK 21. В чистой поставке добавлен явный адаптер JDK21 policy: чтение разрешено, сеть/запись/запуск процессов/отключение контроля запрещены. Проба PortableGuardProbe и чтение проверены с JDK21 на macOS; нативная Linux-проверка обязательна. JDK ≥24 удалил этот механизм: не отключайте контроль ради запуска, используйте закреплённый JDK21.
9. Настройте новые пути, пустые состояния и собственные полномочия. Следуйте официальным UDR docs/setup/README.md, спецификации, roadmap, handoff и ru/01–11. Создавайте systemd user services через включённый render_services.py после проверки портов; не импортируйте launchd plist.
10. Выполните руководства 06–09 и настоящие проверки на этом Linux. До них состояния отмечаются «собрано/установлено», а не «подключено/принято».
