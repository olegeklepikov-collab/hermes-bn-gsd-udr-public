Available tools The MCP server exposes seven tools: resolveIdentifier - Resolve DOIs, PMIDs, PMCIDs, ISBNs, arXiv IDs, ISSNs, ADS bibcodes, and WHO IRIS URLs to structured bibliographic metadata (title, authors, journal, year, identifiers) formatCitation - Format one or more identifiers into a specific citation style. Supports Vancouver, AMA, APA, IEEE, CSE, and 10,000+ CSL styles. Output as text, HTML, or JSON exportCitation - Export one or more identifiers to bibliography file formats: BibTeX, RIS, CSL JSON, EndNote (XML and Refer), RefWorks, MEDLINE/NBIB, Zotero RDF, CSV, or plain text checkRetraction - Check whether a paper has been retracted, corrected, or had an expression of concern raised. Sourced from Crossref and Retraction Watch. Resolves DOI/PMID/PMCID/arXiv/ADS inputs to a DOI before lookup checkOpenAccess - Check whether a paper is openly accessible and return the best legal version (URL, license, hostType, version). Sourced from Unpaywall verifyCitation - Verify a claimed citation against the resolved record at its identifier. Detects the dominant AI-driven fabrication pattern (real DOI paired with a title that does not match the paper at that DOI) documented by Topaz et al. (Lancet 2026) The first three tools accept multiple identifiers in a single request (separated by newlines), so batch operations work out of the box. checkRetraction , checkOpenAccess , and verifyCitation are single-identifier-per-call by design - loop one call per work for multiple papers. Supported identifiers DOIs (e.g. 10.1056/NEJMoa2033700 ) PubMed IDs (e.g. PMID:30049270 ) PubMed Central IDs (e.g. PMC7793608 ) ISBNs (e.g. ISBN:9780192854087 ) arXiv IDs (e.g. 2301.08745 ) ISSNs and eISSNs NASA ADS bibcodes WHO IRIS URLs Identifiers are auto-detected and normalised. You can mix types freely in a single batch request. Setup There are two ways to connect, and both expose the same seven tools, talk to https://scholar-sidekick.com , and run anonymously by default on a rate-limited free tier. Add a free ssk_ key from /account to raise your limits (and enable the verifier’s LLM screen). Hosted endpoint (no install) Point any client that speaks Streamable HTTP directly at the hosted endpoint - no npm install, no local process: POST https://scholar-sidekick.com/api/mcp It works anonymously; to authenticate, send Authorization: Bearer ssk_… . In Claude Code (HTTP transport): # Anonymous: claude mcp add --transport http scholar-sidekick https://scholar-sidekick.com/api/mcp # Or with a free ssk_ key: claude mcp add --transport http scholar-sidekick https://scholar-sidekick.com/api/mcp \ --header "Authorization: Bearer [СЕКРЕТ УДАЛЁН]" In Cursor / Windsurf (remote-server config in .cursor/mcp.json ) - omit headers to run anonymously: { "mcpServers": { "scholar-sidekick": { "url": "https://scholar-sidekick.com/api/mcp", "headers": { "Authorization": "Bearer [СЕКРЕТ УДАЛЁН]" } } } } VS Code uses a top-level servers key with "type": "http" and the same url / headers fields - or install it in one click from VS Code’s built-in MCP gallery: open the Extensions view and search @mcp for Scholar Sidekick (listed via the GitHub MCP Registry ). Using the ChatGPT app? It has its own no-auth endpoint at https://scholar-sidekick.com/api/apps/mcp (a read-only, widget-backed tool surface built for the ChatGPT app). Skip this step. npx skills add mlava/scholar-sidekick-mcp Choosing an auth route There are three routes, and they are alternatives, not layers . Pick one: Anonymous - set nothing. Works out of the box on the rate-limited free tier. First-party key - set only SCHOLAR_API_KEY to a free ssk_ key from /account . Raises limits and enables the verifier’s LLM screen. RapidAPI - set only RAPIDAPI_KEY for a paid RapidAPI subscription. This also switches the base URL to the RapidAPI gateway. If you set both keys, RAPIDAPI_KEY wins and SCHOLAR_API_KEY is ignored - the server says so on stderr at startup (v0.8.7+). Setting SCHOLAR_SIDEKICK_URL alongside a RapidAPI key sends that key somewhere that will not honour it, which is also warned about. A SCHOLAR_API_KEY left at the example placeholder is ignored rather than sent, so a pasted snippet degrades to anonymous instead of 401ing every call. When MCP is useful The MCP integration is well suited to workflows such as: Asking an AI assistant to format a DOI while drafting a document Batch-resolving a list of PMIDs during a literature review conversation Exporting citations to RIS or BibTeX for import into a reference manager Generating formatted reference lists in a specific style on demand Verifying bibliographic metadata for identifiers mid-conversation The same principles apply as with the web tool and API: Scholar Sidekick handles the citation formatting so you can stay focused on the work. Example usage Once connected, you can ask your AI assistant things like: “Format 10.1056/NEJMoa2033700 in Vancouver style” “Resolve PMID:30049270 and export as BibTeX” “Format these three identifiers as AMA and save as a RIS file: 10.1056/NEJMoa2033700, PMID:30049270, ISBN:9780192854087” The assistant will call the appropriate Scholar Sidekick tools and return the results directly in the conversation. Relationship to the API The MCP server wraps the same Scholar Sidekick API that powers the web tool and RapidAPI integration. The underlying resolution, formatting, and export logic is identical. MCP simply provides a standardised interface for AI assistants to call those same endpoints. For a higher-level walkthrough of how the resolver pipeline works under the hood, see the explainer .
