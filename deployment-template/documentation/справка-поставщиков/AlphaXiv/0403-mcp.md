# Справка AlphaXiv: mcp

Сохранённая внешняя документация. Копия адаптирована для переносимости: локальные пути и демонстрационные реквизиты/объекты заменены параметрами; содержимое не является конфигурацией готового аккаунта. Она описывает продукты, версии и варианты доступа, а не состояние какого-либо аккаунта. Примеры ОС, тарифов, путей и лимитов выбираются по целевой установке; числовые условия проверяются у поставщика перед использованием. Даты и исходная терминология могут относиться к версии справки.

MCP Server
The alphaXiv Model Context Protocol (MCP) server gives AI applications, agents, and workflows programmatic access to our research corpus. Search and read papers, analyze PDFs, explore paper codebases, find the researchers behind the work, and manage your library — all through native MCP tools.
Getting startedEndpointhttps://api.alphaxiv.org/mcp/v1TransportStreamable HTTP (POST for requests, GET for server→client SSE stream, DELETE to terminate)AuthenticationBy default the server advertises OAuth 2.1: your MCP client opens a browser sign-in on first use and refreshes tokens on its own. No configuration needed.
For non-interactive use (scripts, CI, headless agents), create an API key under Settings > API Keys and send it as an Authorization: Bearer <key> header instead. A request carrying a key skips the OAuth flow entirely, and deleting the key revokes access immediately.ProtocolModel Context Protocol (MCP) v1.0.0Supported clientsNative MCP clients only — Claude Code, Claude Desktop, Cursor, VS Code, Zed, and CLI bridges like mcp-remote.
Browser-hosted MCP integrations (e.g. adding this server directly inside claude.ai or chatgpt.com) are not supported, because CORS is locked down to first-party origins.
To use this server from a browser-based assistant, run a local bridge such as npx mcp-remote https://api.alphaxiv.org/mcp/v1 and point the assistant at the bridge.
Quick startClaude CodeCodex CLICursorClaude ConnectorBash# Interactive authorization using OAuth2
claude mcp add --transport http alphaxiv https://api.alphaxiv.org/mcp/v1
# Alternatively use an API key to authenticate without interaction
claude mcp add --transport http alphaxiv https://api.alphaxiv.org/mcp/v1 --header "Authorization: Bearer <key>"

Researcher tools
Find people rather than papers: who works on a subject, an organization's roster, where someone is now, and who they publish with. Researchers are addressed by the slug rendered at /@slug, and get_researcher, get_researcher_papers, and resolve_researchers also accept plain names and resolve them for you. The search and profile tools count against your assistant quota; the follow tools do not.
find_researchers
Finds researchers by subject, organization, career history, or coauthorship. A topic query is answered from the authorship graph rather than from profile text, so it reaches the people who publish on a subject rather than only those who describe themselves that way. Composable with current affiliation, role, citation range, and dated position filters.Parametersquerystringoptional
A person's name when identifying that person is the task, or a research subject. Omit for structured roster and career queries.topicstringoptional
Research subject answered from paper authorship, for 'who works on X'. Use one concept in the vocabulary its own papers use; concatenating related concepts matches none of them.topic_authors"lead" | "senior" | "any"optional
Which byline slot topic weights: lead for the students and postdocs driving the work, senior for the PIs closing the author list. Defaults to lead.affiliationstringoptional
Current organization. Every indexed spelling of it is matched, so write the name plainly rather than spelling out variants.include_past_affiliationsbooleanoptional
Shorthand for a past position at affiliation, excluding researchers whose current affiliation still matches. Defaults to false.positionobjectoptional
Career-history filter. Affiliation, role, status, and every date bound apply to the same position row.relationshipobjectoptional
Coauthorship evidence against an anchor researcher: shared papers, what share of that person's own output the collaboration is, and how often they lead a paper the anchor closes.rolestringoptional
Current role, token-matched ('professor' matches assistant and associate professors). Only current roles are indexed.min_citationsnumberoptional
Citation floor, to keep a roster to established researchers.max_citationsnumberoptional
Citation ceiling, to find rising researchers who are not yet famous.sort"relevance" | "citations" | "recent_activity" | "relationship_strength"optional
Result ordering. A topic search carries its own ranking and ignores this. Defaults to relevance.limitnumber (1-100)optional
Results per page. Defaults to 12, or 50 for a relationship search.pagenumberoptional

Common use cases
Literature Review
1. Use discover_papers to surface relevant candidates for the topic
2. Re-run discover_papers with varied keywords/questions or a higher difficulty to fill gaps and ensure comprehensive coverage
3. Use answer_pdf_queries (batching multiple questions per paper) to extract citation-ready excerpts from each paper
4. Synthesize findings across papers
Code Analysis
1. Use discover_papers to find the paper of interest
2. Extract the GitHub URL from results (or from the paper's metadata)
3. Use read_files_from_github_repository with path="/" for an overview, then drill into specific directories
Deep Research
1. Use discover_papers (possibly multiple framings in parallel) to find sources
2. Use get_paper_content to read full text or the AI-generated report
3. Use answer_pdf_queries for citation-grade excerpts from specific pages
4. Use read_files_from_github_repository to verify implementation claims
Researcher Discovery
1. Use find_researchers with a topic to rank the people publishing on it, and read the defining papers it returns alongside them
2. Use get_researcher for their positions, education, and collaborators
3. Use get_researcher_papers sorted by recent to see what they are working on now
4. Use follow_researcher to keep their new papers coming to the feed
Library Management
1. Use list_library to read the user's folders and their folder_id
2. Use create_folder to organize a topic, then save_papers_to_folder to fill it
3. Use move_papers_between_folders to advance papers through reading-status folders as the user reads them
4. Use edit_private_paper_metadata to fix the publication date or byline of uploaded PDFs, which otherwise carry their upload dateSign in
