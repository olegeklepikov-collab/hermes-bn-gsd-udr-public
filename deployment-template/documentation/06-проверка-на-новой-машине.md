# План проверки нового профиля

Все пункты первоначально имеют статус **не проверено**. Результаты другой установки в этот пакет не перенесены. Владелец выбирает допустимые операции и предел расхода; контрольные данные создаются в отдельном проекте.

| Уровень | Что проверить | Условие успешного результата |
|---|---|---|
| Среда | ОС/архитектура, программы, версии, каталоги | Запускается нужный профиль, данные отделены от других пользователей |
| Доступ | Свой аккаунт, ключ/OAuth, область и квота | Нужный метод действительно разрешён; секрет не выводится |
| Каталог | Названия и схемы методов | Клиент понимает текущие параметры; отсутствующие функции не объявлены работающими |
| Чтение | Ограниченный публичный запрос | Возвращён настоящий источник и известный тип материала |
| Ошибки | Неверный параметр, 401/403/429, частичный результат | Ошибка видна, нет бесконечного повтора и скрытой подмены |
| Запись | Новый контрольный объект, чтение обратно, версия/дубль | Совпадает содержимое, область ограничена, повтор не создаёт дубликат |
| Артефакт | Таблица/файл/изображение | Файл существует, тип/сумма/размер подтверждены |
| CLI | Вызовы через агента | Работа выполнена в правильном профиле |
| Приложение | Внутренний сервер и нужные действия интерфейса | Эти две области зафиксированы раздельно |
| Сообщения | Собственный разрешённый чат | Вход, ответ, файл/изображение подтверждены; доставка отделена от ручного открытия |
| Восстановление | Копия и новый отдельный каталог | История/данные доступны без перезаписи действующей базы |

## Небольшие переносимые контроли

- Веб/библиография: собственный ограниченный запрос к публичной документации или общеизвестному DOI; сверить источник, дату и уровень чтения. Публичный идентификатор выбирается как контроль, а не как исследовательский вывод.
- R/Wolfram: синтетические 1:5 — среднее 3, выборочная дисперсия 2,5; уравнение x²−5x+6=0 — корни 2 и 3; отдельный график. Указать единицы, округление и предположения.
- ASReview: новый вымышленный корпус с явными метками/пропусками, seed и моделью; проверить решение, повторное обучение, актуальность ранжирования и полный экспорт.
- Beads: новые задачи A/B с зависимостью; B заблокирована до закрытия A, затем доступна; проверить закрытие чтением.
- Dolt: новая отдельная ветка/набор, изменение, версия, пустое состояние, происхождение и экспорт. Проверку конфликта выполнять транзакционно с откатом без неявного выбора стороны.
- Zotero: свой контрольный отчёт/заметка, разрешённое вложение, чтение обратно, версия/конфликт, выбранные форматы/стили, восстанавливаемая корзина. Штатную синхронизацию и независимое облачное скачивание отмечать как разные проверки.

После теста составить свой протокол: дата/часовой пояс, версии, методы, входы, фактические ответы/ошибки, ID нового проекта, артефакты/суммы и ограничения. Переносить в документацию только сведения, разрешённые владельцем этой установки; готовые личные протоколы других пользователей не используются.
