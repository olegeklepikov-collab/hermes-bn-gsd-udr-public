# Безопасное изменение платформы

Перед новой волной сохраните согласованный слепок и перечень версий/хешей. Работайте в отдельном каталоге/профиле, пока результат не проверен. Подписанные поставки поставщиков остаются исходными; собственные адаптеры и их манифесты версионируются отдельно. Не изменяйте движок Hermes ради коммерческого сервиса, если достаточно подключаемого расширения.

Для обновления Hermes сравните подтверждённые интерфейсы hooks, subagents, skills и middleware с используемыми адаптерами. Проверьте локальную накладку ядра по core-manifest; не называйте совпадение версии совместимостью. После смены кода заново закрепите фактические хеши и транспортные привязки.

Сохраняйте отдельные области GSD/UDR и общей памяти. Не сбрасывайте старые расходы, неразрешённые исходы и первичные документы ради запуска. Архивная копия не даёт полномочий на повтор внешнего действия. При ошибке сначала уточняется состояние/эффект, затем делается ограниченное продолжение с прежним происхождением.

Откат: остановить именно новую копию; сохранить созданные после точки данные; вернуть предыдущие версии/профиль/службы; проверить обязательные контроллеры и чтение известного источника. Если старый и новый форматы несовместимы, не смешивать файлы баз: использовать согласованное поколение и его оригиналы. Чистый пакет другого пользователя не является восстановлением личного состояния прежнего.

Ключи архивов хранятся отдельно. На независимом носителе должна быть проверенная копия архива; совпадение SHA-256 проверяется после копирования, а не только до. Не удаляйте прежнюю рабочую версию, пока новое восстановление не доказано.
