# Scite Knowledge Work Skill

Scite обеспечивает поиск научных источников, чтение доступного текста, проверку цитирований и работу с исследовательскими подборками. Доказательность вывода устанавливается по методам и результатам исследований, а не по числу цитирований.

## When to Use

- Академические исследования: поиск работ, отбор по критериям, сопоставление методов, противоречий, редакционных сообщений, проверка библиографии.
- Бизнес: научное обоснование решений, исследование технологий, патентов, грантов и зарегистрированных исследований.
- Общие исследования: проверка утверждений, восстановление источников, карта цитирований и подтверждённые ссылки.

## Prerequisites

Подключён сервер `scite` по адресу `https://api.scite.ai/mcp` с отдельным входом OAuth для «Hermes BN — AgentRuntime2» и автоматическим обновлением токена. Ключ API для MCP не нужен. Данные подключения и все файлы находятся в `__HERMES_BN_ROOT__/Scite`; токены хранятся средствами Hermes BN, не в запросах или файлах сценариев.

Основные средства: `mcp__scite__search_literature`, `mcp__scite__read_fulltext`, `mcp__scite__citation_graph`, `mcp__scite__bibliography`, `mcp__scite__report_citations`, `mcp__scite__citation_report`, доступные инструменты Evidence и Collections. Состав каталога проверяется при подключении. Наличие инструмента в каталоге не доказывает право на его выполнение.

Через `terminal` доступна оболочка `scite-bn`. Публичные REST-запросы Papers/Tallies не требуют ключа; остальные требуют соответствующих разрешений. Постоянное исследовательское или коммерческое применение прямого Search API требует отдельной лицензии. Для обычного исследования используй MCP. Пробное обращение к Search API допускается только как проверка подключения, с `--evaluation`.

## How to Run

1. В новом разговоре загрузи этот навык через `skill_view`.
2. Установи вопрос, предмет, период, критерии включения, язык ответа и нужную глубину чтения.
3. Выполняй исследование инструментами `scite`. При недостающей функции открой сохранённую документацию через `read_file` и используй оболочку через `terminal`.

```bash
scite-bn profiles
scite-bn catalog --output '__HERMES_BN_ROOT__/Scite/checks/live-catalog.json'
scite-bn call --profile literature --params '/absolute/path/request.json' --output '/absolute/path/result.json'
scite-bn rest --profile paper-metadata --params '/absolute/path/doi.json' --output '/absolute/path/paper.json'
scite-bn batch --params '/absolute/path/calls.json' --output '/absolute/path/session.json'
scite-bn export --from-file '/absolute/path/papers.json' --export-format csv --output '/absolute/path/references.csv'
```

`--params` содержит JSON-параметры, `--body-file` — JSON-тело REST-запроса. Имя инструмента задаётся через `--name`, готовый сценарий через `--profile`. `batch` принимает массив `{name, arguments}` и сохраняет один сеанс MCP для последовательных вызовов и аудита. Имена и типы сверяются с текущим каталогом MCP или официальной спецификацией; неподтверждённые параметры не добавлять.

## Quick Reference

| Задача | Сценарий | Условия |
|---|---|---|
| Литература, свежие работы, обзоры | literature, recent, reviews | term, limit 10, offset; период задавать явно |
| Поддерживающие и противоположные цитирования | supporting, contrasting | Читать конкретные цитирующие утверждения |
| DOI, редакционные сообщения, разделы статьи | editorial-audit, paper-sections | dois без term для метаданных; dois + term для выдержек |
| Доступный текст | fulltext | doi, offset, length; проверять источник текста |
| Сеть цитирований | citation-network | seeds, направление in/out/both, depth 1; ограничивать объём |
| Библиография и аудит | bibliography, source-ledger, citation-audit | Только реально полученные и проверенные источники |
| Патенты, гранты, исследования | patents, grants, clinical-trials | q/f/p; сначала поиск, затем get_* по полученному ID |
| Регуляторные источники | drug-records, device-clearances, device-documents, drug-event-reports, device-event-reports, safety-alerts | Условия доступа зависят от набора данных |
| Подборки и материалы | collections, collection-record, collection-papers, private-collection, add-papers, collection-notes, collection-files | Только явно выбранная подборка; новая закрытая |
| Готовые последовательности исследования | review-workflow, claim-workflow, screening-workflow, reference-workflow | Получение шаблона не выполняет исследование |
| Публичные сведения | paper-metadata, papers-bulk, tally, tallies-bulk, section-tally, tallies-aggregate, pmid-to-doi | Пакетное JSON-тело — массив DOI, до 500 |
| Дополнительные REST-функции | paper-recommendations, author-publications, author-statistics, journal-statistics, assistant-task, reference-check-task | Нужны отдельные права; ID задания берётся из ответа создания |

## Procedure

1. Составь несколько предметных поисков с синонимами и `AND`/`OR`/`NOT`, фразами и, при необходимости, близостью слов. Не проводи произвольный поиск по всей базе без запроса. Для `recent` задай `date_from`/`date_to`; `year` с ними не совмещать. Не считать этот сценарий автоматической сортировкой: используй `sort` только если он есть в текущей схеме.
2. Получи ограниченный набор работ, сохрани DOI, название, дату публикации, журнал, авторов, основание включения. Не исключай противоположные результаты по направлению эффекта. `paper_type` проверяй по первоисточнику: метка индекса может быть неполной.
3. Для отобранных DOI запроси метаданные и `editorialNotices`. Перепроверь название, год и DOI на странице издателя через `web_extract`. Год в DOI не является датой публикации; онлайн-публикация и выпуск журнала могут иметь разные годы. При расхождениях укажи подтверждённую дату и её вид.
4. Читай аннотацию, методы, результаты и ограничения. `dois` + `term` возвращает выдержки, а не всю статью. `read_fulltext` проверяй по `source`, `contentDenied`, `returnedChars`, `hasMore`: `abstract`, `null` и отказ в тексте не являются чтением полного текста. Следующее смещение — текущее плюс фактически возвращённое число символов; не сохранять смещения между днями. Недоступный текст ищи только по разрешённым ссылкам; приобретение доступа требует задания пользователя.
5. Проверяй конкретный контекст цитирований. `supporting`, `contrasting`/`contradicting`, `mentioning` — категории цитирующего утверждения, не оценка всей статьи и не доказательство истинности. `unclassified` означает отсутствие классификации. Показатели считают утверждения, `citingPublications` — отдельные работы; не приравнивать их и не вычислять «процент консенсуса» по этим данным.
6. Сеть цитирований имеет направление от цитирующей работы к цитируемой: `s` → `t`. `in` ищет последующие работы, `out` — ссылки исходной работы. Массив `search_literature.citations` может содержать исходящие ссылки: проверяй `sourceDoi` и `targetDoi`, не выдавай их за отзывы о найденной статье. Низкое покрытие не означает низкую значимость. Учитывай объединение версий и ограничения извлечённых отрывков.
7. Для Evidence используй `q`, `f`, `p`; доступные поля фильтров проверяй по схеме набора. Не переноси `limit`/`offset` из литературы и не применяй сортировку к инструментам, которые её не поддерживают. Получай полную запись по ID из результата поиска. Гранты могут группироваться: одна строка не равна одному присуждённому гранту. Патентное семейство не равно отдельному патенту. Регистрация исследования не доказывает результативность; FAERS/MAUDE не определяют причинность или частоту риска без знаменателя.
8. Подборку создавай только по заданию пользователя с `is_shared_with_org:false` и `is_shared_publicly:false` — это реальные поля текущей схемы. Проверяй возвращённый slug, `isPublic` и unmatchedDoiCount; данные DOI обновляются асинхронно. Добавляй DOI через `add_dois_to_collection`: `update_collection.dois` заменяет весь список. ID заметок и файлов являются целыми числами; передавай полученный ID без преобразования в строку. Изменение видимости, удаление, загрузка частных файлов, оформление подписки и включение уведомлений требуют соответствующего явного задания; необратимое удаление — отдельного подтверждения. Оболочка требует `--confirm-write` для изменений; этот флаг не заменяет разрешение пользователя.
9. В ответе отделяй данные источника от собственного вывода, давай DOI/URL, методы, ключевые результаты и ограничения. Короткие точные цитаты используй там, где они подтверждают вывод; соблюдай права на текст. Указывай фактический уровень чтения: метаданные, аннотация, выдержки, полный текст.
10. Заверши проверенной библиографией, по умолчанию APA. Если используется `report_citations`, записывай реальные решения включения/исключения и причины; не выдумывай записи. Проверяй `citation_report` в том же сеансе. Не передавай необязательный `user_intent`: отдельное разрешение на атрибуцию не получено.

## Pitfalls

- Страницы справки различаются по времени: старые «10 бесплатных обращений» отменены в октябре 2026 года. Проверяй доступ аккаунта и ошибки, а не рекламный текст.
- Документация может описывать 25 инструментов; живой каталог изменяется. Он определяет допустимые параметры, а выполнение — фактический доступ.
- REST-схема требует массив DOI для пакетных Papers/Tallies; некоторые текстовые примеры показывают другое тело. Проверяй OpenAPI и реальный ответ.
- REST Search скрывает текст цитирований на обычном самостоятельном ключе Pro. Не выдавай пустой `snippet` при `snippetHidden:true` за прочитанный источник.
- `401` — проблема входа, `403`/`-32003` — прав, `-32001` — квоты либо обязательного входа. Не менять тариф автоматически. При 429 учитывать заголовки ограничения; не повторять записи с риском дублирования.
- Reference Check и Assistant требуют отдельных разрешений. Идентификатор задания нельзя угадывать: неизвестный Reference Check ID может выглядеть как вечный PENDING.
- CSV у `bibliography` возвращал ошибку сервера `-32603` при двух проверках. Для таблицы используй местную выгрузку `scite-bn export` из сохранённых сведений; не называй её успешной CSV-выгрузкой сервиса. Для полученных BibTeX/RIS тот же `export` с соответствующим форматом исправляет нестандартный тип `@journal-article` и нумерацию перед записями RIS.
- В записях исследований встречается `nctId` с префиксом `clinicaltrials/` и ошибочный URL с повторённым сегментом. Для `get_clinical_trial` используй полученную часть `NCT` с восемью цифрами; официальную ссылку проверяй на ClinicalTrials.gov.
- В `citation_graph.edges` поля `type` и `section` могут быть массивами. Одна пара работ может иметь несколько цитирующих утверждений и категорий; не заменяй их единственной оценкой всей связи.
- Остаток квоты и дата сброса берутся из `manage_subscription` без аргументов через оболочку. У этого аккаунта сброс указан на 27 октября 2026 года; правило «первого числа» из старой справки не применять. Изменение `pay_as_you_go_limit` не входит в проверку остатка.

## Verification

Проверяй статус в `Scite/connection-status.json`. Подключение считается подтверждённым после живого каталога, поиска, проверки чтения и контекста цитирований, библиографии и проверки через Hermes CLI, приложение и Telegram. Непроверенные функции и отсутствующие права перечисляй явно; сохранение конфигурации не является проверкой сервиса.

Официальные материалы: `https://docs.scite.ai/agents`, `https://docs.scite.ai/mcp/overview`, `https://docs.scite.ai/mcp/tools/overview`, `https://docs.scite.ai/openapi.json`. Локальная копия 102 страниц и спецификации находится в `Scite/источники`.
