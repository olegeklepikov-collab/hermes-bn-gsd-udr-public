# Parallel Knowledge Work Skill

Исследуй открытые источники через Parallel: находи и читай страницы, составляй отчёты и проверяемые таблицы. Сохраняй адреса источников, даты и основания выводов; отделяй найденные сведения от предположений.

## When to Use

Пользователь просит Parallel, исследование бизнеса, академических публикаций или общего вопроса. Для обычных запросов сохраняй настроенные пользователем средства поиска.

## Prerequisites

Экземпляр Hermes BN: `__HERMES_BN_ROOT__`.
Ключ сохраняется через защищённое поле Parallel в Hermes. Не показывай ключ, не передавай его в аргументах команды и не читай чужие конфигурации.

Ожидаются серверы `parallel-search`, `parallel-task` и инструмент `terminal`.
Актуальные настройки: `__HERMES_BN_ROOT__/Parallel/config/profiles.json`.
Новые библиотеки изолированы в `__HERMES_BN_ROOT__/Parallel/venv`. Не устанавливай их в основное окружение Hermes: встроенный провайдер использует закреплённую библиотеку 0.4.2. Для программных запросов используй Python из отдельного окружения Parallel.
Документация: `__HERMES_BN_ROOT__/Parallel/источники/index.txt`.

## How to Run

1. Для поиска и чтения используй `parallel-search`: `web_search`, `web_fetch`. При первом обращении узнай точную схему через доступный поиск инструментов.
2. Для исследований и таблиц используй `parallel-task`: `createDeepResearch`, `createTaskGroup`, `getStatus`, `getResultMarkdown`. Схема сервера определяет точные названия и параметры; не угадывай их.
3. Расширенные параметры, FindAll, Responses, изображения и Monitor доступны через `terminal` и собственную команду `parallel-bn`.
4. Полный программный доступ: библиотеки `parallel` и `parallel_web_tools`, OpenAI-совместимый Responses API. Ключ получает собственная оболочка; Python-программы загружают только `.env` этого экземпляра.

```bash
parallel-bn search "исследовательский вопрос" --mode fast --max-results 5 --json
parallel-bn extract https://docs.parallel.ai/getting-started/pricing --full-content --json
parallel-bn research run "исследовательский вопрос" --processor pro --text --memory-scope-key hermes-bn --no-wait --json
parallel-bn research status trun_ID --json
parallel-bn research poll trun_ID --json
parallel-bn profile
parallel-bn profile response-low --body /absolute/path/request.json --output /absolute/path/answer.json
parallel-bn profile findall-preview --body /absolute/path/findall.json --output /absolute/path/run.json
parallel-bn api GET /v1/tasks/runs/trun_ID/result --output /absolute/path/result.json
```

Перед использованием команды с дополнительными параметрами прочитай её `--help` через `terminal`. Сохраняй большие ответы на AgentRuntime2 и исследуй сохранённые результаты через `read_file` и `search_files`.

## Quick Reference

| Задача | Выбор |
|---|---|
| Быстрый поиск | Search `fast`; `turbo` для минимальной задержки |
| Развёрнутые выдержки | Search `basic` |
| Сложный поиск | Search `advanced` |
| Академическая работа | `search-academic`; уточнить дисциплину и список источников |
| Бизнес | `search-business`; добавить официальные сайты предмета исследования |
| Свежие страницы | `search-fresh`; публикационная дата задаётся отдельно |
| Чтение | Extract focused/full/live; поддерживает PDF и динамические страницы |
| Простые факты и дополнение строк | Task `base`; для простых метаданных `lite` |
| Сопоставление источников | Task `core` / `core2x` |
| Исследовательский отчёт | Task `pro`; `ultra` и расширения при достаточном бюджете |
| Быстрый ответ с источниками | Responses `low`, `medium`, `high` |
| Список с проверкой критериев | FindAll сначала `preview`, затем base/core/pro |
| Быстрый список компаний или людей | Entity Search; проверить сведения отдельно |
| Изображения | Image Search fast/advanced; сохранять исходную страницу |
| Наблюдение | Monitor event_stream или snapshot; отдельный запрос пользователя |

## Procedure

1. Зафиксируй предмет, дату, географию, источники, требуемый результат и допустимый объём. Если данных хватает, приступай без дополнительных вопросов.
2. Найди первичные источники. Поисковые выдержки используй для отбора; существенные факты проверяй чтением страниц.
3. Для Search/Extract используй актуальные `/v1/search`, `/v1/extract`. Параметры `max_results`, source_policy, fetch_policy находятся в `advanced_settings`; у Extract туда же входят full_content и excerpt_settings.
4. В прямом API сохраняй возвращённый session_id для связанных Search/Extract. В MCP используй один UUID разговора во всех вызовах; это идентификатор учёта, а не перенос исследовательского контекста. Платный MCP может игнорировать его и возвращать разные API session_id. Продолжение исследования задаётся previous_interaction_id или previous_response_id. Поля model_name/client_model опускай, если пользователь не запросил учёт использования по моделям.
5. Ограничивай объём: обычно 5–8 результатов, 20000 знаков. В одном Extract допускаются несколько URL; проверяй отдельные errors, даже при успешном HTTP-ответе.
6. Для таблиц задавай схему JSON: корневой object, все поля required, additionalProperties=false, неизвестные значения допускают null. До 100 свойств, глубина 5, общий вход и схема до 25000 знаков.
7. Для пакетного дополнения данных используй TaskGroup или `parallel-bn enrich run`. Начни с небольшой выборки, затем масштабируй. Для сопоставления источников выбирай core; base подходит для простых фактов, проверенных на выборке. Стоимость Task начисляется за строку, а не за отдельное поле.
8. Длительные задания запускай без ожидания. Сохрани run_id/group_id, проверяй состояние с разумным интервалом и получи полный результат с basis: confidence, reasoning, citations, excerpts.
9. Продолжение Task использует previous_interaction_id; Responses — previous_response_id. Это разные идентификаторы.
10. В Responses модель называется `parallel`, effort — low/medium/high. JSON задаётся через text.format, поток через stream=true; обработай конечное состояние и annotations с URL. Background не поддерживается.
11. В FindAll обязательно укажи entity_type и проверяемые match_conditions. Preview оценивает 5–10 кандидатов, может возвращать неподходящие записи. В конечный список включай только подтверждённые совпадения. Preview нельзя расширять.
12. CLI FindAll `--dry-run` вызывает Ingest для подготовки схемы и не равен preview. По умолчанию CLI использует core: для пробного запуска явно выбирай preview через подготовленный профиль.
13. Для сохранения истории Task/FindAll/Monitor используй memory_scope_key `hermes-bn`; при чтении Memory указывай тот же scope-key. Оболочка задаёт эту область по умолчанию. Удалённый Task MCP не предоставляет такого параметра: для строгого разделения памяти используй программные запросы или CLI. Не исследуй историю других приложений.
14. Постоянное наблюдение создавай только по отдельному запросу пользователя с предметом, периодом и доставкой. Monitor trigger выполняет реальную проверку; cancel окончательно прекращает задание. Подготовленные профили сами ничего не запускают.
15. Подключение частных страниц, файлов, сторонних MCP и платных источников выполняй для явно указанных данных и цели. Настройки доступа и автоматические уведомления не вытекают из обычного исследовательского запроса.

## Pitfalls

- Не заменяй `/v1beta/findall` и `/v1alpha/monitors` на `/v1` по аналогии с Search.
- Включённый allowlist источников отменяет exclude_domains. Не применяй список академических источников как исчерпывающую базу литературы.
- Фильтр after_date относится к публикации, max_age_seconds — к сохранённой копии. Минимальный возраст копии 600 секунд; строгая свежесть отключает использование старой копии при ошибке.
- Ответ или уверенность сервиса не заменяют проверку первичного источника. Публикация в архиве препринтов не подтверждает рецензирование.
- Для цен и показателей фиксируй способ доступа, единицу, период и вариант продукта. При чтении одной заданной страницы ограничивай source_policy её точным доменом/путём. Обычный API и шлюз MPP/x402 имеют разные тарифы; платёжный шлюз не настроен.
- Snapshot может возвращать событие при изменении обоснований с прежними значениями. Перед уведомлением сравнивай changed_output.content и previous_output.content; изменение формулировок basis не объявляй изменением факта.
- Ссылки поиска изображений не предоставляют права на использование изображения.
- Не смешивай API-ключ Parallel с подпиской ChatGPT и не меняй модель Hermes ради Responses.
- Большие лимиты и дорогие генераторы не гарантируют полноты поиска. Фиксируй стоимость и пределы до масштабирования.

## Verification

Проверь конечное состояние задания, отсутствие необработанных ошибок, соответствие JSON схеме, адреса и содержание существенных источников. Для таблиц проверь пропуски, совпадения критериев и повторы. В отчёте укажи дату проверки, ограничения охвата и выявленные противоречия.
